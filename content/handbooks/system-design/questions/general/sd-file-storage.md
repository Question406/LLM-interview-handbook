## 题目描述

设计团队文件服务，支持最大10GB 文件上传、下载、目录、共享和版本历史。手册练习假设支持断点续传，不要求实时多人协作文档编辑。请输出上传会话与提交协议、对象和元数据布局、访问授权与删除流程，说明分片重复、提交响应丢失、孤立分片和共享权限撤销时的结果。

## 回答思路

> **问题与场景：** 假设上传一个大文件，在九成时断网，用户希望恢复而不是重传。
>
> **做法与原因：** Metadata 管理所有者、权限与版本，object storage 保存内容；它们的状态需要配合。
>
> **检查与取舍：** 测试断点续传、重复完成、权限撤销与旧版本读取。

## 可以这样回答

假设上传一个大文件，在九成时断网，用户希望恢复而不是重传。可以先建立上传会话，分块写入并记录校验，全部完成后再原子地发布文件版本。

Metadata 管理所有者、权限与版本，object storage 保存内容；它们的状态需要配合。未完成的块应能清理，重试同一块不应制造多个可见文件。

测试断点续传、重复完成、权限撤销与旧版本读取。文件 bytes 已上传，不等于它已经可以向所有用户公开。

### 分片上传与最终提交

元数据服务创建上传会话并授权客户端直接上传分片到对象存储。客户端提交有序分片清单与校验信息，服务确认内容后才把文件版本标为可见；未完成的会话不能作为完整文件下载。分片标识允许重传，提交接口使用幂等标识。

### 元数据与一致性

文件标识稳定，版本记录指向不可变对象，目录项指向当前文件版本。改名或移动更新元数据，避免复制10GB 内容。并发更新用版本条件检测冲突；不同设备上传不同新版本时，不应静默覆盖。

### 权限与删除

短期下载授权的有效期决定撤权窗口；敏感场景可通过下载网关或更严格的授权检查缩小窗口。对象去重不能泄露其他租户是否拥有某内容；引用计数和延迟 GC 要与版本保留规则相容。

### 示例与追问

第3片上传超时，客户端重传相同片号；最终提交已经成功但响应丢失，再次提交返回同一版本。每日清理过期上传会话和孤立分片，但要隔离仍活跃上传。跨区域复制未完成时，不要先把目标区域文件承诺为可读。
