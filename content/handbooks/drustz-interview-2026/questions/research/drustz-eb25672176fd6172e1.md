> DrustZ 整理的补充研究笔记。公司与轮次信息沿用作者的来源记录。

题干：为组织成 rooted n-ary 树的分布式系统实现基于消息的协议。每个节点是一台机器，有唯一 string ID(0..n-1)、父 ID(-1 为 root)、子 ID 列表。节点只能通过消息 API 与直接父/子双向通信。需支持两个由外部客户端向 root 触发的操作：1) 'count' 统计cluster所有节点数；2) 'topology' 把cluster拓扑重建为字符串。考点：分布式消息传递状态机、DESIGN。Follow-up：如何处理节点失败/丢消息？多操作能否并发互不干扰？重建拓扑串时如何优化带宽？若通信从异步变同步如何改？
