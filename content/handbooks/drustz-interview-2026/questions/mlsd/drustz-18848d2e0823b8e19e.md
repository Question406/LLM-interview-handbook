## 9. 隐私与合规

### 9.1 核心原则：合成 ≠ 匿名

从真实数据训练出来的 generator，会以两种方式泄漏：

1. **逐字记忆**：训练数据里的罕见字符串（身份证号、病历号、罕见姓名组合）被原样吐出。Carlini 等人的 "Secret Sharer" 给了标准做法：**往训练数据里插入 canary（人造的罕见字符串），训练后测模型吐出它的概率（exposure）**。这是一个可以直接执行的泄漏测试。
2. **准标识符组合重识别**：单个字段都不敏感，组合起来唯一定位到一个人（邮编 + 出生日期 + 性别是经典例子）。**只做命名实体识别（NER）扫 PII 是不够的**——NER 抓不到组合泄漏。

监管侧的立场也是一致的：合成数据不会自动获得"匿名数据"的身份，判据是**能否重识别**。

### 9.2 三档隐私强度（按需选，不要一上来就上最重的）

| 档 | 做法 | 保证 | 代价 |
|---|---|---|---|
| **弱**：PII 清洗 + 人工抽检 | 规则 + NER 脱敏，抽检 | 无形式保证，只挡低垂果实 | 低 |
| **中**：清洗 + 记忆测试 + 近重复过滤 | 加 canary exposure 测试；合成样本与任何真实样本的相似度超阈值就丢 | 经验保证，可量化 | 中 |
| **强**：差分隐私 | 用 DP-SGD 微调 generator，然后sampling | **形式保证**：由于 DP 的后处理免疫性（post-processing immunity），从 DP 训练的模型sampling出的任意多合成数据，都继承同一个 (ε, δ) 预算，**sampling本身不额外消耗隐私预算** | 高：文本质量明显下降，ε 越小越明显；需要专门的训练基础设施 |

**"后处理免疫性"这个点在面试里很值钱**：它解释了为什么 DP 合成数据是有吸引力的——训练一次付一次隐私代价，之后想生成多少条都不再增加泄漏风险。这是 DP 合成数据相对"每次查询都加噪"的关键优势。

### 9.3 医疗场景的具体锚点

我在 Anthropic 的 take-home（医疗领域）里做过相关的东西，可以诚实地讲：那个任务是判断回复是否 grounded 在给定材料上。我做的 **claim 级 grounding grader** 在"预测医生标注的不安全回复"上 AUROC 达到 0.844，而 ROUGE 只有 0.569（约等于掷硬币），两者confidence interval不重叠。**这套东西直接可以复用为合成数据的 L2 闸门**：判"这条合成回答的每个 claim 是否有来源支撑"，比判"这条回答质量好不好"可靠得多。

同一个 take-home 里我还建了 **137 对扰动测试套件**，按扰动类型分层报检出率——这个方法论对合成数据同样适用：**造一批已知有缺陷的合成样本（故意去掉前提、故意加矛盾、故意改数字），看闸门能抓住多少**。这是给质量闸门做单元测试。

### 9.4 合规红线清单

- 用第三方 API 的输出训模型 → 先看服务条款（§1.1 第 4 问）。
- 从用户数据合成 → 确认 consent 覆盖这个用途，租户隔离，保留 / 删除策略要能级联到合成产物（删了原始数据，从它衍生的合成数据怎么办？**provenance 就是为了回答这个问题**）。
- 医疗/金融领域有明确的去标识化标准（如 HIPAA 的 Safe Harbor 十八类标识符 vs expert determination 两条路径）。
- **诚实边界**：我没有做过金融/交易领域的数据，也没有承担过受监管数据的合规签字责任。涉及这块我会说"我知道要问什么问题、要建什么测试，但具体的合规判定我会拉法务和领域专家"。
