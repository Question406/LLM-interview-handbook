## 8. 回归防护：怎么保证没有静默退化 ⭐⭐⭐

### 8.1 冻结回归集

- 规模 1000–3000 条，覆盖**所有 guardrail 切片**，每个切片有最小配额。
- **永不修改**。要改就发新版本号，并且**新旧版本双跑一个重叠期**建立换算关系。
- 跑的是**整条产品链路**（系统提示 + 模板 + 检索 + 工具 + 后处理），不是裸模型——静默退化最常见的三个来源是系统提示改了、chat template 改了、依赖的检索/工具变了，只测裸模型全都测不到。

### 8.2 paired test：省一个数量级的样本

**不要用两组独立样本比胜率。**在**同一批 prompt** 上跑新旧两版，做配对比较：

- 二元结果用 **McNemar 检验**（只看不一致的那些对）。
- 连续分用 **paired bootstrap**（按 prompt resampling；多轮对话要**按会话做 cluster bootstrap**，同一会话的多轮不独立）。

数量级直觉（面试可以现场算）：胜率在 50% 附近，独立比较的标准误是 $\sqrt{0.25/n}$，$n=1000$ 时 SE≈1.6pp，95% CI 约 ±3.1pp——**连 2pp 的差异都分不出来**。配对后有效方差按 $(1-\rho)$ 缩小，$\rho=0.7$ 时同样的功效大约只需要三分之一样本。

### 8.3 非劣性检验：不显著 ≠ 没退化 ⭐⭐⭐

这是本节最容易拉开差距的一句话。

- 错误做法：`p > 0.05` → "没有显著退化" → 放行。样本不够时永远 `p > 0.05`，等于没有 gate。
- 正确做法：**预先设定容忍边界 δ（比如 -1pp）**，要求"差值的 95% CI 下界 > -δ"才算通过。这叫非劣性（non-inferiority）检验。
- 附带好处：它逼你先回答"跌多少我们不能接受"，这是产品决策不是统计决策。
- 如果 CI 太宽以至于既不能证明非劣也不能证明退化 → 结论是"**样本不足，不能下结论**"，要么加样本要么降级发布，而不是默认放行。

### 8.4 Canary prompts：像单元测试一样增长

- 每修一个线上事故，就往 canary 集加一条**最小复现 prompt** + 期望行为的断言。
- 任何一条 canary 回退 → **直接 block**，不参与统计、不看 p 值（它是回归测试不是抽样估计）。
- 这套集合会随时间单调增长，是团队记忆的物化形式。规模到几百条时按类别归档，跑起来仍然只要几分钟。

### 8.5 变更矩阵：一次只变一个

| 变了什么 | 是否需要重跑全量 | 是否需要 judge 重calibration |
|---|---|---|
| 模型 checkpoint | 是 | 否 |
| 系统提示 / chat template | 是（最容易被忽略） | 否 |
| judge 模型或 judge prompt | 是，且要**双跑重叠期** | **是** |
| eval 数据集版本 | 是，且要建换算关系 | 否 |
| sampling参数（温度、top-p） | 是（会改变方差，影响所有 CI） | 否 |

**必背句**：模型和 judge 不能在同一次发布里一起动。同时动了，分数变化无法归因，这一轮评测就废了。
