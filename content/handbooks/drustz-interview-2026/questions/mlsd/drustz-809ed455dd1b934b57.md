## 2. RL 数据 ≠ SFT 数据 ⭐⭐⭐

这是整题的地基。很多候选人会把「造 RL 数据」讲成「造高质量 QA 对」，那是 SFT 的思路。

### 2.1 对照表

| 维度 | SFT 数据 | RL（RLVR）数据 |
|---|---|---|
| **一条样本是什么** | `(prompt, 参考回答)` | `(prompt, verifier, 元信息)`；**回答由策略自己产生** |
| **「质量高」的定义** | 回答写得对、写得好、风格一致 | **这个 prompt 能产生非零 advantage** |
| **参考答案的作用** | 是训练目标本身 | 只是 verifier 的输入；**如果泄漏进 prompt 就是灾难** |
| **模型太强会怎样** | 无所谓，仍然学得到风格 | **样本直接作废**（全对，组内方差 0） |
| **模型太弱会怎样** | 无所谓 | **样本直接作废**（全错，组内方差 0） |
| **数据量的边际收益** | 大致随 log(N) 上升 | **强烈非线性**：一条 p≈0.5 的题 > 十条 p≈0.98 的题 |
| **重复样本的危害** | 轻微overfitting | 严重：同一题被反复 rollout，等价于给这个题族加了权重 |
| **数据集的寿命** | 长，可跨模型复用 | **短，绑定 checkpoint**；模型更新后难度标注全部失效 |
| **生产成本主体** | 标注 / teacher model生成 | **rollout 生成（decode）**，是数据 pipeline 的 80%+ 成本 |
| **典型失败形态** | 学到过时/错误示范 | 学到 hack verifier 的捷径 |

### 2.2 一句可以直接说的话

> SFT 里「好答案」是资产；RL 里「好答案」是**风险**——它只应该存在于 verifier 一侧，一旦泄漏到 prompt 侧（比如爬论坛帖时把楼下的解答一起爬进来了），这道题的 pass rate 会跳到 1.0，然后被我的难度筛选当成「太简单」丢掉。**污染在这里不是让指标虚高，是让我最好的题被静默删掉。**（详见 §8.3，这是本题最反直觉的一个失败模式）

### 2.3 数据集的最小 schema

```jsonc
{
  "prompt_id": "sha256(canonical_problem_text)", // 去重主键
  "prompt": "...", // 不含答案、不含解法
  "domain": "math/olympiad_geometry",
  "source": "aops_thread_2019 | synth_v3 | user_log",
  "license": "...",
  "verifier": {
    "type": "exact_numeric | sympy_equiv | unit_test | rubric_claims | judge",
    "gold": "...", // 或测试用例集合
    "tolerance": 1e-6,
    "version": "v7" // verifier 也要版本化
  },
  "difficulty": {
    "probe_policy": "ckpt_step_4200", // ⭐ 难度绑定 checkpoint
    "sampling": { "T": 1.0, "top_p": 0.95, "max_tokens": 8192 },
    "n_probe": 16,
    "p_hat": 0.31,
    "measured_at": "2026-07-02"
  },
  "flags": ["self_contained_ok", "no_answer_leak", "single_valued"],
  "contamination": { "checked_against": ["MATH500", "AIME24", "GPQA"], "max_sim": 0.42 }
}
```



**面试里值得点出的三个字段**：`difficulty.probe_policy`（难度绑 checkpoint）、`verifier.version`（verifier 变了难度标注就失效）、`sampling`（探测和训练的sampling参数必须一致，否则 p̂ 系统性偏差，见 §14 失败模式 5）。
