## 8. 监控：报什么、不报什么

### 8.1 在线

| 类别 | 指标 |
|---|---|
| 延迟 | TTFT p50/p95/p99、TPOT p50/p99、端到端 p99 |
| **拆解** | **排队时间**、prefill 时间、decode 时间——**必须分开** |
| throughput | input tok/s、output tok/s、goodput（达标请求/s） |
| 引擎内部 | running / waiting 序列数、**KV cache 利用率**、**抢占/重算次数**、prefix cache 命中率 |
| 资源 | 显存占用、**MFU**（不是 nvidia-smi 的利用率）、网络 |
| 错误 | 5xx 率、429 率、OOM 次数、超时率 |

### 8.2 离线

| 类别 | 指标 |
|---|---|
| 产出 | **goodput（最终入库样本/GPU-hour）**、tokens/GPU-hour、&#36;/M token |
| 进度 | 完成率、**ETA 及 ETA 的漂移量**（ETA 一直后退 = 并发在退化） |
| 并发 | 有效并发 vs 目标并发、AIMD 退避次数 |
| 可靠性 | 抢占次数与恢复耗时、重试率、**dead-letter 计数**、**finish_reason 分布** |
| 流水线 | 各阶段队列深度、各阶段 tokens/s（找瓶颈） |

### 8.3 两条"这个指标在骗你"

1. **`nvidia-smi` 的 GPU 利用率是骗人的。** 它报的是"有没有 kernel 在跑"，不是"算力用了多少"。一个 batch=1 的 decode 循环可以让它显示 100%，而实际 MFU 不到 5%。**要看 MFU 或 tokens/s per GPU。** 这是面试里非常有区分度的一句。
2. **平均延迟是骗人的**（§2 的 M/M/1）。均值 200 ms、p99 5 s 是一个完全正常的（且很糟的）状态。
