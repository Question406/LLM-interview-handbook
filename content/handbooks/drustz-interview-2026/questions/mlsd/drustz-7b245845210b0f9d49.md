## 3. 生成范式对比 ⭐⭐⭐

### 3.1 六种范式的取舍表

| 范式 | 机制 | 多样性来源 | 单条成本 | 典型失效 | 什么时候选 |
|---|---|---|---|---|---|
| **模板 / 程序化** | 语法、槽位填充、程序合成（如自动出题、代码变异） | 组合空间（可穷举、可控） | 近似 0 | 表面变化大、语义变化小；模型很快学到模板指纹 | 需要**精确控制**某个因子（数值范围、代码结构、噪声类型）；需要 100% 正确标签 |
| **LLM zero/few-shot 直接生成** | 写个 prompt 让模型造 | prompt + sampling噪声（**很弱**） | 低 | 模式坍塌：几千条里就那几种句式和主题 | 只适合快速 smoke test，不适合规模化 |
| **Self-Instruct** | 少量种子任务 → 模型自举生成新指令 → 过滤 → 回填输入输出 | 种子池 + 迭代扩池 | 低 | 指令越滚越像；需要显式相似度过滤（原论文对已有指令 ROUGE-L > 0.7 就丢弃） | 从 0 到 1 造指令数据；Alpaca 用它以约 500 美元造出 52K 条 |
| **Evol-Instruct** | 对已有指令做定向"进化"：加约束、加推理步数、具体化、复杂化输入（in-depth）+ 换主题（in-breadth），并淘汰进化失败的 | 进化算子的设计 | 中 | 进化过头变成不可解或题意矛盾；**必须配一个"进化失败检测"** | 有一批简单指令，想造难题；难度阶梯需要连续可控 |
| **从真实数据反推** | 拿真实文档反向生成问题/指令（instruction backtranslation）；或把网页按风格改写（rephrase，如 WRAP 报告约 3× 预训练加速） | **真实语料的多样性**（最强） | 中 | 反推出的问题与文档不自洽；改写引入事实漂移 | 有大量无标注真实文本时的**首选**。事实性来自真实文本，表达多样性来自改写 |
| **distillation / rejection sampling** | 强 teacher 产多个候选 → verifier 或 judge 选 → 只留通过的（STaR / RFT 家族） | teacher 的sampling多样性 | 高 | teacher 不会的能力蒸不出来；teacher 的系统性错误被放大 | 有可验证信号时性价比最高；Nemotron-4 340B 报告其对齐数据 98% 以上为合成 |

### 3.2 三条能当"判断力"讲的结论

**结论 A：多样性来自 seed，不来自 prompt。** 在 prompt 里写"请生成多样的题目"几乎无效。HuggingFace 的 Cosmopedia（25B token 合成教科书语料）复盘的核心经验就是：多样性靠**种子的多样性**——从真实网页聚出的主题、不同的受众设定、不同的文体，而不是靠让模型自己发挥。这条在面试里非常好用，因为它把"多样性"从玄学变成了可工程化的东西：**多样性是sampling设计问题，不是 prompt 工程问题**。

**结论 B：范式要混着用，而且要分阶段。** 我在 Reflection 做 math/STEM 数据的真实做法是一条**多阶段 LLM 流水线**，而不是一次生成：

```text
seed：开源数据集 + 原始文本（教材 / 论坛 / Stack Exchange / 竞赛题）
  → stage 1  question rewriting：补全缺失前提、去掉图片依赖、统一表述
  → stage 2  QA 转换：把不可验证的题改写成可验证形式（唯一数值答案 / 可判定命题）
  → stage 3  answer rewriting：规范解题格式，剥离与答案无关的闲聊
  → stage 4  质量特征打分（自包含 / 无矛盾 / 假设充分，见 §4.2）
  → stage 5  难度探测与筛选（§5）
  → 出库（带 provenance）
```



**"把不可验证的题转成可验证的题"是这条流水线里价值最高的一步**——它把下游从"只能靠 judge"变成"可以靠程序"，直接决定了 §4 漏斗的成本结构。面试里讲这一步比讲任何 prompt 技巧都有分量。

**结论 C：合成数据最好的用途往往是"改写"而不是"凭空造"。** 凭空造的东西受限于 generator 的知识；改写真实文本时，事实来自真实语料，模型只负责换表达。前者容易hallucination，后者不容易。phi 系列那类"教科书质量"合成语料之所以有效，也是因为它是**在真实知识上做教学化重组**，不是无中生有。
