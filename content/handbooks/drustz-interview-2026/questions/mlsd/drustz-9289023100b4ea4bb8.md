## 8. 分布偏移：怎么量、怎么校正

### 8.1 度量工具箱

| 方法 | 做法 | 读法 | 适用 |
|---|---|---|---|
| **判别器二样本检验（C2ST）** | 训一个分类器区分真实 vs 合成，报 held-out AUC | AUC ≈ 0.5 → 不可区分；AUC 高 → **看分类器最看重的特征，那就是 artifact 清单** | **首选**。便宜、可解释、直接给出修复方向 |
| **TSTR vs TRTR** | Train-on-Synthetic-Test-on-Real 与 Train-on-Real-Test-on-Real 对比 | 差距即"合成数据的可替代性" | 隐私替代场景的**标准评估** |
| **MAUVE** | 在 embedding 空间聚类后比较两个分布的散度前沿 | 单一标量，适合做趋势监控 | 开放式文本生成 |
| **precision / recall 分解** | 生成分布落在真实分布支撑内的比例（precision）vs 真实分布被覆盖的比例（recall） | **必须分开看**：高 precision 低 recall = 只会造安全的常见样本；低 precision = 在造真实世界不存在的东西 | 想区分"质量问题"还是"覆盖问题"时 |
| **边缘分布对比** | 长度、perplexity（冻结reference model）、词频齐夫曲线、实体分布、标签分布 | 最便宜的一层，先跑这个 | 永远先做 |

**C2ST 的用法值得展开讲**：AUC 0.95 不只是"差别大"，它还告诉你**差在哪**——去看分类器的 top feature。我见过的典型 artifact：合成样本长度分布过于集中、几乎不出现拼写错误、标点用法过于规范、总是以某几个固定短语开头、数字总是整数。**这些都是可以直接回去修 prompt 的。**

### 8.2 校正手段

| 手段 | 说明 | 代价 |
|---|---|---|
| **重要性加权** | 用 C2ST 判别器的输出算权重，在训练时给"更像真实"的合成样本更高权重 | 权重方差可能爆炸，要 clip |
| **rejection sampling对齐** | 用判别器直接拒掉最容易被识别为合成的样本 | 会降低多样性（把尾部砍掉了，可能加速坍塌） |
| **调整生成配置** | 按 C2ST 的 top feature 反向修 prompt / sampling参数 / seed 分布 | **最根本的修法，优先做这个** |
| **调整混合比例** | 不修分布，改用量。用 ablation 扫 5% / 10% / 20% / 40% | 最实用；很多时候少加一点就够了 |
| **只在缺口处补** | 不追求全局分布匹配，只在 taxonomy 网格的空格子里生成 | 目标是长尾覆盖时的**正确做法** |

### 8.3 一个必须说清楚的反直觉

**"和真实分布越接近越好"是错的**，取决于 §1.2 的目的：

- 隐私替代：越接近越好（但要防泄漏，见 §9）。
- 长尾覆盖：**故意偏离**——如果你的合成数据分布和真实分布一样，那它对长尾就毫无贡献。
- 难度控制：分布无关，只要可解率落在区间。

所以我在报告里会写"相对真实分布的偏移量"，但**不会把它当作要最小化的目标函数**，而是当作一个必须被解释的量：这个偏移是我要的吗？
