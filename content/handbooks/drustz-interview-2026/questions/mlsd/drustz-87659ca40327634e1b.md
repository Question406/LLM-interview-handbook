## 9. 在线评测：为什么线上指标也会骗你 ⭐⭐⭐

离线→在线的发布阶梯见 [08 §6](?book=drustz-interview-2026&section=mlsd&question=drustz-f15a9e25a058981436)，不重复。这里只讲对话助手特有的坑。

### 9.1 在线信号的偏差清单

| 信号 | 覆盖率 | 主要偏差 | 正确用法 |
|---|---|---|---|
| **thumbs up / down** | 通常 <1% | 极化（只有很满意和很不满的人点）；用户点的是"感觉对"不是"事实对"（专业领域用户根本无法验证）；**系统性奖励讨好** | 只当**变化检测**（突然掉了 = 出事了），不当水平判断；按用户分群去重，防止重度用户主导 |
| **regenerate / 编辑重发 / 立刻改问** | 高 | 也可能是用户在探索 | **最好的免费负信号**，比 thumbs 覆盖率高两个数量级 |
| **复制代码 / 点击引用 / 采纳建议** | 中 | 只在特定域可得 | 高质量正信号，域内可当准结果指标 |
| **会话轮数 / 时长** | 全量 | **方向歧义**：可能是深入使用，也可能是卡住反复问 | 必须与"是否完成"联合看；单独用会奖励啰嗦 |
| **次日 / 7 日 / 30 日留存** | 全量 | 受一切因素影响，延迟长 | 最终指标，用 cohort + 长期 holdback 测 |
| **付费转化 / 流失** | 全量 | 延迟最长 | 季度级复盘 |

### 9.2 必讲案例：2025 年 4 月的 GPT-4o 讨好回滚

公开事件，面试里非常好用（说清是公开信息即可）：OpenAI 在一次 GPT-4o 更新后出现明显的过度讨好（sycophancy），几天内回滚。他们的公开复盘里给出的原因和教训，正好命中本节三个要点：

1. **引入了基于用户 thumbs up/down 的额外奖励信号**，削弱了原本抑制讨好的主奖励 → **用户即时偏好不是长期效用的无偏代理**。
2. **离线评测和 A/B 都没抓到**——A/B 里用户"喜欢"这个版本 → **短期参与指标会奖励讨好**。
3. **少数专家测试者定性上"感觉不对"，但没能阻止发布** → **定性专家评审应该有 veto 权，不能只作参考输入**。

**这个案例的迁移用法**：我在 Reflection 手动检查 RL trace 时，就是靠人眼发现了格式化推理、失控推理、错误推理和 reward hacking——**这些在任何聚合指标上都看不出来**。所以我会在发布流程里固定安排"读 N 条原始输出"的环节，并且给它拦截权。这不是仪式，是唯一能发现"指标没定义过的失败模式"的手段。

### 9.3 CSAT 与真实留存为什么会背离

| 驱动即时满意的因素 | 驱动长期留存的因素 |
|---|---|
| 被认同、被夸 | 任务真的完成了 |
| 回答快 | 没有被误导过 |
| 回答长、看起来很全面 | 出错时会明确说"我不确定" |
| 语气热情 | 一致、可预期 |

两列几乎不重叠——**这就是背离的机制**。三条对策：

1. **即时偏好和延迟结果分开建模、分开报**，绝不合成一个数。
2. **长期 holdback**：留一小部分用户几周到几个月不接受新版本，用来测量累积效应。短期 A/B 测不到信任侵蚀。
3. **主指标配反向 guardrail**：满意度涨的同时，看"事实错误率""过度同意率""用户后续纠正模型的比例"有没有一起涨。

### 9.4 A/B 的技术坑（对话产品特有）

- **随机化单位是用户不是会话**：同一用户跨会话必须粘住同一版本，否则体验不一致且污染留存指标。
- **延迟是混杂变量**：更慢的模型参与度天然更低，和质量无关。要么对齐延迟，要么把延迟作为协变量回归掉。
- **Novelty effect**：新行为（比如更爱提问澄清）前两周指标会动，之后回归。看曲线不看单点。
- **用户会适应**：用户学会怎么给这个版本写 prompt，这本身是长期收益但短期看像噪声。

> **诚实边界**：我在 Meta 做 Instagram Reels / Facebook Feed 推荐建模时，深度参与过大规模在线实验的指标设计、延迟指标 join 和 cohort 分析，这套实验方法论我是熟的。但**我没有做过 LLM 对话产品的线上 serving 与 oncall**，所以像"模型延迟抖动如何影响会话完成率"这类，我只能给设计和验证方案，不能给经验数字。
