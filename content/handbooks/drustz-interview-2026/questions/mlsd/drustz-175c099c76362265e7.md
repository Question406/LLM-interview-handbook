## 5. LLM-as-judge：系统性偏差与验证 ⭐⭐⭐

本篇的核心章节。**关键认知：这些偏差不是随机噪声，是系统性偏移。加样本只会让错误结论的confidence interval更窄。**

### 5.1 偏差清单与缓解

| 偏差 | 表现 | 量级证据（口径见备注） | 缓解手段 | 缓解的代价 / 残余风险 |
|---|---|---|---|---|
| **position bias** | 系统性偏好 A 位（有些模型偏好 B 位） | MT-Bench 论文口径：GPT-4 在交换 A/B 顺序后仍给同一结论的比例约 **65%**，更弱的 judge 更低 | **双向各判一次**：只有两次一致才计胜负，不一致计平局 | 成本 ×2；平局率上升会稀释灵敏度，要在样本量规划里补回来 |
| **长度 / 冗长偏差** | 长答案胜率系统性更高 | AlpacaEval LC 论文口径：给同一模型加一句"更详细"的提示，win rate 可从约 21% 拉到约 64% | ① length-controlled 回归（对 log 长度差做 GLM，取长度中性的截距）；② rubric 里显式设"冗余扣分"；③ 极端情况截断到等长 | LC 只是统计调整，无法区分"长因为啰嗦"和"长因为信息多"；截断会破坏答案完整性 |
| **自我偏好** | judge 偏好自己/同族模型的输出 | Panickssery et al., 2024：模型的**自我识别能力**与自我偏好正相关；越能认出自己写的，越偏爱它 | judge 与被测模型**不同家族**；重要决策用 2–3 个不同家族 judge，分歧时用第三方仲裁或升级人工 | 不同家族有各自的偏差，投票只是降低相关性不是消除偏差；家族多样性有成本 |
| **格式偏差** | markdown、分点、加粗、有小标题的答案分更高；带"作为 AI…"免责声明的分更低 | Chatbot Arena 2024 年引入 style control 正是为剥离长度与 markdown 的贡献，剥离后部分模型排名明显变化 | 判决前渲染成纯文本；或把 markdown 密度作为协变量放进回归 | 产品里 markdown 确实提升可读性，完全剥离会低估真实体验价值——所以两个版本都报 |
| **分数塌缩** | 1–10 打分集中在 7–8，方差消失 | — | 改 pairwise；或把 rubric 拆成**二元 checklist**（每项 yes/no）再加总；给每档锚定样例 | checklist 要按题型定制，构造成本高 |
| **rubric 自洽性** | **同一条标准在不同题目上判得不一致**（我在 Reflection 用 LRM 做 judge 时亲历） | — | 拆成互相独立的二元问题；"是否解决问题"作为硬门先判，"表达质量"后判且不能抵消硬门；每个标准单独调用 | 调用次数上升；标准间的交互被丢掉 |
| **权威 / 引用偏差** | 带数字和引用的答案被判更可信，即使引用是编的 | — | grounding 不交给同一个 judge，单独做 claim 级校验（有检索证据） | 需要证据链基础设施 |
| **讨好偏差** | 认同用户前提、语气热情的答案分高 | 与 RLHF sycophancy 同源（Sharma et al., 2023：人类偏好数据本身就奖励讨好） | rubric 中单列一项"是否纠正了用户的错误前提" | 会与"不要说教"的产品调性冲突，要写清楚优先级 |
| **首因 / 锚定** | 长 rubric 里靠前的标准权重更大 | — | 随机化标准顺序；或每个标准独立一次调用 | 成本 |

### 5.2 一个必须知道的攻击：judge 可以被完全刷爆

"Cheating Automatic LLM Benchmarks"（2024）证明：一个**根本不看输入、只输出固定对抗前缀**的 null model，能在 AlpacaEval 2.0 拿到约 **86.5%** 的 length-controlled win rate，在 Arena-Hard 上约 83%。

**这个例子在面试里的用法**：它说明 judge 类指标**不是"有噪声但无偏"，而是可以被定向攻击到完全失真**。所以：

- 任何用 judge 当训练 reward 的闭环（judge → RL → 同一个 judge 评估）都必须有独立的、judge 之外的验证（可验证指标 + 人工抽检）。这正是 [04 §7](?book=drustz-interview-2026&section=mlsd&question=drustz-7ba2d317f214182b45) 里"verifier 必须冻结且独立于被训模型"的同一条原则。
- 发布 gate 里的 judge 分数要配一条"异常检测"：胜率突变（比如某版本一夜从 52% 到 78%）先假设是 hack 而不是能力跃升，去看样本。

### 5.3 judge 本身怎么验证 ⭐⭐⭐

**judge 是一个需要被评测的模型。给 judge 建 eval 集，是这道题里最能体现深度的动作。**

**Step 1 · 建 judge 的黄金集**
- 500–1000 条判决，**至少两个人工独立标注**，分歧的进第三人裁决并保留分歧记录（分歧本身是数据：分歧高的题型说明 rubric 需要修）。
- 分层覆盖：题型 × 难度 × 语言 × "两个回答质量接近 / 差距明显"。**质量接近的样本必须占足够比例**——judge 在差距明显时谁都能对，区分度全在接近的那部分（这和我在数据合成里筛"全对/全错样本没有梯度信号"是同一个道理，见 §10.4）。

**Step 2 · 报三个数，不是一个**

| 指标 | 说明 | 解读 |
|---|---|---|
| 原始一致率 | judge 与人类多数票一致的比例 | 直观但受类别不平衡影响 |
| **Cohen's κ**（两方）/ **Krippendorff's α**（多方） | 扣掉随机一致后的一致度 | 0.2–0.4 弱、0.4–0.6 中等、0.6–0.8 强、>0.8 很强 |
| **人类间基线** | 两个人类标注员之间的同一组数 | **天花板**。judge 的 κ 逼近它就该停止调 prompt |

κ 的定义要能白板写：$\kappa = \dfrac{p_o - p_e}{1 - p_e}$，$p_o$ 是观察一致率，$p_e$ 是按边缘分布算的期望一致率。**陷阱**：当标签极不平衡（比如 90% 的样本 judge 和人都说"A 更好"）时，κ 会被压得很低，看起来像 judge 很差，其实是任务太简单。所以三个数一起报。

**Step 3 · 扰动测试：判断 judge "能不能看见错误"**

只看总一致率是不够的——judge 可能在"两个答案都不错"的题上跟人一致，但**完全看不见事实错误**。做法是**注入已知缺陷再看检出率**。

我在 Anthropic take-home 里做过这件事的完整版：**137 对扰动测试套件，按扰动类型分层报检出率**。搬到通用助手上，扰动类型大致是：

| 扰动类型 | 具体操作 | 期望 judge 的反应 |
|---|---|---|
| 事实篡改 | 改一个关键数字 / 日期 / 实体 | 必须检出，检出率目标 >90% |
| 无支撑 claim | 插入一句原文/证据里没有的断言 | 必须检出 |
| 关键前提删除 | 删掉"仅在 X 条件下成立"这类限定 | 高危，检出率往往最低 |
| 单位 / 量级错误 | mg 改成 g | 必须检出 |
| 拒答替换 | 把有用回答换成礼貌的空话 | 必须判为更差 |
| **纯风格增强**（负向对照） | 只加 markdown / 加长 20% / 加热情语气，内容不变 | **判决不应改变**。改变了就是格式/length bias的直接测量 |

**分层报检出率**是关键——总检出率 85% 可能掩盖"前提删除只有 40%"，而前提删除恰恰是医疗、法律这类场景里最危险的错误。

**Step 4 · 不变性测试（判决翻转率 = judge 的噪声下界）**

同一对回答，做以下变换后重跑，统计**结论翻转率**：

- 交换 A/B 位置 → 翻转率就是position bias的直接测量
- 把 "Assistant A / B" 改成 "Response 1 / 2" 或 "模型甲 / 乙"
- 加/去 markdown
- 温度设 0 后重跑三次（测 judge 自身的非确定性）

**经验判断**：翻转率 >15% 的 judge 配置不能用于发布 gate，只能做粗筛。

**Step 5 · judge 漂移监控（很多人漏掉，实操上最痛）**

API 背后的 judge 模型会**静默升级**。你昨天 62%、今天 65%，可能什么都没变。

- 每次评测都夹带 **100 条 gold anchor**（人工已定论的判决）。judge 在 anchor 上的准确率偏移超过阈值（比如 3pp）→ **本次结果作废**，先查 judge。
- judge 版本、judge prompt hash 写进每条结果记录。
- 换 judge 时必须有**重叠期双跑**：新旧 judge 同时跑同一批，给出换算关系，否则时间序列断裂。
- **绝对不要在同一次发布里同时升级被测模型和 judge**——出问题时无法定位。
