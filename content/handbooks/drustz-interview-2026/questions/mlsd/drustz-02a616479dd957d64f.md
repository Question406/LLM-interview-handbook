## 15. 10 分钟口述稿 ⭐⭐⭐

> **（澄清，1 分钟）** 我先确认四件事：训的是哪个 checkpoint、用什么 RL 算法和多大的组、目标是单域还是多域、以及数据生成和训练是不是共用同一批 GPU。最后一条最容易被忽略——**筛选本身就是 rollout，它是从训练预算里扣的**。
>
> **（定位，1 分钟）** 我要强调一个和 SFT 数据的根本区别：这条 pipeline 的产出物不是「问题 + 标准答案」，是**一组带 verifier 的 prompt，且每条对当前策略而言处在有梯度信号的难度带里**。在 SFT 里「好答案」是资产，在 RL 里它只能存在于 verifier 一侧——泄漏到 prompt 里的答案会让这道题 pass rate 变成 1，然后被我的难度筛选静默删掉。
>
> **（指标，1 分钟）** 所以我汇报的不是「造了多少条」。我报**有效梯度产出率**——一个 batch 里既不全对也不全错的组占多少。它能直接换算成钱：如果是 60%，说明 40% 的 rollout 预算生成的 token，advantage 恒等于 0。最终裁判还是固定算力下的下游 eval 提升，但那个反馈要几天，所以中间要靠有效梯度率、策略熵、平均长度这三个领先指标。
>
> **（供给，1.5 分钟）** Prompt 有四条供给线：开源集（已被榨干且是污染重灾区，只当 baseline）、**原始语料转换（这是真正的产能，也是我在 Reflection 的主线）**、合成（用来定向填难度空洞，不做主力，因为种子少会多样性坍缩）、真实用户分布（量少但用来定义合成往哪儿靠）。原始语料那条线我做的是一个多阶段 LLM 流水线：解析 → 抽题 → question rewriting 做成自包含题面并剥离答案 → answer rewriting 从散落讨论里归纳唯一答案 → QA 转换。质量特征我打的标是：自包含、无矛盾信息、假设是否给足、答案唯一、无泄漏。**「无矛盾」这条对 RL 特别关键**——矛盾题在 SFT 里只是噪声，在 RL 里它的 pass rate 会稳定在一个低值，**恰好落进我的难度保留带**，被当成好难题大量 rollout。所以质量 gate 必须在难度探测之前。
>
> **（可验证化，1 分钟）** 能往规则/符号等价/单元测试/形式化走就绝不停在整体 judge，理由后面讲。转换有三条路：答案抽取加类型化比较器、单元测试化、把证明降级成可数值化的推论。第三条有代价——降级会改变难度，**转完必须重新探测**。实在不可验证的用 claim 级 rubric，把整体打分拆成 N 个独立的 yes/no。这个我有实测支撑：在一个医疗任务上，整体相似度指标预测「不安全回复」的 AUROC 只有 0.569，拆成 claim 级 grounding 之后到 0.844，confidence interval不重叠。**判断迁移过来就是：judge 不一致往往不是模型笨，是我们让它一次做了太多判断。**
>
> **（难度筛选，2.5 分钟——最重的一段）** GRPO 里一个 prompt 全对或全错，组内优势严格为 0，但照样消耗 G 条 rollout。**如果池子平均 p 是 0.9、G 是 8，那 43% 的 rollout 算力生成的 token 对应的 advantage 恒等于零。** 我的做法是两阶段：正式 rollout 之前先用 **16 条**探测，全对全错的直接丢，保留的再跑 **128 条**，**大约 12% 算力花在筛选上**。16 这个数字是算过的：以「全对或全错」为判据，真实 p 在 0.2 到 0.8 之间的题误杀率不到 3%，但 p 超过 0.95 的能捞掉四成以上——它不是一个精确的 p 估计器，**我也不需要精确估计 p，我只需要区分退化和不退化**。这个思想和 DAPO 的 dynamic sampling 是一致的，区别是它在训练循环里做、永远贴合当前策略但每步耗时可变且不可复用；我在离线做、便宜可抢占可复用但会过期。**我的答案是叠加：离线粗筛干掉「对任何近期 checkpoint 都退化」的大头，在线细筛处理漂移的残差。**
>
> 然后是漂移：**难度不是题目的属性，是题目、策略、sampling参数的联合属性**。策略变强，整个池子的 p 向右漂，训到中期梯度就没了。所以阈值必须自适应——训练本身的 rollout 就在免费提供每道题的当前 pass rate，用它维护滑动估计；平均 p 越过上界就触发对 reserve 池的重探。**早期判为「全错」的题绝对不能删，要进 reserve**，它们正是几千步之后的燃料。
>
> **最后一个关键区分**：组内优势为 0 有两个来源——题目退化和熵坍缩。筛数据只能解决第一个。所以我同时监控策略熵和组内答案的唯一值个数，避免把优化问题误诊成数据问题。
>
> **（reward 与 hacking，1.5 分钟）** verifier 的两类错误代价严重不对称：假阴性只是噪声，假阳性会被策略**主动搜索**——RL 的机制就是找高 reward 路径，而假阳性区域是免费高分。所以我对「判对」这一侧要求高 precision，**匹配要严格、等价要宽松**。搞反了就是最经典的 hack：宽松匹配加严格等价，模型学会枚举一串候选答案，只要正确答案在里面就通过，而 pass rate 曲线看起来完全正常。
>
> 检测靠读 trace，这是唯一能发现我没预料到的失败模式的通道。我实际见过四种：格式化推理（推理有外形没做功，用 CoT ablation验证——截断推理强制作答，准确率不掉就是它）、失控推理（撞 max_tokens，注意不要对截断一刀切给 0，那是噪声惩罚）、错误推理侥幸答对（小答案空间的题天然高危）、答案泄漏。读 trace 我是分层抽样加固定节奏：最高 reward 的、组内方差最大的、pass rate 跨 checkpoint 突然从 0 跳到 1 的（这是假阳性被发现的瞬间，最强的 hack 信号）、长度 p99 的、新数据源的。
>
> **（基础设施，1 分钟）** 一轮 10000 题的探测加 rollout 大概要生成 **90 亿 token**——和一次小规模预训练的数据量同量级，而且是 decode 不是 training。所以这首先是一个batch inference系统。我们的卡是共享池，被抢占是常态，我自建了 pause/resume 框架：工作单元细到 (prompt_id, sample_idx)，结果 append-only 带idempotency key，resume 就是 diff；动态申领和让出容量；并发用 **TCP 式的 AIMD** 调节——成功加性增加，失败窗口内乘性退避。这里有两个调出来的细节：**必须用失败窗口率而不是单次错误退避**，否则瞬时错误会把并发打到零；**必须有并发下限**，否则退避之后爬不回来。
>
> **（闭环，30 秒）** 整个东西是个环：训练 → 读 trace → 归类失败模式 → 回改 verifier、质量 gate 或难度带。我会区分哪些观察值得回流——一类 hack 出现在超过 1% 的高分 trace 里才做成规则，单条题判错就直接修那条，不做成规则。
