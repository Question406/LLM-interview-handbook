## 题目描述

公开示例仅给出“实现对 agent 友好、具有任务依赖关系的 Todo List”这一任务方向，没有完整 API、样例或测试。下面是手册重构的小型实现练习，所补规则不是官方原题要求。

### 任务与接口

实现一个内存任务管理器。每个任务有唯一字符串 ID、标题、完成状态以及依赖任务 ID 集合。提供创建任务、增加依赖、标记完成、列出所有任务和列出当前可执行任务的接口；可用类方法或等价函数组织，但需说明输入和返回格式。

创建任务时默认未完成。任务仅在所有依赖已完成时才能被标记完成；依赖未满足时保留状态并报告未完成依赖。给任务增加依赖时，若新依赖造成自环或间接环，则拒绝该更新且保留原图。其他输入合法，引用的任务都已存在。为让 agent 能继续采取动作，返回结果应包含稳定的任务 ID 和明确的状态，而不是只打印自然语言。

列出当前可执行任务时，只返回尚未完成且所有依赖已完成的任务；列表按 ID 升序返回，不能重复。提交实现、使用示例，以及正常依赖链和环检测的简单测试。

### 示例

创建 A“收集资料”、B“写总结”、C“检查格式”，添加 B 依赖 A、C 依赖 B。开始时可执行列表为 `[A]`。完成 A 后为 `[B]`，完成 B 后为 `[C]`。若尝试增加 A 依赖 C，应报告形成依赖环，原依赖关系保持不变。

## 解题思路与参考答案

Perplexity 的动手编码不考力扣，一轮一到两名面试官，大多 30–60 分钟，题分成几个 part，不要求做完。官方给的例题只有一句：Todo List，做一个对 agent 友好的任务列表，支持依赖管理。准备的重点是在 CoderPad 里一个 part 一个 part 写干净，别为了赶进度写乱。

这些都来自 Perplexity 自己的候选人说明，没有哪次 onsite 的复盘，所以是 `realInterview: false`。页面写明例题只用来说明风格，别押这几道原题。例题没有函数表，也没有样例输入。招聘官可以给一个 CoderPad 练习链接。

流程上，开头结尾各留 5–10 分钟。现场可以用自己的电脑，也可以借。远程要共享整个屏幕，共享失败不补时间。CoderPad 能写也能跑。Part 1 通常是读说明、签诚信声明，之后才是题目，做完一部分和面试官一起对一下，再进下一部分。

时间到了没做完很正常。他们让自己的工程师、经理和联合创始人在不准备的情况下做过同一题来定标，做完所有 part 不是通过条件。写乱了往前赶，比停在一个正确的 part 上更差。

题是他们的人按自己系统里的组件出的，不用力扣、HackerRank 题库。他们期望你会用数组、字符串、字典、集合、堆、排序、图上的遍历和类；最长公共子序列、编辑距离、斐波那契堆、树状数组、后缀树、Dijkstra、最小生成树、最大流这些不期望。语言优先 Python，也提供 C++、Go、Rust、TypeScript。Java 他们写明强烈不建议，样例数据显示选 Java 的人更难通过，时间都耗在样板代码上了，只有你非常熟才选 Java。训练、推理、前端这类专门岗位可以换领域，考察思路一样。

AI 的规矩是不许用 AI 或别人写答案，也不许搜题。例外有两个：查在线语言文档；用 Perplexity、搜索引擎或别的 AI 问某个库怎么用，包括看用法示例。答案的主要部分不能让工具写。

## 待办这道例题我会怎么拆

页面没给规格，我会按「多 part、带依赖」自己拆成三段，每段都能单独做完，用来体会他们的节奏，别当成真题答案。最开始，任务有 id、标题、状态，能添加、完成、按状态列出。接着让任务可以依赖别的任务，完成前检查依赖都已完成，往依赖图里加边时用 DFS 拒绝环。最后给 agent 一个读接口，返回未完成、且依赖已满足的任务，字段稳定，别把整张内部字典丢出去。

「对 agent 友好」我理解成返回值可预测，出错时给一个明确的值，别抛一串栈。这是我自己的读法，页面没解释这个词。线程安全也不用加，除非这一 part 在考并发。他们的说明里写了，题干没把并发当重点，就别写锁。

## 追问

**依赖失败要不要把下游标成失败？**
页面没说。先做成「不能完成」，下游保持未完成。级联失败是新语义，等面试官加上了再写。

**能不能拿 Python 的 `hash()` 做缓存 key？**
别用。这道例题未必有缓存；如果某个 part 要按内容去重，用稳定的摘要，别用内置 `hash()`。

**最后一个 part 没做完怎么办？**
没关系，他们的校准写了这不是要求。把已经做完的 part 跑给面试官看，比留下一个编译不过的第三 part 好。
