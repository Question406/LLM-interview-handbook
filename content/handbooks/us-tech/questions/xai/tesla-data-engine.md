## 可以这样回答

## 技术备查

数据引擎把一次路上失败变成下一轮可验证的训练数据：触发采集、回传短 clip、离线自动标注、人修错、训练发布，再检查同类失败有没有减少。比如车道头判断能走、占用头却看到障碍，这种矛盾就值得触发采集。

这道架构题依据 AI Day 对车队采集、难例触发、向量空间标注、离线自动标注和仿真补盲的公开介绍。Karpathy 早期提过「99.9% 的秒很好开，要找那 0.1%」。这些是公开机制，不能据此补写某次 onsite 原话、车队数据条数或标注员规模。

沿着这个 feedback loop，每一步都有具体的输入和作用：

1. 触发。车上模型低置信、多相机互不一致、规划接管、影子模式和人类驾驶分歧、专门的 clip 请求（某类施工、某类加塞）。
2. 回传。只传短 clip 加传感器包，不是全天视频。带宽和隐私都限制「全量上传」。
3. 离线自动标注。用更重的模型、未来帧、多相机、时序，在向量空间出 3D 框 / 占用 / 车道。车上跑不起这个。
4. 人修正自动标注失败的位置，减少从零画几万框的工作。改过的 clip 同时进入训练集和评测集，后续评测还要检查同类错误，避免把相同错误再次训回去却误以为涨点。
5. 训练与发布。多任务头见 `tesla-hydra-nets`。发布后再用新模型挖下一轮失败。

数据引擎的单位是 clip + 向量空间标签。单张图上的 2D 框投影不到规划用的 3D。自动标注 data quality checks 见 `tesla-autolabel`。

随机抽帧容易集中在空旷高速。难例触发可以关注模型错了但人没接管的沉默失败、人接管时模型仍很自信的 calibration 问题，以及车道与占用头互相矛盾的情况。后两种信号比单纯 loss 高更贴近产品事故。

公开叙事里，自动标注吃的是「已经发生的真实几何」：遮挡后行人仍在、车辆从视野外进到视野内，用未来帧回填。仿真吃的是「真实里不够密」的组合：罕见交通灯 + 大车遮挡 + 暴雨。仿真标签完美但分布偏；自动标注分布真但有系统误差。仿真当压力测试和覆盖，真值仍以车队 clip 的审计过的标签为准。

feedback loop 的评测集必须冻结。每轮只往里面加「新失败模式」的金标，不要用当前模型的自动标注刷新评测，否则指标会自我表扬。Occupancy 评什么见 `tesla-occupancy-net`。

训练数据的 feedback loop 和车载执行需要分开设计。离线可以用更重的模型补标，车上则必须遵守实时延迟，见 `tesla-latency-slo`。

一轮 feedback loop 看冻结集上某一类失败有没有掉，不看「又标了多少小时」。比如加塞漏检：触发召回、自动标注同意率、人改后的 交并比（IoU，即两个区域的交集与并集之比）、上路影子分歧，四条要能对上。这些指标对不上时，要检查训练与评测的分布是否失配。

上传优先传「人机分歧 + 低置信」，不要优先最长视频。带宽是数据引擎的硬约束，和模型精度同一级。没进回传队列的失败，feedback loop 不存在。

影子模式只能当触发：人没接管不等于标签正确，更不等于规划最优。金标仍然要过协议和抽查，见 `tesla-autolabel`。

## 追问

**影子模式标签能当金标吗？**
能当触发，不能当金标。人开得对不等于几何标注对，也不等于规划最优。金标仍要过标注协议。
**失败太稀怎么办？**
提高触发召回（宁可多传），再用离线模型筛。稀有类用分层和仿真，不要等自然出现。
**feedback loop 何时停止？**
不以「数据量」停，以冻结评测集上的事故类失败率和 calibration 停。新地理、新车型会再打开一轮。
**和通用互联网数据引擎差在哪？**
驾驶标签有物理一致性和安全成本。错一个加塞 clip 比错一张猫图贵。抽查比例要按严重度分层，见 `tesla-autolabel`。
