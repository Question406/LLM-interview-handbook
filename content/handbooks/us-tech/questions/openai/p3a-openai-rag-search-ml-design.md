## 题目

口述设计一个检索系统，面试官会深挖 embedding 怎样训练，以及检索流程的每一步。

> 来源：一亩三分地 OpenAI 题卡摘要（2026-10-18 用 Chrome 读取），是网站对候选人报告的二手整理，没有逐条核对原帖；收录为面经题型不代表公司官方确认。规模数字、SLO 和故障情景是手册补的练习约定。

## 思路

把训练目标和线上指标连起来讲：embedding 用对比学习训练，负例的质量直接影响线上召回效果。只用随机负例，模型学不会区分容易混淆的文档。

线上用稀疏召回（BM25）和稠密召回融合，再交给精排。评估要分段归因：召回、排序和最终答案各自有指标，坏了能定位到是哪一段。评测集按时间切分以防污染，同时核算每一段的延迟预算。

## 完整非编程练习（场景与参考回答）

### 具体题目与需求澄清

设计语义加关键词的混合搜索，并用检索到的证据回答问题。目标是在 500ms 的检索预算内提升事实问答效果，语料每天更新。

开始回答时复述这些范围，问面试官语料规模和有没有点击或标注反馈。

### 一套可展开的参考答案

**1. 架构与关键路径。** 一次查询依次经过：

1. query 理解。
2. BM25 稀疏召回和向量召回并行执行。
3. 候选去重并融合分数。
4. cross-encoder 重排。
5. 裁剪证据。
6. 生成答案并附引用。

**2. 数据模型和状态变化。** 每次查询记录 query、候选 id 和版本、各阶段分数、最终引用和用户反馈。训练对比学习 embedding 时，负例要包含容易混淆的 hard negatives，并保留去污染的留出集。

**3. 走一遍一次查询。** 用户问"某药物的推荐剂量是多少"。BM25 靠药名精确匹配召回几十篇，向量召回找到用别名或描述性说法写的段落；两路结果去重后按排名融合，取前若干条交给 cross-encoder 逐对打分。分数最高的几段被裁剪成证据，生成模型只根据这些证据回答并标注引用。各阶段耗时加起来要落在 500ms 预算内。

**4. 失败、重复与恢复。**

- 一路召回超时，就用另一路降级返回，并给结果打上质量标记。
- 权限过滤放在最前面；索引更新带版本。
- 引用支撑不了结论时，拒答或收窄回答，不让生成模型补充没有证据的细节。

**5. 容量和验证指标。** 分阶段测 recall@k、MRR / nDCG、答案支持率、端到端成功率和时延。离线的改进要经过分层 A/B 验证，避免把检索变差和生成变差混成一个分数。

### 面试追问与参考回答

**融合时为什么不能直接把两路原始分数相加？** BM25 分数和向量相似度的尺度完全不同，直接相加会让一路主导。可以用排名融合、先做分数标定，或者训练一个排序器；分布变化后都要重新评估。

**hard negatives 从哪里来？** 常见做法是用当前模型或 BM25 检索出"排名靠前但不是正确答案"的文档。要剔除其实也是正确答案的假负例，否则会把正确信号当噪声学掉。
