错法：换成多模态大模型就能以图找同款。后端要新增视觉特征服务、图搜索引、工具 schema，以及编排上的「图 → 候选 → 确认」状态；同时评估延迟、成本和审核，避免把整条客服链路拖进视觉推理。图质量差、无版权、或只要文本 SKU 查询时，不要硬上。状态机与确认闸门见 `ali-modular-agent-plan`、`ali-guardrail`。

## 改造落到服务，不是换模型

改造清单：接入特征提取或多模态理解；商品图索引与相似度检索；新 tool（如 `image_search_same_item`）；链路上传 → 检索 → 重排 → 商品卡 → 用户确认；内容安全与版权审核；监控检索空结果率、同款准确率、RT。把原图原样塞进大模型上下文，RT 和费用会暴涨，且没有商品库约束，模型可能编一个「同款」链接。特征服务与图搜是检索系统，生成模型只负责描述候选差异、问确认，不负责当搜索引擎。

索引覆盖率决定上限：没有图的商品、或图是白底棚拍而用户传街拍，召回会空。要准备类目 + 属性的文本回退，两条路共用重排和审核；图搜失败别幻觉补链。

## 图→候选→确认

用户发一张运动鞋街拍。Agent 调图搜拿回 top-k 商品卡，文案只描述候选差异（颜色、尺码、价），等用户点确认才进入加购。没有确认态就自动下单，是资损事故。审核拦截盗图、违禁品、未成年人相关商品；空结果降级为「描述关键属性我帮你搜」。权限上，图搜工具只读；写购物车仍走原有确认与库存校验。

## 延迟、审核与回退

视觉特征提取和 ANN 检索都是新的 p99 来源，要单独设超时，超时回退文本检索，不能阻塞查订单。成本上对大图做缩放与缓存，同一图 hash 命中则跳过提特征。文本检索仍要保留：图搜失败走类目 + 属性，两条路共用重排。评估拆开：检索 Hit@k / 同款准确率，与「用户是否确认加购」的端到端，别只看模型是否「说得像同款」。

## 追问

- **文本检索还要不要？** 要。图搜失败回退类目 + 属性，共用重排和审核。
- **要不要把图塞进对话模型？** 仅当需要描述图中属性时短边送入；检索本身走特征索引。
- **如何定义同款？** 先对齐 SKU / spu / 款式粒度，否则准确率不可比。
- **版权怎么拦？** 上传审核 + 索引侧过滤盗图；模型侧无法可靠判断版权。
