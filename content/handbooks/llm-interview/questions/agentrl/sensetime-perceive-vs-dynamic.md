## 真题记录

- 公司：商汤
- 岗位：大模型算法应用实习；二面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“固定的「感知-推理-校验」流程和动态多 Agent 最大区别是什么。”**；**“如果拆成感知/推理/校验 Agent，哪些能并行，哪些要顺序，什么时候需要反向通信。”**；**“校验 Agent 和推理 Agent 结论冲突时怎么处理”**

商汤这面三问其实是同一张图：拓扑是编译期写死还是运行时拼。固定「感知-推理-校验」把角色和边写死，延迟、权限、失败模式可预期，好评测、好限权。动态多 Agent 按任务现组团队，能并行、能临时加专家，但冲突、成本和责任边界更糊。视频 / 多模态场景多变，后者诱人，但不要默认更强。模块拆法见 `sensetime-agent-three-modules`。

## 固定流 vs 动态组：差在调度权

固定流是编译期拓扑：谁先谁后、哪些工具可见、校验看哪些字段，发布时就钉死。好处是每条边可测、权限可收缩、延迟可估。坏处是遇到没见过的专家需求（突然要 OCR 一张新表）只能走完死流程或整链失败。

动态多 Agent 是运行时调度：orchestrator 按任务拉感知专家、推理、校验，边是临时的。好处是能绕路、能并行多路传感器。坏处是 team reward 更难分，见 `arl-multi-credit`；还容易变成「大家聊天、没人负责」。面试里我会说：能用固定流解决的，先证明拆分降低了可测错误，再动态化。商汤业务里视频场景多变，动态组的卖点是临时加专家模型，不是让三个生成模型自由辩论。

## 并行、顺序、反向通信

拆成三个 Agent 时：

- 可并行：多路感知（不同摄像头、检索、OCR）在同一时间窗内独立跑，结果写入共享快照。部分只读检索也可以和感知重叠。
- 必须顺序：推理依赖「已对齐的感知快照」，不能边看边改世界；任何写操作 / 对外动作生效前必须校验。
- 反向通信：校验失败时把结构化错误（缺字段、证据冲突、越权）打回推理，有限次修复。禁止开放式互喷。超时或两次修复仍冲突就升级，不要无限吵。

共享黑板只放已验证字段，原始模型输出当不可信，见 `xiaohongshu-multiagent-quality`。反向通信的 payload 应是错误码 + 缺哪些证据，而不是再生成一段反驳散文；后者会把延迟和幻觉一起放大。

## 冲突：校验优先，不要投票平均

推理说「可能有人」、校验说「证据不足 / 规则禁止」时，涉及安全、误报、不可逆动作，以校验和规则为准。推理只能提出候选，不能用多数票把不确定平均成「可能没人、也可能有人」。产品上：高严重度停并升级人工；低严重度允许推理在约束内改假设再送检。不要让两个生成模型互相说服。

固定流是编译期拓扑，动态组是运行时调度。感知可并行，写前必校验，反向通信只传结构化错误。冲突时校验和规则优先，不投票。

## 追问

- **动态组什么时候值得？** 任务类型事先未知、需要临时专家模型，且你已经有冲突协议和成本上限。否则固定流更可控。
- **校验会不会成为瓶颈？** 会。只读感知可并行；校验可以对独立证据分片，但合并门必须在动作前。用延迟预算，不要为了并行跳过门。
- **反向通信几次算够？** 先定上限（例如两次）和错误 schema。没有结构化错误码的互喷应直接升级。
- **和训练的关系？** 固定流更好做过程奖励；动态组先冻工人只训调度，见 `arl-multi-credit`。
