## 真题记录

- 公司：蚂蚁集团
- 团队 / 岗位：智能体与大模型应用
- 届别 / 流程：一面
- 面试时间：原帖写 5 月 20 日；帖子为 2026 年讨论
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“如何解决大模型 hallucination？”**

解决 hallucination 要先分清是哪一类，再分别治：知识缺失靠检索或工具，检索错要修索引和 ACL，格式乱用 schema 和约束 decoding，越权编造按注入处理。推理时要求回答能指到证据，没证据就拒答或澄清，系统层再做结构化校验。蚂蚁智能体应用一面，这题最容易答成「加 RAG、prompt 里写不要编造」，金融场景要听的是你能指出证据。

比如用户问某款产品的利率，模型直接报了个数。如果它是在背利率、额度、制度，那是知识缺失，该走检索或工具，用 SFT 背表没用。如果检索召回了一条已经废止、或者用户无权看的条款，看起来像 hallucination，根子在索引和 ACL。字段类型、枚举、JSON 不合规是格式问题，用字段和类型规范（schema）加 constrained decoding。还有一种是把网页或用户的话术升级成指令，去调高风险工具，这属于注入，和知识无关，见 `agent-prompt-injection`。分清这些原因，才能选对处理方法。

分清之后，推理时把检索证据放进上下文，要求引用到具体片段或工具返回；没有证据就拒答或澄清，别补一句「据我所知」。信贷、意见类的回答必须接一条可解释的证据链。系统层对 JSON schema、字段正则、业务规则（额度范围、证件号）做校验，不通过就重试、换工具或转人工。工具输出当数据看，不当权威。评测把「无根据陈述」单独列出来，只看流畅度和任务完成率不够，任务完成了但内容是凭空生成的，在金融里就是事故。

微调适合领域话术、工具格式和拒答风格，别拿它当制度数据库；它能改善格式和术语，事实 hallucination 不会因此自动消失。面试官追到检索增强生成（RAG）时，可以主动说 RAG 只能降低知识缺失，检索错了还会制造新的「有根据的 hallucination」。金融智能体最好把「不确定」做成产品状态，展示证据片段、给过期警告或者转人工，别用更肯定的语气把缺口盖过去。上线后抽样人工审计无根据陈述率，按任务类型切片，再把无根据陈述、错误承诺和越权调用分组统计告警。prompt 里的「不要编造」只是最弱的一层。相关卡：`jd-rag-hallucination-fallback`、`xiaohongshu-hallucination-prompt`。

## 追问

**拒答会不会伤体验？**
高风险槽位宁可澄清。把不确定标出来，比编一个利率更符合合规。

**有引用就一定没 hallucination 吗？**
不一定。可能引错段、引了过期段，或者引用只是装饰。要核对引用是否真的支撑这句断言。

**只加强 system prompt 够吗？**
不够。无根据陈述要靠检索 acceptance checks 和 schema 校验，注入要靠权限，见 `agent-tool-permissions`。

**评测怎么做？**
构造无证据题、过期制度题、冲突条款题，主指标看无根据陈述率和错误承诺，BLEU 说明不了问题。
