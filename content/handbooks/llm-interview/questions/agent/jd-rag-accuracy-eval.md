## 真题记录

- 公司：京东
- 团队 / 岗位：大模型应用开发实习
- 届别 / 流程：实习；一面
- 面试时间：原帖未披露；帖子发布于 2026-03-14
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“如何评测RAG系统的准确率？”**

我会拆成三层分开报：检索有没有把证据召回来，答案是不是忠实于引用，用户的问题最后有没有解决，每层都用金标或独立的自动检查来判断。只报一个「问答准确率」，检索错和生成编造混在同一个数字里，是改索引还是改输入提示（prompt）没法归因。

举个例子，用户问某款商品的价保政策，系统答错了。如果是检索没把那条政策召回来，该改索引；如果政策召回了，模型却在里面多编了一个时效，该改生成。一个总分把这两种情况混在一起，下一步改哪里就说不清。

检索层看相关证据块有没有进入 top-$k$，报 Recall@$k$、nDCG，按 query 类型切片：货号精确查、口语同义、政策条款、无答案。金标是「必须召回的文档 / chunk ID」，和生成文本像不像无关。忠实层看答案里每条断言能不能对齐到引用 span，报无依据断言率、引用错挂率；价格、库存、时效、售后政策必须能指回证据，对不上就拒答，或者降级到结构化字段。任务层看问题是不是真的解决了：字段对、能下单、政策解释对。零售里「答得很像官网、可就是下不了单」也算失败。

自动检查用字符串匹配、结构化字段比对或 NLI 对齐，再用人工抽检校准自动标签。别只报 RAGAS 这类合成总分，它会掩盖「检索更差了，生成在背答案」。报数时主动说分母：Recall 的分母是必须召回的证据，任务成功的分母是用户问题，两者不能共用一个百分比。

## 集合设计与归因

评测集按时间切分，防止文档更新泄漏进评测。必须有无答案题，系统该拒答，别拿参数知识去补。按类目、语言、新老商品切片，微平均 accuracy 会被简单的货号题拉高。线上抽样要覆盖客诉和退款、价保这类高风险问题，频率要覆盖大促前后的政策变更，静态离线集很快就会过时。实习面就算只拿得出小集合，三层也要各有几条金标，并且固定一张「改哪一层看哪一列」的对照表，否则一周后的调参没法复盘。

归因用替换实验。给了 gold 检索就变对，主因在检索；固定 gold 证据还在编，主因在生成，详见 `kuaishou-rag-retrieve-vs-generate`。改检索只许动检索层的指标，改 prompt 只许动忠实层；总准确率升了、召回却掉了，说明模型在背答案。同面连问的 ES、向量库准召是支撑指标，算不上最终准确率，见 `jd-es-vector-usage`；向量库 IVF / HNSW 和混合检索权重也是支撑，见 `jd-hybrid-retrieval-weight`，别把相似度分数当成准确率。幻觉兜底怎么设计见 `jd-rag-hallucination-fallback`。Agent 场景还要再看工具和拒答，见 `jd-agent-eval-beyond-qa`。

## 追问

**没有金标怎么办？**
先抽线上 query，小规模人工标证据 ID，再用它来校准自动 oracle。别让模型给自己打一个总分当最终数。

**和 Agent 评估有什么不同？**
检索增强生成（RAG）这三层只覆盖「知识有没有用对」；Agent 还要评路由、工具合法、恢复，见 `jd-agent-eval-beyond-qa`。

**无答案题为什么必须有？**
没有拒答金标，模型靠参数知识「答对」，分数会虚高，上线后就在编价格和库存。

**准召率和准确率是一回事吗？**
不是一回事。准召是检索层的支撑，准确率还要加上忠实和任务成功。只优化 Recall，可能把干扰文档也灌进上下文。
