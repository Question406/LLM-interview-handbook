## 真题记录

- 公司：京东
- 团队 / 岗位：Agent 开发
- 届别 / 流程：27 暑期实习；二面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“意图识别用的是哪个大模型？如何判断和测试意图识别结果的准确率？”**

我会分层路由：订单号、SKU、明确的「查物流 / 开发票」走规则，模糊的口语交给小分类器或者输出受字段和类型规范（schema）约束的 LLM，置信度低就澄清。用哪个模型是次要的，可以是业务小模型，也可以是通用 LLM，关键是分层和按意图切片的评测。退款、改址这类误路由的业务后果要单独看。

举个例子，用户说「这单不对」，可能是物流延迟、少件，也可能想退款。拿单句分类去赌很危险，要看槽位：有没有订单号、有没有提到钱。判断不了就问一个能帮助确定路由的问题，别直接猜进退款技能。

为什么分层？大模型把「看看我的订单」送进导购还是售后，两种错误的成本不对称。订单号、运单号、广告计划 ID 这类规则能锁死的 query，用规则和词典，延迟低、可解释、好审计，不必每次花一轮 LLM。其余口语用轻量分类器或受限 decoding 的 LLM，输出意图枚举，不输出自由文本；置信度低或者几个意图互相冲突时，就去澄清。工具目录很大时，意图是第一层路由，后面再进工具检索，见 `jd-agent-tool-catalog-context`。被问「用的哪个模型」，可以说候选，比如业务 BERT 分类器、Qwen 等，然后马上补一句：决策靠规则和置信度，跟品牌关系不大，换模型要看切片指标还稳不稳。

## 准确率按意图切片测

测试集按意图、语言（口语还是书面）、新老用户、时间切分，防止泄漏，同一用户同一天的改写不能既当训练又当测试。指标看每类的 precision 和 recall、混淆矩阵、abstain 之后的解决率。微平均会被高频的「查物流」抬上去，掩盖低频「改价 / 退款」的假阳性。高风险意图单独定阈值，假阳性要严（不该进退款却进了），假阴性可以转人工或澄清。再构造对抗集，比如没有订单号却说「给我退了」、多个意图连着发。线上用人工抽检和用户改写率 calibration 离线分：离线分很高、用户却一直改口，说明 taxonomy 和真实话术没对齐。

标注 guidelines 要说明 ambiguous cases，模糊样本进澄清集，别硬标成某一类，再把模型刷到虚高的 accuracy。taxonomy 一变，回归集就要重标，否则旧标签会把新路由「测错」。意图也只是 Agent 评测的一层，后面还有工具选择和轨迹，见 `jd-agent-eval-beyond-qa`，意图 accuracy 代替不了整条链路。

再说和业务的衔接。意图决定走导购、售后、广告诊断还是纯 SOP 问答，scene boundaries 见 `jd-agent-beyond-guide`。分到检索增强生成（RAG）的意图仍要允许「无答案」，分到 Agent 的意图才暴露写工具。taxonomy 还要和权限模型一致，没有退款权限的身份，话术再像退款，也应该拦截或转人工，别「识别对了就执行」。

## 追问

**必须上大模型吗？**
不必。ID 和模板句用规则就够，大模型吃长尾口语。规则能锁死的，别交给生成。

**澄清算不算意图失败？**
低置信时澄清是正确行为，要单独统计。把澄清算成错误，会逼模型乱猜。

**多意图怎么测？**
允许输出有序列表，或者主意图加辅意图，看主路由有没有进对技能；辅意图留到后续轮次处理，别一次塞进两个写操作。

**和快手那张意图卡有什么不同？**
工程优化和评测定义用的是同一套 taxonomy 思路，京东这面更强调电商的高风险切片，报一个模型名就结束是不够的。恢复与澄清可以对照 `kuaishou-agent-intent-recovery`、`ant-intent-impl`。
