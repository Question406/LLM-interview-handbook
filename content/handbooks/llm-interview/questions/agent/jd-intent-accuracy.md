## 真题记录

- 公司：京东
- 团队 / 岗位：Agent 开发
- 届别 / 流程：27 暑期实习；二面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“意图识别用的是哪个大模型？如何判断和测试意图识别结果的准确率？”**

陷阱是答一个模型品牌、再报一个微平均 accuracy。京东 Agent 二面要的是路由策略：高确定性走规则，模糊再上分类器或带 schema 的 LLM，低置信则澄清。模型名可以是业务小模型或通用 LLM，重点是分层和切片评测。错误路由的业务后果（退款、改址）必须单独看。恢复与澄清也可对照 `kuaishou-agent-intent-recovery`、`ant-intent-impl`。

## 不要全程一个大模型

订单号、运单号、广告计划 ID、明确的「查物流 / 开发票」用规则和词典，延迟低、可解释、好审计。其余口语用轻量分类器或受限解码的 LLM，输出意图枚举而不是自由文本。低置信或意图互斥时问一个能翻转路由的问题，而不是猜进退款技能。

分层的原因：大模型把「看看我的订单」送进导购还是售后，错误成本不对称。规则能锁死的 ID 型 query，不必每次花一轮 LLM。工具目录很大时，意图是第一层路由，再进入工具检索，见 `jd-agent-tool-catalog-context`。

面试被问「用的哪个模型」时，可以说候选（业务 BERT 分类器 / Qwen 等），但立刻补：决策在规则与置信度，不在品牌；换模型要看切片指标是否还稳。

## 准确率必须按意图切片

测试集按意图、语言（口语/书面）、新老用户、时间切分，防泄漏——不能把同一用户同一天的改写既当训练又当测试。指标：每类 precision / recall、混淆矩阵、abstain 后的解决率。微平均会被高频「查物流」抬起来，掩盖低频「改价 / 退款」的假阳性。

高风险意图单独阈值：假阳性要严（不该进退款却进了），假阴性可转人工或澄清。构造对抗集：无订单号却说「给我退了」、多意图连发。线上用人工抽检和用户改写率校准离线分：离线很高但用户一直改口，说明 taxonomy 和真实话术不对齐。

意图只是 Agent 评测的一层，后面还有工具选择和轨迹，见 `jd-agent-eval-beyond-qa`。不要用意图 accuracy 代替整条链路。标注规范要写清边界：用户说「这单不对」可能是物流延迟、少件或想退款，必须靠槽位（有无订单号、是否提到钱）而不是单句分类赌。模糊样本进澄清集，不要硬标成某一类再把模型刷到虚高 accuracy。taxonomy 变更必须重标回归集，否则旧标签会把新路由「测错」。

## 和场景、和 RAG 的衔接

意图决定走导购、售后、广告诊断还是纯 SOP 问答，场景边界见 `jd-agent-beyond-guide`。分到 RAG 的意图仍要允许「无答案」；分到 Agent 的意图才暴露写工具。taxonomy 要和权限模型一致：没有退款权限的身份，即使话术像退款，也应拦截或转人工，而不是「识别对了就执行」。

## 追问

- **必须上大模型吗？** 不必。ID 和模板句规则就够；大模型吃长尾口语。能规则锁死的不要交给生成。
- **澄清算不算意图失败？** 低置信时澄清是正确行为，应单独统计。把澄清当错误会逼模型乱猜。
- **多意图怎么测？** 允许有序列表或主意图+辅意图，看主路由是否进对技能；辅意图用后续轮次处理，不要一次塞进两个写操作。
- **和快手意图卡有何不同？** 工程优化和评测定义是同一套 taxonomy 思想；京东这面更强调电商高风险切片和「不要报一个模型名就结束」。
