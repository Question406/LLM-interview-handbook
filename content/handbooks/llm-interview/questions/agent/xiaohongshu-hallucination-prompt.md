## 真题记录

- 公司：小红书
- 团队 / 岗位：大模型算法
- 届别 / 流程：秋招；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“提示工程的主要方法有哪些？”**；**“阐述大模型的幻觉现象及抑制方法。”**

错法：把「加一句不要编造」当成幻觉方案。提示工程改善可解析性和轻度倾向，改不了参数里的错事实，也替代不了检索和鉴权。社区场景对地点、价格、功效尤其要可回源；医疗 / 功效主张要拒答或转审核。同面还问 RAG 短板，短板答完要落到「评测不能只看流畅」，见 `xiaohongshu-rag-limits`。

## 提示工程能做什么

常见方法：角色与边界、少样本、输出 schema、把检索结果标成「仅数据」、要求引用、把不确定写成拒答模板。它能降低格式漂移、减少「看起来像答案」的空话，让后处理能校验字段。模板必须版本化，否则一次措辞改动会让拒答率整体漂，见 `pdd-prompt-template-versioning-rollback`。提示词迭代若没有 golden set，会把「更会说」误当成「更真」。

## 幻觉从哪来，抑制靠什么

来源大致三类：缺知识（参数里没有）、检索错仍一本正经、解码阶段乱编实体。抑制对应三层：无证据拒答；RAG / 工具核实并做归因实验；高风险槽位走结构化校验和人审。字段级检查（价格必须来自块、地点必须能指回笔记）比整段「请真实」有效。检索冲突时输出「来源 A/B」而不是随机站队，见 `pdd-pick-relevant-chunks`。多模态笔记还要防 OCR 错、图文不一致，见 `xiaohongshu-mmkg-chunk`。

## 评测把无根据原子事实单列

不要只用流畅度或「像不像小红书口吻」。把无根据原子事实、错误引用、该拒未拒分开计。提示只改变分布形状，知识库和工具改变支撑集。治理 Agent 还要把误伤、漏放和可申诉算进去，见 `xiaohongshu-agent-business-eval`。能上工具的槽位不要用提示硬背；不能上工具的槽位默认拒答。秋招常把「提示方法」和「幻觉抑制」连问：先报角色、少样本、schema、引用约束，马上说清边界，地点 / 价格 / 功效必须回源，提示不能替代知识库。一致性还要固定检索快照，见 `xiaohongshu-rag-limits`。

## 追问

- **提示工程能不能消除幻觉？** 不能。它降格式和轻度编造，事实靠证据、工具和拒答。
- **RAG 之后还会幻觉吗？** 会。检索错、切块丢、冲突被抹平都会编，见 `xiaohongshu-rag-limits`。
- **功效类笔记怎么处理？** 无来源或医疗主张默认拒答 / 转审核，不要靠「请谨慎」生成。
- **如何证明提示改动有用？** 固定检索快照和模型版本，只改模板，看无根据事实率和拒答率，而不是看更会说。
