## 真题记录

- 公司：小红书
- 团队 / 岗位：大模型算法
- 届别 / 流程：秋招；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“提示工程的主要方法有哪些？”**；**“阐述大模型的幻觉现象及抑制方法。”**

提示工程能改善可解析性和轻度的编造倾向，但改不了参数里的错事实，也替代不了检索和鉴权。秋招常把「提示方法」和「幻觉抑制」连着问，我会先报提示方法，马上说清边界，再讲幻觉从哪来、靠什么抑制。加一句「不要编造」算不上幻觉方案。

举个小红书的例子：用户问一家店的人均价格，笔记库里没有这家店的最新信息。prompt 写得再严，模型也可能凭参数里的旧印象给一个数。有效的做法是要求价格字段必须来自检索到的某个块，指不回去就拒答。社区场景里地点、价格、功效尤其要能回源，医疗和功效类主张要拒答或转审核。

提示工程的常见方法有：角色与边界、少样本、输出 schema、把检索结果标成「仅数据」、要求引用、把不确定的情况写成拒答模板。它能降低格式漂移，减少「看起来像答案」的空话，让后处理能校验字段。模板必须版本化，否则一次措辞改动会让拒答率整体漂移，见 `pdd-prompt-template-versioning-rollback`。提示词迭代如果没有 golden set，会把「更会说」误当成「更真」。

幻觉的来源大致有三类：缺知识（参数里没有）、检索错了仍一本正经、解码阶段乱编实体。抑制也对应三层：没有证据就拒答；用 RAG 或工具核实，并做归因实验；高风险槽位走结构化校验和人审。字段级的检查，比如价格必须来自块、地点必须能指回笔记，比整段写「请真实」有效。检索结果冲突时输出「来源 A/B」，别随机站队，见 `pdd-pick-relevant-chunks`。多模态笔记还要防 OCR 错和图文不一致，见 `xiaohongshu-mmkg-chunk`。能上工具的槽位不要用提示硬背，不能上工具的槽位默认拒答。

评测要把无根据的原子事实、错误引用、该拒未拒分开计，流畅度和「像不像小红书口吻」只能当参考。提示影响的是模型怎样生成回答，知识库和工具提供的是回答所需的事实依据。一致性还要固定检索快照，见 `xiaohongshu-rag-limits`；治理 Agent 还要把误伤、漏放和可申诉算进去，见 `xiaohongshu-agent-business-eval`。同一面还问了检索增强生成（RAG）的短板，答完短板也要落到评测上：引用错误要单列，流畅度只是辅助。

## 追问

**提示工程能不能消除幻觉？**
不能。它能降格式错和轻度编造，事实要靠证据、工具和拒答。

**RAG 之后还会幻觉吗？**
会。检索错、切块丢、冲突被抹平，模型都会编，见 `xiaohongshu-rag-limits`。

**功效类笔记怎么处理？**
没有来源的、或者带医疗主张的，默认拒答或转审核，别靠一句「请谨慎」去生成。

**怎么证明提示改动有用？**
固定检索快照和模型版本，只改模板，看无根据事实率和拒答率，「更会说」不算证据。
