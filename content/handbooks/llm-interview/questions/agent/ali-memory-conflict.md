Agent 记忆需要有更新规则。如果只是不断把新句子放进向量库，新旧地址或偏好可能同时被检索出来，模型就会随机选一个。

## 短期记忆和长期记忆分别保存什么

短期记忆服务当前任务：最近的对话、还没有问清的字段、当前订单编号。上下文满了可以做摘要，近期内容保留更多细节，较早内容压缩；订单号、地址等关键字段应结构化保存，见 `ali-prompt-optimize`。

长期记忆保存跨会话仍有效的事实或偏好，例如默认地址、忌口和配送偏好。每条都要带实体键、时间、来源和置信度。来源要说明是谁说的、来自哪个会话或哪次工具结果。

重新开始长周期对话时，检索相关事件即可，不需要把几个月的聊天全部放进上下文。证据检索和用户偏好也应分开管理，见 `ali-rag-eval` 和 `ali-skill-memory-rag`。

## 新旧信息冲突时怎么处理

先判断是不是“同一个实体、同一个字段、不同值”。相似文本不一定指同一件事，所以不能只靠向量相似度判断。

对用户偏好，可以采用这个优先级：用户明确更正 $\gt$ 工具提供的权威数据 $\gt$ 模型推断。比如，上周用户说送到公司地址 A，今天说以后送到家里地址 B，就把 B 设为当前值，同时保留 A 被替换的历史、时间和会话来源。

会员资料与用户口述的地址冲突时，应根据这次明确更正处理，并复述新地址以防听错。“可能喜欢辣”只是模型推断，应保持低置信度，不能直接变成长期事实。

具体字段仍要区分：实际履约状态以工具记录为依据；用户自己的偏好以明确更正为依据。时间更新也不意味着一定优先，例如新政策可能使旧的退货约定失效。这时要解释所依据的政策。

存储层最好维护实体键、单一当前值和历史版本，让检索只取当前有效值。冲突应在写入时解决，避免交给生成模型临场猜。

## 哪些记忆应该删除

过期事实、被替换的旧值、低置信度推断，以及保留政策不允许存储的敏感信息，都需要相应的清理机制。低置信度记忆可以定期衰减，减少错误累积。

用户要求不再记住家庭地址时，要执行实际删除并留下可审计记录。仅从这次提示词里删掉一句话，无法保证下一次不再检索到它。

## 面试追问

- **向量检索能完成冲突检测吗？** 不能单独完成。还需要明确的实体键，例如用户编号和字段名。
- **摘要可能丢失关键字段吗？** 会，所以订单号、地址等应另外结构化保存。
- **如何验收？** 更正后开启新会话，检查是否使用新值、是否还会检索到旧值。写入条数不能证明记忆有效。
