- 原始措辞：**“多模态输入同时有网页、文档和本地截图时，桌面端该怎样做上下文管理？”**

常见误区是：把网页、PDF、截图全部拼进 输入提示（prompt）。桌面端需要管理证据的采集、版本、使用和失效，窗口越大不一定越好。月之暗面一面和本地文件权限、任务中心是同一套产品：每份输入要能指回版本，模型只能看见当前任务选中的证据包。隐式继承所有历史附件，是污染和越权的来源。通用原则见 `agent-context`。

## 先记录每份资料，再选择本轮证据

每种输入先变成 artifact：来源 URI 或本地路径、采集时间、内容 hash、权限、版本、解析状态、可引用锚点。网页记快照（DOM / 可读文本），文档记页码或段落，截图记屏幕 / 窗口 / 区域坐标，并保留 OCR 文本以便检索。权限从文件授权继承，未授权路径不能因为出现在截图里就被当可读文件，见 `moonshot-desktop-local-file-permission`。

任务层维护显式 evidence set：当前步骤可见哪些 artifact、用全文还是摘要。模型输入应带 evidence manifest（ID + 版本），输出引用必须能点回原位置。用户替换文件或网页刷新后，旧版本标 stale，依赖该版本的计划或草稿要重新确认，不能静默继续。这和任务中心的输入证据对象一致，见 `moonshot-desktop-task-center`。

## 长内容按需展开，调用可回放

长网页和文档分块检索、按需展开、可验证摘要，摘要要能指回 chunk，不能只剩不可核验的散文。视觉输入同时保留原图锚点和 OCR，引用「图中第二列表格」时能高亮对应区域。窗口预算类似三级压缩：当前步骤原文、中期摘要、远期只留句柄，见 `byte-three-level-compress`。

每次模型调用记录实际送入的 manifest，才能解释答案从哪来、定位上下文污染、做离线回放。多窗口不要各拼一份隐式上下文，否则同一任务看到不同证据版本，见 `moonshot-desktop-multiwindow-state`。评测看引用能否点回、stale 是否被使用、无关附件是否泄漏进窗口，别只看「能不能同时上传三种文件」。把「解析」和「送进模型」拆开：解析可以后台把 PDF 和截图做成可检索块，送进模型必须经过当前步骤的预算和权限。用户拖进一个无关大 PDF，不应自动占满下一轮上下文。桌面端还要处理焦点：当前前台窗口的截图默认进入候选，是否进入 evidence set 仍要用户或任务规则确认，避免把锁屏、通知、密码管理器残影悄悄送进模型。

## 追问

- **截图里有另一个文件窗口，算授权吗？** 不算。看见 $\neq$ 可读磁盘文件。要读必须走文件权限。
- **网页刷新后还用旧摘要？** 旧 artifact 标 stale，任务需确认或重抓。继续用旧摘要要在 UI 标明版本时间。
- **三种模态谁优先？** 由任务 evidence set 显式选，不要靠模型自己「觉得截图更新」。冲突时展示版本并让用户选。
- **为什么必须记 hash？** 没有指纹就无法发现静默替换，也无法在审计里证明模型当时看见的是哪一版。
