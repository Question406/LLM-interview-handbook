## 真题记录

- 公司：月之暗面（Moonshot AI）
- 团队 / 岗位：研发工程师（AI-Native 方向）
- 届别 / 流程：原帖未披露；一面
- 面试时间：2026-07-23；帖子发布于 2026-07-30
- 来源类型与可信度：牛客候选人原帖，B（公司、岗位、轮次与面试日期明确，届别未披露）
- 原始措辞：**“多模态输入同时有网页、文档和本地截图时，桌面端该怎样做上下文管理？”**

我的做法是把证据的采集和使用分开管：每份输入先变成一条带版本的 artifact，任务层再显式决定这一步模型能看见哪些。把网页、PDF、截图全部拼进 prompt 看着省事，但窗口越大不一定越好，隐式继承所有历史附件，正是上下文污染和越权的来源。月之暗面这道一面题和本地文件权限、任务中心是同一套产品，每份输入都要能指回版本，模型只能看见当前任务选中的证据包。

举个例子：用户在写竞品分析，拖进来一份产品 PDF，开着一个官网页面，又截了一张定价表。过了一会儿官网刷新，价格变了。如果三样东西只是拼成了一段文本，模型会继续用旧价格，谁也发现不了；有了 artifact 记录，旧的网页快照会被标成 stale，依赖它的草稿要重新确认。

每种输入记成 artifact 时，要存来源 URI 或本地路径、采集时间、内容 hash、权限、版本、解析状态和 citation references。网页存快照（DOM 或可读文本），文档存页码或段落，截图存屏幕、窗口或区域坐标，再保留 OCR 文本方便检索。权限从文件授权继承，某个路径出现在截图里，不代表它变成了可读文件，见 `moonshot-desktop-local-file-permission`。

任务层维护一个显式的 evidence set：当前步骤能看见哪些 artifact，用全文还是摘要。模型输入带上 evidence manifest（ID 加版本），输出的引用要能点回原位置。用户替换了文件或网页刷新了，旧版本标 stale，依赖该版本的计划和草稿要重新确认，不能静默继续。这和任务中心里的输入证据对象是同一个东西，见 `moonshot-desktop-task-center`。

解析和送进模型也要拆开。解析可以在后台把 PDF 和截图做成可检索的块；送进模型必须经过当前步骤的预算和权限，用户拖进一个无关的大 PDF，不该自动占满下一轮上下文。长网页和文档分块检索、按需展开，做可验证的摘要，摘要要能指回 chunk，只剩一段核验不了的散文就没法引用。视觉输入同时保留原图的 region references 和 OCR，引用「图中第二列表格」时能高亮对应区域。窗口预算可以照三级压缩来分：当前步骤放原文，中期放摘要，远期只留句柄，见 `byte-three-level-compress`。桌面端还要处理焦点：当前前台窗口的截图默认进入候选，进不进 evidence set 仍要用户或任务规则确认，免得把锁屏、通知、密码管理器的残影悄悄送进模型。

每次模型调用都记录实际送入的 manifest，这样才能解释答案从哪来、定位上下文污染、做离线回放。多窗口不要各自拼一份隐式上下文，否则同一个任务会看到不同版本的证据，见 `moonshot-desktop-multiwindow-state`。评测看引用能不能点回、stale 的资料有没有被用、无关附件有没有漏进窗口，「能同时上传三种文件」说明不了什么。通用的上下文原则见 `agent-context`。

## 追问

**截图里露出另一个文件窗口，算授权吗？**
不算。看见 $\neq$ 可读磁盘文件，要读必须走文件权限。

**网页刷新后还能用旧摘要吗？**
旧 artifact 标 stale，任务要确认或重新抓取。继续用旧摘要的话，UI 上要标明版本时间。

**三种模态谁优先？**
由任务的 evidence set 显式选，别让模型自己「觉得截图更新」。有冲突就展示版本，让用户选。

**为什么必须记 hash？**
没有指纹，就发现不了静默替换，审计时也证明不了模型当时看见的是哪一版。
