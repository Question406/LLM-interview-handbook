可以把问题看成 value of information：若询问用户的时间成本小于错误行动的期望损失，就应该 clarify。反过来，低成本可逆的观察（搜索、列目录、读文件）往往比打断用户更划算。面试别答成「不确定就问」——那会把 agent 变成复读机；也别答成「尽量自己猜」——那会在不可逆动作上赌错。分界线是 **歧义会不会改成另一条高代价路径**。

## 先算清：问人是否比自己看更值

记当前对用户意图的几种合理解释为 $h_1,\ldots,h_k$。若它们导向的下一步动作几乎相同（都是「先检索再读」），澄清的价值低。若它们导向显著不同且昂贵的动作（删库 vs 备份、给 A 汇款 vs 给 B、覆盖文件 vs 另存），而你无法用廉价观察排除假设，就应该问。

特别应问：

- 目标 / 范围缺失：没说「改哪个环境、影响到谁」；
- 不可逆 side effect：发送、支付、删除、对外部客户可见的变更；
- 权限 / 身份不明：用谁的凭证、能否读生产数据；
- 多个对象同名：两个 `main.py`、两张「用户表」；
- 预算 / 时间约束决定方案：要最快还是要最稳。

可以不问、先自己做：搜索、读取、列出候选、在 sandbox 里试一次可回滚的操作。ReAct 式「先观察再行动」解决的是环境信息不足；Ask Clarification 解决的是 **用户意图不足**。两者都是信息收集，对象不同：一个问环境，一个问人。价值可以定性比较：问一次用户的成本是打断和延迟；猜错的成本是发错邮件、删错目录、用错账号。后者期望损失更大时才问。若几种解释的下一步都是「先 `ls` / 先检索」，期望损失几乎为 0，提问只是把延迟转嫁给用户。Agent 产品里「聪明」往往表现为 **该问才问**：既不是话痨，也不是莽撞。

## 低成本可逆探索优先，但不要用探索代替澄清

「先执行信息收集」不是「先猜一个目标做完」。读日志、跑 `--dry-run`、在 staging 复现，属于探索；把邮件写好发出去再问「是这个收件人吗」，属于用不可逆动作代替澄清。一条实用规则：下一步若不能 undo，且存在至少一个同样合理的替代解释，就停下来问一个 **能改变动作选择** 的具体问题，而不是开放式「您想做什么」。

问也有成本：打断、延迟、用户也不一定答得对。好的澄清问题应：

- 互斥且覆盖主要假设（「给 Alice 还是 Bob 的账户」）；
- 带上你已经看到的证据，降低用户负担；
- 一次只解一个会改变计划的歧义，避免问卷调查。

训练上可把 `ask_user` 视为一个与 `search` / `edit` 并列的 action，用 tool schema 约束问题格式。若策略从未在「歧义 prompt」上因乱猜而受罚，它会学会从不提问。SFT 示范里如果全是「直接干」，模型会把提问当成偏离；如果示范全是「先问一句好的」，又会在可查事实上打扰用户。数据应显式覆盖两类：意图歧义必须问，环境未知必须查。Clarification 问题要可执行：带选项、带已见证据，让用户用很低成本消解那一个会改变计划的维度。开放式「请提供更多信息」几乎等于没问，还会把责任推回去。

## 用隐藏目标评测，而不是用「问得多」当指标

构造 ambiguity benchmark：同一 prompt 的隐藏目标不同，模型只有澄清后才能稳定成功；乱猜则一半任务失败。指标应同时看：

- 该问的时候是否问了（不可逆动作前的澄清率）；
- 不该问的时候是否废话（可逆探索阶段的多余提问率）；
- 澄清之后成功率是否真的上去。

只优化「多问」会得到礼貌但无能的 agent；只优化「少问」会在高风险动作上自信犯错。SWE-agent 一类系统表明：接口上是否容易「先看再改」，会强烈影响要不要问人——观察工具越强，需要用户澄清的是意图而不是文件内容。产品上还要设权限：没有 `ask_user` 通道时，高风险动作应直接拒绝，而不是默默猜。评测构造可以很简单：同一句话「把那个文件删了」，隐藏目标分别是测试目录和主仓；不提问就无法稳定成功。把这类 case 混进普通 SWE 任务里，才能看到策略有没有学会分界。澄清不是礼貌模块，是高代价动作前的信息价值判断。

收束：该问当且仅当不同合理解释会导向显著不同的高成本或不可逆动作，且廉价观察消解不了。其余情况先搜集环境信息。训练要把 `ask_user` 当成真实动作来赏罚，评测要用隐藏目标，而不是用提问次数当 KPI。分界线是价值：不同合理解释会不会导向高成本或不可逆的不同动作，以及廉价观察能不能先消解歧义。该问就问一个能翻转计划的具体问题；不该问就去搜索、列举、dry-run。训练要把提问放进动作空间并赏罚漏问和过问，评测要用同一句话对应不同隐藏目标。没有提问通道时，高风险动作应拒绝而不是默默猜。

## 追问

- **不确定就要问吗？** 不必。若廉价观察能消解不确定，先观察。只有观察后仍存在会导向不同高代价动作的假设，才问。把不确定等同于提问，会得到话痨 agent。
- **问什么？** 能翻转决策的那一维：对象、权限、不可逆范围。不要问模型自己能查的事实。问题应带选项和已见证据，避免开放式「请补充信息」。
- **用户答错了怎么办？** 把澄清结果当成仍可能错的假设，高风险动作保持确认或 sandbox；不要把一句回复当成绝对 ground truth。必要时二次确认不可逆步骤。
- **如何训练这个行为？** 将 `ask_user` 纳入动作空间，在歧义数据上：乱猜给负奖励、恰当提问后成功给正奖励；并单独评测「过问」与「漏问」。SFT 示范也要覆盖两类，否则会塌到永远问或永远不问。
