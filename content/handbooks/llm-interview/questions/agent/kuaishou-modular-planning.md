- 届别 / 流程：日常实习；二面
- 面试时间：原帖未披露；帖子发布于 2026-03-31
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“在Modular Agent中，多步规划是如何实现的？”**；**“针对多个工具的调用链路，你的调度策略是如何设计的”**

错法：答成「模型一次把步骤说完，然后按文本顺序执行到底」。Modular 的要点是规划、执行、记忆分开，计划是可检验的图，别写成一段散文。快手二面同帖还问评估维度，规划对不对要用节点覆盖而不是 BLEU，见 `kuaishou-agent-eval-dims`。调度看数据依赖、权限和预算，不是谁先写在 prompt 里谁先跑。

## 规划器出 DAG，执行器按入度推进

规划器输出带依赖的步骤：每步绑定候选工具、成功条件和预期观测。无数据依赖的节点入度为零，可以并行（同时拉素材元数据和作者信息）；有数据依赖则串行（先查权限再写）。结果写回显式 state，下一步只读 state，不靠模型回忆上一步原话。

记忆模块回答「这步还是原任务吗」：用户中途改口或检索漂到相邻产品，应触发局部重规划，别把旧 DAG 执行完。意图漂移的工程处理见 `kuaishou-agent-intent-recovery`。计划要带预算：最大步数、最大并行度、费用上限，防止规划器写出无限展开。

## 调度：依赖、风险、失败子图

调度策略可以很具体：

- 无依赖并行，受并发和 QPS 配额限制；
- 有数据依赖串行，且下游以实际 observation 为准，不假设上游一定成功；
- 高风险工具（发布、删除、消耗额度）放最后，并加确认；
- 只读失败可立即换参或换工具；写操作超时先查最终状态，避免重复提交，见 `kuaishou-tool-timeout-empty-result`。

失败时区分参数错、权限错、环境瞬态错。只重跑受影响子图，已成功节点的产出保留。连续 $k$ 步无进展或观测与预期冲突，才全局 re-plan，见 `agent-when-to-replan`。每步都重规划会抖动且贵；死守过期计划会在工具变更后空转。评测看必要节点覆盖、非法顺序、无效调用、多余全局推倒次数。Modular 不是「多几个 prompt 角色」：规划器不能直接打有副作用的工具，执行器不能擅自改目标。接口是 state 和 DAG，角色是权限隔离。调度要能讲清并行的合并点：三路只读汇总后再进入写节点，部分失败时是降级、重试还是整支取消。同面评估卡会追问 Planning 量化，落回这张图：节点有没有、边合不合法、失败后重规划范围有多大。

## 追问

- **并行会不会把配额打满？** 会。并行度要挂配额和超时；高 QPS 三工具正是同面的场景，评估集要含负载。
- **计划和 ReAct 每步思考怎么选？** 结构稳定的 SOP 用 DAG；环境强不确定时允许局部 ReAct，但用规则闸门限制重规划次数。
- **模型规划的边不可执行怎么办？** 执行器按 schema 校验依赖和权限，非法边直接拒绝并要求重规划，不要「尽量跑」。
- **记忆污染会怎样破坏调度？** 旧任务的「下一步」被当成本任务依赖，会调错工具。写入门禁和任务 ID 隔离，见 `byte-memory-pollution`。
