## 真题记录

- 公司：小红书
- 团队 / 岗位：AI Agent 算法
- 届别 / 流程：一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“会根据不同问题切换不同模型吗？”**；**“那你是怎么判断一个问题是简单还是复杂的？”**

陷阱是「难的就换大模型」。复杂度应看是否多跳、是否要工具、槽位是否齐、失误成本多高，而不是句子长不长。简单走小模型短链路，复杂才升级并开 Deep Research。同面还问限流与多租户——路由必须带配额，复杂链路不能把简单租户拖死。停止策略见 `xiaohongshu-deep-research-stop`。

## 简单 / 复杂的信号

简单：单实体事实、已填槽、一次检索可答、低风险闲聊。复杂：多跳对比、要写长研究、连续检索仍低置信、涉及功效 / 价格 / 治理处置。信号来自 query 分类、检索分数、缺失槽位、是否触发工具、用户身份（内部工具 vs 对 C）。规则能拦住明显简单（「这件多少钱」且 SKU 已在上下文）；边界 case 用轻量分类器，不要一上来就让大模型自评「我很难」。检索高分且槽位齐，即使句子长也该走短链路。

## 切换：默认小模型，触发再升级

默认小模型 + 短工具集。触发复杂则换强模型、提高步数预算、打开 Deep Research。误升级烧钱、占配额；误降级答错、漏证据。升级 / 降级都要打日志：触发特征、所选模型、预算。中途可以再升级（检索冲突、覆盖不足），但要受租户配额硬限制。治理处置、外发、删除这类高影响动作，复杂度标记应直接升高，并接人审，见 `xiaohongshu-agent-business-eval`。模板和模型版本一起进 release，避免「只换模型、提示还是旧的」，见 `pdd-prompt-template-versioning-rollback`。

## 按任务桶看成功和成本

阈值按延迟和失误成本分档：对 C 搜索偏严，内部分析可松。评测按任务桶看成功率、升级率、token、限流拒绝。不要只报「平均更准」。简单租户被复杂链路拖死，是路由事故，不是模型不够好。复杂题的停止仍用覆盖 / 增益 / 预算，见 `xiaohongshu-deep-research-stop`。小红书这面把「换不换模型」和「简不简单」绑在一起：先定义复杂信号，再谈升级。不要一上来比较模型名字。配额是硬约束，复杂链路的并发要单独限流，避免研究型请求挤占成交 / 搜索短链路。路由日志要能回答「为什么升、为什么没升」，否则阈值无法迭代。

## 追问

- **句子很长就是复杂吗？** 不是。看多跳、工具、槽位和风险。长闲聊仍可走小模型。
- **让大模型自己决定要不要上？** 不稳，且贵。用规则 + 轻量分类，大模型只处理已升级的任务。
- **升级后还能降级吗？** 可以，但要记日志；配额打满必须降级或排队，不能无限升。
- **和 Deep Research 停止什么关系？** 路由决定进不进长链路，停止决定何时退出，两套预算要对齐。
