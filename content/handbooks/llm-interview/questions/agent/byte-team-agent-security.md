## 真题记录

- 公司：字节跳动
- 岗位：Agent 开发实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“如果让你把这个本地 Coding Agent 做成团队内部工具，你会怎么处理权限、安全和审计？比如文件读写、命令执行、敏感信息泄露。”**

我会把边界放在工具服务端和策略引擎里：按人、仓库、命令三层授权，密钥和敏感输出在执行层拦截，审计日志单独存、模型写不了。写在输入提示（prompt）里的「请不要泄露」挡不住注入，一句「忽略以上指令」就能打穿，所以它最多算提醒。这一层就是 Harness 的授权层。

举个例子。同学 A 在有写权限的 `frontend` 仓里，可以改 `src/**`、跑 `npm test`；同一个 Agent 被要求 `cat ~/.ssh/id_rsa`，或者把 `.env` 发到外网，策略引擎直接拒掉并记一条审计。同学 B 没有这个仓的 ACL，用同一套模型也读不到。模型是同一个，能做什么取决于背后是谁、在哪个仓。

授权按顺序一层层过。身份走 SSO，会话绑定到人，不绑定「这台笔记本」；然后看仓库 ACL，默认只读当前有权限的 repo；再过工具策略，禁网络、禁 `sudo`、禁读 `~/.ssh`；最后做输出脱敏。命令白名单按风险分级，只读检索默许，写文件要匹配路径前缀，网络和特权命令要额外审批。个人本地试验可以松一点，一旦能 `git push`、能碰密钥或生产配置，就默认拒绝、全程可审计。访问控制不写在 system prompt 里。Skill 和工具描述里也藏着注入面，见 `agent-skill-security`。

密钥这块，扫描器拦 `.env`、私钥、云厂商 AK，命中了就不读、不写进上下文、也不让它出现在 Observation 里。生产部署密钥放独立的 secret 服务；会话要访问下游时，只发一次性、短 TTL、最小权限的只读凭证，用完就废，模型上下文里不出现长期凭据。输出脱敏同时处理工具返回和模型的最终回复，订单号可以留后四位，完整身份证、cookie、token 要打码。宁可多打码，误杀还能补救，漏出去的密钥收不回来。这一步也在执行层做，别指望模型自己「注意别输出」。

审计日志要记全：谁、哪次会话、读了哪些路径、执行了哪条命令、写了哪个文件、有没有被策略拒绝。日志走独立通道，模型没有写权限；审计和业务库写在一起、Agent 又能编辑的话，就等于没有审计。有了它，事后才能回答「这个错误 patch 是谁的 Agent 合进去的」，也能接上回滚。SSO 过期就吊销会话，已经发出去的短 TTL 凭证失效，进行中的高风险动作停下来。常见的几种失败，就是靠 prompt 防泄露、把模型当防火墙、让 Agent 能改审计。默认拒绝的安全策略和错误 patch 的回滚属于同一套 Harness，不用拆成两个产品。

## 追问

**白名单怎么列才不会把人锁死？**
按仓库语言给默认模板，比如前端允许 `npm test`、禁止 `curl | sh`，再按团队加例外，并且审计例外的使用率。没有例外流程的白名单，最后要么被绕开，要么被废弃。

**脱敏误杀了合法日志怎么办？**
开一个「审批后查看原文」的通道，别让 Agent 自己把脱敏关掉。

**prompt 注入从哪来？**
仓库 README、网页、工具返回都可能夹带指令。不可信内容进隔离区，不能借它提升权限，见 `agent-prompt-injection`。

**和开源 Coding Agent 差在哪？**
团队版多了身份、ACL、审计和密钥治理。本地个人工具「能跑」，离能共享还差这几样。
