## 真题记录

- 公司：字节跳动
- 岗位：Agent 开发实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“如果长期记忆里保存了过时的文件摘要，后面 Agent 又拿它做判断，这种污染怎么处理？”**；**“如果模型把错误结论写进了记忆，比如误判某个函数作用，后续任务一直沿用这个错误，你怎么做纠错？”**；**“多轮执行中，Agent 可能反复读同一个文件或重复调用同一个工具。你是怎么识别重复状态的？”**

常见误区是：「下一轮 prompt 写请忽略上次记忆」。污染一旦入库，后续任务会把它当先验，仅修改提示词无法消除已经存入记忆的错误事实。记忆是带 provenance 的可变状态：把记忆绑定到可检查的版本或内容哈希，过期时使其失效；错误结论通过工具或测试证伪后回滚；重复调用则用指纹识别并复用结果。和短长记忆分工见 `byte-short-long-memory`，和 检索增强生成（RAG） 混用见 `byte-rag-memory-context`。

## 文件变化时，旧摘要必须失效

文件摘要绑定 `path + content_hash`（必要时加 branch / commit）。读文件或 CI 变更时先比哈希：变了就作废并重读，而不是用旧摘要推理。配置、接口契约、默认超时这类「看起来像永久知识」最容易过期，必须写上可失效条件。用户偏好可以较稳，但仍要时间戳；仓库事实不能当永久常识。

发现过期不必等用户投诉：轨迹里同一文件摘要与当前 `read_file` 观察矛盾、测试断言与记忆中的函数签名不一致，就应触发失效。检索命中长记忆时，先校验引用是否仍有效，无效条目不进窗口。

## 错误结论：假设入库，证伪回滚

写入时标成假设，带证据指针（测试名、grep 命中、用户确认）。被单测失败或 `grep` 否定后删除或改写，并记一条负例：「不要再假设 `foo()` 只做校验」。纠错是状态机操作：`invalidate / rewrite / ban-pattern`，不是再生成一段「以后注意」。

模型自述不能当事实入库。「我觉得这个函数没用」若没有测试或引用支撑，只进短记忆或直接丢弃。高置信写入的门槛应高于生成一句总结。纠错后要把影响范围写进评测：同类任务是否还会绕开正确入口。回滚要级联：若后续记忆引用了这条错误结论，一并失效，避免「已删除的假设」仍通过别的条目活着。Coding Agent 里最常见的污染链是误读函数职责 → 写入长记忆 → 下次任务跳过正确文件 → 再把跳过合理化成新记忆。打断链的办法是证伪后删，别追加一条相反的自然语言。

## 重复状态：对 (tool, args, cwd) 做指纹

多轮里反复 `read_file(path)` 或同一参数调同一工具，会把过期观察叠进上下文，污染被放大。对 `(tool_name, canonical_args, cwd, content_hash)` 做指纹：命中则返回缓存并提示「内容未变」，除非上游哈希已变或用户显式要求重读。这能减少无效调用，也避免同一错误摘要被写进记忆两次。

不要用「模型说自己读过了」当去重；要用执行层缓存。工具有副作用时（写文件、发请求）指纹只能用于读操作，写操作必须走幂等键或拒绝重复提交。

## 追问

- **输入提示里写「忽略过期记忆」行不行？** 不行。后续检索仍会命中旧条目。必须从存储删除或标记无效，并阻止它再进入组装窗口。
- **怎么发现污染？** 看轨迹：同一错误假设反复出现、测试与记忆矛盾、同一指纹被当成新观察。把这些做成离线检查，而不是靠人工翻日志。
- **和 RAG 脏数据怎么区分？** RAG 脏的是外部文档，应改索引与切块；Memory 脏的是 Agent 自己沉淀的状态，应回滚条目并记负例。混进一个向量库会让两边都无法单独修，见 `byte-rag-memory-context`。
- **负例会不会让 Agent 过度保守？** 负例要绑定证据范围（哪个函数、哪次任务），不要写成全局「不要读任何摘要」。过宽的 ban 会造成新的行为塌缩。
