## 可以这样回答

记忆要当成带 provenance 的可变状态来管：文件摘要绑定内容哈希，哈希变了就失效重读；错误结论入库时标成假设，被测试或工具证伪就删除或回滚，连带引用它的条目一起失效；反复读同一文件、反复调同一工具，用执行层的状态指纹识别并复用结果。在下一轮 prompt 里写「请忽略上次记忆」没用，污染一旦入库，后续任务会把它当先验，改 prompt 消除不了已经存进去的错误事实。短长记忆分工见 `byte-short-long-memory`，和RAG混用见 `byte-rag-memory-context`。

先说过期摘要。文件摘要绑定 `path + content_hash`，必要时加 branch / commit。读文件或者 CI 有变更时先比哈希，变了就作废重读，别拿旧摘要接着推理。配置、接口契约、默认超时这类东西看着像永久知识，其实最容易过期，必须写上可失效条件；用户偏好相对稳，也要带时间戳，仓库事实不能当永久常识。发现过期也不必等用户投诉：轨迹里同一文件的摘要和当前 `read_file` 的观察矛盾，或者测试断言和记忆里的函数签名不一致，就该触发失效。检索命中长记忆时，先校验引用是否仍然有效，无效的条目不进窗口。

## 真题记录

- 公司：字节跳动
- 岗位：Agent 开发实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“如果长期记忆里保存了过时的文件摘要，后面 Agent 又拿它做判断，这种污染怎么处理？”**；**“如果模型把错误结论写进了记忆，比如误判某个函数作用，后续任务一直沿用这个错误，你怎么做纠错？”**；**“多轮执行中，Agent 可能反复读同一个文件或重复调用同一个工具。你是怎么识别重复状态的？”**

记忆要当成带 provenance 的可变状态来管：文件摘要绑定内容哈希，哈希变了就失效重读；错误结论入库时标成假设，被测试或工具证伪就删除或回滚，连带引用它的条目一起失效；反复读同一文件、反复调同一工具，用执行层的状态指纹识别并复用结果。在下一轮 prompt 里写「请忽略上次记忆」没用，污染一旦入库，后续任务会把它当先验，改 prompt 消除不了已经存进去的错误事实。短长记忆分工见 `byte-short-long-memory`，和检索增强生成（RAG）混用见 `byte-rag-memory-context`。

先说过期摘要。文件摘要绑定 `path + content_hash`，必要时加 branch / commit。读文件或者 CI 有变更时先比哈希，变了就作废重读，别拿旧摘要接着推理。配置、接口契约、默认超时这类东西看着像永久知识，其实最容易过期，必须写上可失效条件；用户偏好相对稳，也要带时间戳，仓库事实不能当永久常识。发现过期也不必等用户投诉：轨迹里同一文件的摘要和当前 `read_file` 的观察矛盾，或者测试断言和记忆里的函数签名不一致，就该触发失效。检索命中长记忆时，先校验引用是否仍然有效，无效的条目不进窗口。

再说错误结论。Coding Agent 里最常见的一条污染链是这样：误读了某个函数的职责，写进长记忆，下次任务就跳过了正确的文件，再把「跳过」合理化成一条新记忆。要打断它，写入时就标成假设，带上证据指针，比如测试名、grep 命中、用户确认。被单测失败或者 `grep` 否定之后，删除或改写，并记一条负例：「不要再假设 `foo()` 只做校验」。纠错是状态机操作，`invalidate / rewrite / ban-pattern`，再生成一段「以后注意」没有用；证伪后就删，别追加一条相反的自然语言。回滚要级联，后续记忆要是引用了这条错误结论，一并失效，免得「已删除的假设」通过别的条目活下来。模型自述不能当事实入库，「我觉得这个函数没用」没有测试或引用支撑，只进短记忆或者直接丢掉，高置信写入的 threshold 要比生成一句总结高。纠错之后把影响范围写进评测，看同类任务还会不会绕开正确入口。

最后是重复状态。多轮里反复 `read_file(path)`，或者用同样的参数调同一个工具，会把过期的观察一层层叠进上下文，污染被放大。对 `(tool_name, canonical_args, cwd, content_hash)` 做指纹，命中就返回缓存并提示「内容未变」，除非上游哈希已经变了或者用户明确要求重读。这样能少做无效调用，也避免同一条错误摘要被写进记忆两次。去重要靠执行层缓存，「模型说自己读过了」不算。工具有副作用时（写文件、发请求），指纹只能用在读操作上，写操作必须走 idempotency key，或者拒绝重复提交。

## 追问

**prompt 里写「忽略过期记忆」行不行？**
不行。后续检索还会命中旧条目，必须从存储里删掉或标记无效，并阻止它再进入组装窗口。

**怎么发现污染？**
看轨迹里有没有这几种信号，同一个错误假设反复出现、测试和记忆矛盾、同一个指纹被当成新观察。把这些做成离线检查，别靠人工翻日志。

**和 RAG 的脏数据怎么区分？**
RAG 脏的是外部文档，要改索引和切块；Memory 脏的是 Agent 自己沉淀的状态，要回滚条目并记负例。两者混进一个向量库，哪边都没法单独修，见 `byte-rag-memory-context`。

**负例会不会让 Agent 过度保守？**
写得太宽就会。负例要绑定证据范围，哪个函数、哪次任务，别写成全局的「不要读任何摘要」，过宽的 ban 会造成新的行为塌缩。
