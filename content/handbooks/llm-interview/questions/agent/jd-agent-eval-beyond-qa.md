## 真题记录

- 公司：京东
- 团队 / 岗位：AI Agent 开发
- 届别 / 流程：一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B（公司、岗位与轮次明确）
- 原始措辞：**“模型效果评估为什么不能只看问答准确率，Agent 系统至少还要评什么”**

因为 Agent 做的事比回答多。它要选工具、填参数、决定继续还是拒答，答对了但乱调工具、越权、成本爆炸，工程上一样不合格，问答准确率只看最后一句，把这些都盖住了。所以评测要覆盖整条轨迹，按任务桶出表，一个总分说明不了问题。

举个例子，用户问「我这单能退吗」，模型最后答对了，可中间反复调了改址接口，还有一次带着别人的订单 ID。按 QA 准确率算这条是满分，按轨迹看它是一个有越权、有无效调用的失败样本。

我会顺着决策链拆指标，不按「聪明程度」拆。先看意图和路由，有没有进对技能或业务域，见 `jd-intent-accuracy`；再看工具选择，该调库存还是该调 SOP 检索；然后是参数的字段和类型规范（schema）合法率，缺字段、类型错、越权 ID 都算；接着是平均调用轮数和无效调用率，看有没有空转、有没有重复同一个失败调用；还有失败恢复率，超时、空结果之后有没有按策略恢复，有没有拿幻觉填空；最后是该拒答时有没有拒、高风险时够不够保守，退款、改址、改价之前该停就停。最终答案照样要评，和轨迹放在一起看。

测法上，环境要可回放：同一套 tool mock、同一个时间快照、同一个权限角色，不然「库存接口今天超时」就会让离线分数抖。金标除了最终那句话，还包括允许的工具集合、禁止的工具、必须引用的订单号。按任务桶出表，比如导购、售后、广告诊断、无答案各一行，一个微平均 accuracy 会让高风险桶淹没在海量闲聊里。工具目录变了要回归，目录治理见 `jd-agent-tool-catalog-context`。别拿「让模型自评这次调用合理吗」当主指标，Reflection 没有 oracle 和替换实验，会把自信当成正确，归因实验见 `jd-agent-reflection-error-attribution`。文本处理单位（token）、延迟、调用次数这类成本指标放进同一张表，否则优化准确率的时候会把 QPS 打爆。汇报时固定模型、任务、token 预算和 harness 版本，不然轨迹指标没法归因。

线上还要补离线沙箱看不到的东西，真实客诉和权限边角都在这里：延迟、token、客诉、人工接管率、越权拦截次数、用户改写率。离线分在涨、接管率也在升，说明评测集没覆盖真实的歧义。答对率上升要是伴随着无效调用和越权尝试一起上升，也不能当成上线理由。和检索增强生成（RAG）的评测要拆开，检索命中归 RAG 那边管，工具乱调归 Agent 这边管，见 `jd-agent-vs-rag`。某个技能内部的步骤有没有按清单走，属于 Skill 级评测，接到 `agent-skill-eval`；各维度的完整对照见 `kuaishou-agent-eval-dims`。

## 追问

**答对了但多调了工具，算失败吗？**
产品上可能过关，工程上要记一次无效调用。内部工具有副作用或者按次计费时，多余调用就是缺陷。

**没有金标轨迹怎么办？**
至少标出允许的工具集和禁止的工具集，再用规则检查 schema 和越权，最终答案人工抽检。不用等完整的逐步金标才开始测。

**和模型能力评测怎么切开？**
同一个模型换 Harness，轨迹指标就会变。汇报时写清 harness 版本，免得把脚手架的增益算成模型的增益，见 `agent-harness`。

**高风险保守性怎么量化？**
构造一个「不该执行」集，比如无权限改价、模糊退款，看拦截率；同时看「该执行的查询」有没有被误杀。
