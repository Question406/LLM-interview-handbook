## 真题记录

- 公司：商汤
- 岗位：多模态大模型算法实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“介绍你 Agent 的三个模块”**；**“你觉得哪个模块最重要？为什么”**；**“为什么不用训练”**

我会按数据流讲三个模块：感知产出结构化观测，推理做假设和工具选择，校验对照规则、二次视觉或人工。三个里我认为校验最重要，因为它决定错误能不能被拦住、任务能不能被评测；没有校验，反思和 chain of thought（CoT）也可能只是在重复同一个错误假设。模块名按自己的项目说就行，但数据流要讲清。只背一套「规划-工具-记忆」再说推理最重要，很难接住后面的追问。

多模态的错误往往看起来很自信。比如模型读一张折线图，把纵轴刻度看错一格，推出一个并不存在的大幅增长，推理的每一步都很顺，结论却是错的。这类错，推理层自己发现不了，要靠另一层去对照。

多模态 Agent 常见的拆法是感知、推理、校验，也可以叫规划-工具-验证。感知这层把图像、OCR、检测框变成可以引用的观测，停在「模型看过了」不够。观测要带证据 span 或框，后面的关系边也必须能指回证据，这和 `xiaohongshu-mmkg-chunk` 是同一条纪律。推理这层根据观测选工具、形成假设、决定要不要再看一眼。ReAct 的 Thought / Action / Observation 是策略骨架，见 `xiaohongshu-react-structure`；商汤这题更强调哪一层能挡住错。校验这层对照业务规则、二次视觉模型或人审，拦住格式错、看错表、编造关系。

校验排在前面，是因为它定义了任务是否可评：有规则就能自动拦，有二次视觉就能独立找错，有人审就能升级。指错列、看错刻度、把海报文案当成事实，这些都要靠它来挡。高风险槽位，比如计量、价格、安全，必须校验通过才能往下走；低风险的描述可以降级。没有这一层，训练也只是在拟合「更会说」。

至于为什么不用训练：标注贵、上线窗口短、错误能被规则抓住，或者先要证明任务可评的时候，我会先把可验证的 feedback loop 跑起来，也就是工具、schema、校验和评测集。基座已经够用、瓶颈在数据和工具时，SFT/GRPO 修复不了「没有证据」。适用条件也要主动说明：格式不稳、领域术语乱、基座不会看表，这时再上训练，训练目标对齐校验信号（格式、定位、拒答），别再堆开放域流畅度。hallucination 抑制也是同一个道理，提示只能降格式错，事实靠证据，见 `xiaohongshu-hallucination-prompt`。商汤多模态面容易把「不用训练」听成回避算法，所以我会说清楚：feedback loop 先证明任务可评，评测权在校验和 benchmark 上，训练是 feedback loop 不够时用来补基座的，别默认第一步就训。同一面要是问刷过哪些 benchmark，也是在验证有没有评测权，报榜单没多大用。

## 追问

**三个模块一定是感知、推理、校验吗？**
不一定，按项目说。我会讲依赖关系和谁拦住错误，不背固定名词。

**校验会不会误杀召回？**
会。按风险分档：高风险严拦，低风险记录后放行，评测里精确和漏放一起看。

**不用训练，会不会被认为没算法？**
先证明 feedback loop 可评、基座的瓶颈不在权重；现有方法不足时再尝试 SFT/GRPO。训练是补丁，用来补 feedback loop 够不到的地方，谈不上逃避。

**和 ReAct 什么关系？**
ReAct 是循环骨架，校验是循环里必须落地的那一跳，见 `xiaohongshu-react-structure`。
