## 真题记录

- 公司：商汤
- 岗位：多模态大模型算法实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“介绍你Agent的三个模块”**；**“你觉得哪个模块最重要？为什么”**；**“为什么不用训练”**

这块容易直接答成背一套「规划-工具-记忆」，再说推理最重要。我会讲依赖：感知产出结构化观测，推理做假设与工具选择，校验对照规则 / 二次视觉 / 人工。没有校验，反思和 CoT 都会变成表演。模块名按项目说，但数据流要讲清。同面若问刷了哪些 benchmark，是在验证有没有评测权，不是让我报榜。

## 三个模块按依赖介绍

多模态 Agent 常见拆法是感知 / 推理 / 校验（也可说规划-工具-验证）。感知把图像、OCR、检测框变成可引用观测，别停在「模型看过了」。推理根据观测选工具、形成假设、决定是否再看一眼。校验对照业务规则、二次视觉模型或人审，拦住格式错、看错表、编造关系。ReAct 的 Thought / Action / Observation 是策略骨架，见 `xiaohongshu-react-structure`；商汤这题更强调哪一层能挡住错。观测必须带证据 span 或框，关系边必须能指回证据，和 `xiaohongshu-mmkg-chunk` 同一纪律。

## 最重要的通常是校验

多模态错误往往看起来很自信：指错列、看错刻度、把海报文案当成事实。推理再强，没有对照层就会把错观测写成对结论。校验之所以排前面，不是因为实现最炫，而是因为它定义了任务是否可评：有规则就能自动拦，有二次视觉就能独立找错，有人审就能升级。没有这一层，训练也只是在拟合「更会说」。高风险槽位（计量、价格、安全）必须校验通过才能往下走，低风险描述可以降级。

## 为什么有时不用训练

标注贵、上线窗口短、错误能被规则抓住、或先要证明任务可评时，先把可验证闭环跑起来：工具、schema、校验、评测集。基座已够用、瓶颈在数据和工具时，SFT/GRPO 不会修复「没有证据」。要主动补边界：格式不稳、领域术语乱、基座不会看表时，再上训练。训练目标应对齐校验信号（格式、定位、拒答），别再堆开放域流畅度。幻觉抑制同理：提示只能降格式错，事实靠证据，见 `xiaohongshu-hallucination-prompt`。商汤多模态面容易把「不用训练」听成回避算法；主动补一句：闭环先证明任务可评，评测权在校验和 benchmark，训练是在闭环不够时补基座，别默认第一步就训。

## 追问

- **三个模块一定是感知推理校验吗？** 按项目说。我会讲依赖和谁拦住错误，不背固定名词。
- **校验会不会误杀召回？** 会。按风险分档：高风险严拦，低风险记录后放行，并在评测里同时看精确和漏放。
- **不用训练会被认为没算法吗？** 先证明闭环可评、基座瓶颈不在权重；边界不够再上 SFT/GRPO，把训练当补丁不是逃避。
- **和 ReAct 什么关系？** ReAct 是循环骨架；校验是循环里必须落地的那一跳，见 `xiaohongshu-react-structure`。
