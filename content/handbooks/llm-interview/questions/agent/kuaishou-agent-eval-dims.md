- 原始措辞：**“Agent 评估体系包含哪些核心维度？如何量化衡量Planning能力与Hallucination Rate?”**

我会把 Agent 评估拆成几块分开报：任务成功、过程（规划、工具、观察使用）、幻觉、安全和成本，别合成一个「Agent 分」。Planning 用 gold 必要节点和先后约束来量，幻觉率用对不上证据的断言占比来量，两者的分母都要写死。用最终回答的流畅度或者单一 QA 准确率代表 Agent 不够，它会选工具、填参数、决定继续还是停，答对了但乱调工具，工程上一样不合格，京东侧的同类问题见 `jd-agent-eval-beyond-qa`。

举个例子，任务是「查一下这条视频的数据，再把标题改了」。模型最后说「已修改」，看着很流畅，可它没先查权限就去写，改标题的接口其实超时了，它说的成功是编的。只看最终回答，这条会被判对；拆开看，规划里有非法顺序，观察没用上，还有一条工具幻觉。快手 LLM 二面连着追问评估、规划调度和 RAG 是否有效，就是要你能把过程里的这些问题分别讲清楚。

具体维度是这些。任务成功看用户目标有没有达成，字段对、动作真正生效。规划看必要子目标有没有出现、顺序是否可行、是不是过早终止。工具看选没选对、参数是否合法、有没有越权、无效调用多少次。观察使用看它有没有根据返回改计划，还是忽略报错继续编。幻觉看事实或工具结果对不上的断言比例。安全看越权、泄漏、高风险操作有没有确认。成本看步数、文本处理单位（token）、延迟，以及失败恢复是否成功。切片按意图、工具失败类型、是否超时。只优化成功率，会得到一个爱重试、爱编造成功的策略。

## Planning 和 Hallucination Rate 怎么量化

Planning 别用计划文本的 BLEU。给任务写一张 gold 计划图，标出必要节点和偏序，然后看必要节点的覆盖、非法顺序（比如没查权限就写）、过早终止、多余步骤。还可以做探针：给一个残缺的 state 让它补计划，或者中途注入环境变化，看它会不会死守过期的计划，见 `agent-when-to-replan`、`kuaishou-modular-planning`。覆盖率的分母是 gold 必要节点，模型自己生成的步骤数不能当分母。

Hallucination Rate 要先定义什么是断言。分母用全部事实断言，或者全部回复里可核验的句子；分子是在检索或工具结果里对不上的断言。编造 API 返回、伪造 request ID 这类工具幻觉单独一个桶，和文档幻觉分开报。自动对齐用 span 或结构化字段，再加人工校准；按场景切片，推荐理由、数据指标、政策条款的幻觉代价不一样。流畅、自信的错答也要算进分子。分母是可核验断言，token 数不能当分母。分母一漂，周报上的「下降」就没有意义。RAG 侧的三层指标见 `kuaishou-rag-eval-build`。

原帖同一面还问了高 QPS 下三个工具的延迟，所以评估集要有负载和超时的 case，见 `kuaishou-tool-timeout-empty-result`。高 QPS 切片单独报超时后的诚实率，任务失败但如实说明超时，比编造成功好。二面把评估和调度连着问，也是因为没有这些分母，调度策略没法回归。

## 追问

**任务成功了但规划很烂，算不算过？**
工程上不算。多余调用和不可恢复的路径，在负载下会爆，过程分要单独卡阈值。

**没有 gold 计划图怎么办？**
先标必要节点，也就是必须调用的工具和先后约束，别试图标唯一的完整计划。

**幻觉率用模型打分行不行？**
可以做初筛，但必须用证据对齐和人工校准，否则评测模型会和被测模型一起幻觉。

**延迟要进评估吗？**
要。同面问了多工具高 QPS，评估集里要有超时和空返回，看它是诚实反馈还是编造成功。
