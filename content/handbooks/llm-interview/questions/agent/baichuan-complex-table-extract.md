- 原始措辞：**“如何提取复杂表格信息”**

常见误区是：「把 Excel 截图丢给 VLM」。复杂表经常不符合简单的行列网格，难点在于恢复结构。模型负责理解问法和选择操作，数值以 spreadsheet engine 为准。同一面的 SQL 安全、多 Agent 分工见 `baichuan-sql-agent-safety-detection`、`baichuan-multi-agent-collab`。

## 先恢复结构，再定位单元格

合并格、多级表头、隐藏列、单位写在标题里、跨 sheet 引用，都会让「第 $i$ 行第 $j$ 列」失效。先用解析器得到单元格图：每个格子的坐标、合并范围、表头层级、公式依赖。不要把整表拍成图。流程：识别表头层级 → 把用户问题绑到行列键 → 取数或让引擎执行公式 → 核对单位与合计行。跨表沿引用链走，不要复制粘贴数值。抽取结果必须带回坐标和公式依赖，便于 验证器（verifier） 重算。

## 模型与引擎怎么分工

模型适合：问法改写、选哪张表、解释结果。不适合：心算合计、读像素里的数字、发明公式。抽取后用引擎重算，并检查必须成立的关系（合计行、勾稽关系、单位换算）。评测按表结构族切片，合并格和跨 sheet 单独集；只拿干净网格表刷准确率会虚高。若必须处理扫描件，OCR 之后仍要重建单元格图，而不是让生成模型直接报一个数。

多 Agent 时一个角色理解意图，一个角色操作表格 API，一个角色校验。比三个通用助手互聊更清楚。高风险改表或导出前走权限，与 SQL Agent 同一套「执行前拦截」。

## 追问

- **VLM 读表为什么不够？** 合并格和公式依赖在像素里丢失；同一数字可能是原始值或合计。结构解析 + 引擎重算更可校验。
- **公式和缓存值不一致怎么办？** 以引擎重算为准，并标出依赖链。不要静默采用缓存。
- **很大的表怎么放进上下文？** 不要整表塞 输入提示（prompt）。按表头和问题定位子区域，工具只返回相关矩形。
- **怎样验收？** 单元格级准确率 + 合计 invariant + 跨 sheet 引用集；报告结构族切片，而不是一个总分。
