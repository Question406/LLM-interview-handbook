- 团队 / 岗位：大模型实习
- 届别 / 流程：实习；一面
- 面试时间：原帖未披露；帖子发布于 2026-02-12
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“如何提取复杂表格信息”**

复杂表格先恢复结构，再定位单元格，数值以 spreadsheet engine 为准，模型负责理解问法和选择操作。合并单元格、多级表头、跨 sheet 引用一多，表就不再是简单的行列网格，难点在恢复结构，把 Excel 截图丢给 VLM 读像素很容易出错。抽取结果要带回坐标和公式依赖，方便验证器（verifier）重算。

举个例子，问「华东区二季度销售额是多少」，表头分两级，上面是年份、下面是季度，地区那列是合并格，单位写在表标题里，合计行还引用了另一个 sheet，中间可能还有隐藏列。按「第 $i$ 行第 $j$ 列」去读，这些都会让定位失效。所以第一步用解析器得到单元格图：每个格子的坐标、合并范围、表头层级、公式依赖，别把整张表拍成图。然后识别表头层级，把用户的问题绑到行列键上，取数或者让引擎执行公式，最后核对单位和合计行。跨表就沿着引用链走，别复制粘贴数值。

模型和引擎要分工。模型适合改写问法、选哪张表、解释结果；心算合计、读像素里的数字、自己发明公式，这些都别交给它。抽取完用引擎重算，再检查必须成立的关系，比如合计行、勾稽关系、单位换算。实在要处理扫描件，OCR 之后也要重建单元格图，别让生成模型直接报一个数。评测按表结构族切片，合并格、跨 sheet 单独成集，只拿干净的网格表刷准确率会虚高。

如果做成多 Agent，一个角色理解意图，一个角色操作表格 API，一个角色校验，比三个通用助手互相聊清楚得多，见 `baichuan-multi-agent-collab`。高风险的改表或导出要先过权限，和 SQL Agent 用同一套「执行前拦截」，见 `baichuan-sql-agent-safety-detection`。

## 追问

**VLM 读表为什么不够？**
合并格和公式依赖在像素里就丢了，同一个数字可能是原始值，也可能是合计。结构解析加引擎重算更好校验。

**公式和缓存值对不上怎么办？**
以引擎重算的结果为准，并标出依赖链，别悄悄采用缓存值。

**很大的表怎么放进上下文？**
别整表塞进 prompt。按表头和问题定位到子区域，工具只返回相关的那块矩形。

**怎么验收？**
看单元格级准确率、合计 invariant 和跨 sheet 引用集，按结构族切片报告，别只给一个总分。
