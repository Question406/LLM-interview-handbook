## 真题记录

- 公司：小红书
- 团队 / 岗位：AI Agent 算法
- 届别 / 流程：一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“这个Deep Research是多轮检索，那你会进行到什么程度才停止？用什么判断？”**；**“这些判断的阈值是怎么设置的？”**

常见误区是：写死一个轮数，或把「模型说够了」当成唯一信号。Deep Research 多轮检索会空转、重复 query、被噪声带跑题。停止必须分层：预算做硬停，信息增益和覆盖做软停。简单事实一跳即可，争议话题提高覆盖要求。路由上，简单题根本不该进这条链路，见 `xiaohongshu-simple-complex-route`。

## 硬停止与软停止

硬条件：最大轮数、总 token 数、费用上限、重复 query、连续空召回。这些不依赖模型自觉，防止死循环。软条件：新增文档与已有证据的增量低于阈值；关键问题槽位已填满；模型自报置信且独立 checker 同意。软停可以提前结束，但不能突破硬预算。Observation 过长要先压缩再决定是否再跳，见 `pdd-context-overflow`。重复 query 检测要用规范化后的检索串，而不是字面相等。

## 三类判断：覆盖、增益、质量

原帖提到「三类判断」，落地可对应：覆盖（该找的实体齐了没）、增益（这一跳有没有新信息）、质量（来源是否可信）。覆盖看槽位清单，不看「感觉资料很多」。增益可用新文档与已选集合的重叠、新事实原子数，近似 MMR 的多样性思想，见 `pdd-pick-relevant-chunks`。质量看来源类型、时效、是否冲突；冲突不能当增益，应留下并列证据，见 `xiaohongshu-rag-limits`。在留出的验证集上比较阈值对应的质量和成本：过早停则引用缺失，过晚则延迟和跑题。不要在训练集上调到「刚好停在金标跳数」再拿去吹。

## 分档、日志、和路由一起定

阈值按租户 / 任务类型分档：内部工具可以多跳，面向消费者的产品需要更严格地限制延迟和费用。记录实际停止原因（预算 / 覆盖 / 增益 / 空召回），否则无法调参。误升级进 Deep Research 会烧钱，误降级会漏证据，所以停止策略和简单/复杂路由是同一套预算，见 `xiaohongshu-simple-complex-route`。评测看引用完整率、空转步数、延迟和任务成功，不要只看平均跳数。覆盖用「必填槽位是否齐」，增益用「本跳新增可引用原子事实是否 $\gt 0$」，质量用来源白名单和冲突标记。三者同时满足才软停；任一不满足且预算未尽就继续，预算尽了必须停并降级为「证据不足」。

## 追问

- **模型说够了能不能停？** 不能当唯一信号。必须过覆盖检查或 checker，且不能突破硬预算。
- **阈值能写死吗？** 不能。在验证集上扫早停 vs 空转，按任务分档，并记录停止原因。
- **连续空召回算硬停还是软停？** 建议硬停或立即改写 query 一次；再空就停，避免同 query 空转。
- **简单题为什么也要停止策略？** 简单题应在路由层拦住；一旦误入，硬预算仍要能砍掉，见 `xiaohongshu-simple-complex-route`。
