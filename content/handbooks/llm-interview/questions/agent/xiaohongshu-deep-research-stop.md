## 真题记录

- 公司：小红书
- 团队 / 岗位：AI Agent 算法
- 届别 / 流程：一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“这个Deep Research是多轮检索，那你会进行到什么程度才停止？用什么判断？”**；**“这些判断的阈值是怎么设置的？”**

停止条件我会分两层：预算做硬停，信息增益和覆盖做软停。写死一个轮数，或者把「模型说够了」当唯一信号，都撑不住，Deep Research 的多轮检索会空转、重复 query、被噪声带跑题。简单事实一跳就够，争议话题要提高覆盖要求；简单题从路由层就不该进这条链路，见 `xiaohongshu-simple-complex-route`。

举个例子，用户问某项政策这些年是怎么变的。前几跳拿到了官方文件和主要时间点，再往后一跳，搜出来的全是转述同一份文件的文章，新增的可引用事实为零。这时覆盖齐了、增益没有了、来源也可信，就该软停；如果还缺某个阶段的关键文件，预算也没用完，就继续搜。

硬条件包括最大轮数、总 token 数、费用上限、重复 query 和连续空召回，这些都不依赖模型自觉，用来防死循环。重复 query 检测要比较规范化后的检索串，只比字面会漏掉换了说法的重复。软条件是新增文档相对已有证据的增量低于阈值、关键问题的槽位已经填满、模型自报的置信得到独立 checker 认可。软停可以提前结束，但不能突破硬预算。Observation 过长时先压缩，再决定要不要再跳，见 `pdd-context-overflow`。

原帖提到的「三类判断」，落地可以对应成覆盖、增益、质量。覆盖看该找的实体齐了没有，依据是槽位清单，「感觉资料很多」不算，判定用「必填槽位是否齐」。增益看这一跳有没有新信息，可以用新文档和已选集合的重叠、新事实原子数来算，思路接近 MMR 的多样性，见 `pdd-pick-relevant-chunks`；判定用「本跳新增可引用原子事实是否 $\gt 0$」。质量看来源类型、时效和有没有冲突，用来源白名单和冲突标记来判；冲突不能当增益，要把并列证据留下来，见 `xiaohongshu-rag-limits`。三者同时满足才软停；任一不满足、预算没用完就继续；预算用完必须停，并降级为「证据不足」。

阈值在留出的验证集上定，比较不同阈值对应的质量和成本：停得太早引用会缺失，停得太晚延迟高、还容易跑题。在训练集上调到「刚好停在金标跳数」再拿去讲，没有说服力。阈值按租户和任务类型分档，内部工具可以多跳，面向消费者的产品要更严格地限制延迟和费用。每次都记录实际的停止原因（预算、覆盖、增益、空召回），否则没法调参。误升级进 Deep Research 会烧钱，误降级会漏证据，所以停止策略和简单 / 复杂路由用的是同一套预算，见 `xiaohongshu-simple-complex-route`。评测看引用完整率、空转步数、延迟和任务成功，平均跳数说明不了多少。

## 追问

**模型说够了能不能停？**
不能当唯一信号。必须过覆盖检查或 checker，而且不能突破硬预算。

**阈值能写死吗？**
不能。在验证集上扫早停和空转，按任务分档，并记录停止原因。

**连续空召回算硬停还是软停？**
建议硬停，或者立即改写 query 再试一次；再空就停，避免同一个 query 空转。

**简单题为什么也要停止策略？**
简单题应该在路由层拦住；万一误入，硬预算也要能把它砍掉，见 `xiaohongshu-simple-complex-route`。
