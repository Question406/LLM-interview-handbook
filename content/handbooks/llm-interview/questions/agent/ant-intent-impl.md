## 真题记录

- 公司：蚂蚁集团
- 团队 / 岗位：大模型
- 届别 / 流程：一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“是否做过意图识别？如果要做意图识别，可以怎么实现？”**

原帖问的是「没做过也能讲实现」。错法：端到端 Agent，让模型自己猜用户要转账还是投诉。蚂蚁场景里意图是路由器：taxonomy、规则拦截、低置信澄清、高风险误路由单独计价。工具怎么选见 `agent-tool-routing`，意图恢复见 `kuaishou-agent-intent-recovery`。

## 最小可用链路

1. **定义**：意图表 + 槽位 + 不允许静默猜测的高风险类（转账、改绑、额度、销户）。每类写清要澄清的槽和禁止的默认。
2. **规则**：订单号、卡号、固定话术、关键词黑白名单先拦截，降低明显 case 的模型抖动。
3. **模型**：小分类器或 LLM 多标签；输出意图分布与置信度。低置信或多意图并行时澄清，不要硬路由。
4. **数据**：日志抽样、难例（否定、反讽、多意图、口语、方言）。
5. **评估**：宏平均不够。按意图切片精确/召回，并单列「错成高风险意图」的代价。

意图只决定走哪条技能或工具子集；执行仍要鉴权，见 `agent-tool-permissions`。金融宁可多一轮澄清，也不要把投诉打成支付。

## 和 Agent 怎么接

高确定、低风险：规则或小模型直接走工作流。模糊、多槽：进入带状态的澄清循环，而不是一次 function call。不要用「大模型什么都能分」替代 taxonomy。没有表，就无法回归、无法算误路由成本。上线后用人工抽检和用户改写率看漂移。指标设计可对照 `jd-intent-accuracy`。没做过也可以这样讲落地顺序：先冻结 20 个高频意图和 5 个高风险意图，规则覆盖能覆盖的，其余进分类器；高风险类先追求精确率，长尾再补召回。taxonomy 要版本化，新增意图不能静默改变旧类含义，否则历史标注全废。

## 追问

- **为什么不让 Agent 直接选工具？** 可以当后段。前段意图把高风险动作挡在路由层，工具层再验权，双闸门比单靠模型选 tool 稳。
- **多意图怎么办？** 拆成主意图 + 次意图，或先澄清「这次先处理哪件」。合并成一个超级意图会让槽位和权限爆炸。
- **小模型还是 LLM？** 高频、闭环、标签稳用小模型；长尾、口语、要解释用 LLM，低置信再升级。
- **没有标注怎么冷启动？** 先规则 + 少量种子 + 日志主动学习；先覆盖高风险类的精确率，再铺长尾召回。
