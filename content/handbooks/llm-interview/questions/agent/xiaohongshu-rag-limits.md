## 真题记录

- 公司：小红书
- 团队 / 岗位：大模型秋招算法
- 届别 / 流程：秋招；一面
- 面试时间：原帖未披露；帖子发布于 2025-12-11
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“RAG存在哪些缺陷？”**；**“如何确保大模型输出内容的一致性？”**

常见误区是：「装了检索就不会编」。检索增强生成（RAG） 把错误从参数里挪到检索链路上：切块丢失、索引过期、语义近但事实错、引用错挂、多证据冲突时随机站队。社区笔记还有时效和立场冲突。同面还问生成评测、幻觉、多智能体，短板答完要落到「评测不能只看流畅」，见 `xiaohongshu-hallucination-prompt`。

## RAG 短板按链路拆

结构切断：表格、图注、价格条被切开，见 `xiaohongshu-mmkg-chunk`。语义近但买不了：同款种草文被当成当前 SKU 条款。热更新滞后：活动下线后索引还在。引用错挂：生成引用了未召回块。被噪声带偏：top-$k$ 近重复占满窗口，售后槽位缺失，见 `pdd-pick-relevant-chunks`。对表格 / 多模态弱：OCR 错、图文不一致。冲突被最高分抹平，会把幻觉伪装成检索成功。这些都不是「再加一句根据资料回答」能修的。

## 一致性：固定快照，别连跑三次碰运气

同一 query 固定索引版本、检索参数和 top-$k$ 集合；解码降随机或约束 JSON；冲突时输出「来源 A/B」而不是随机站队。模板、工具 schema、检索版本组成不可变 release，见 `pdd-prompt-template-versioning-rollback`。一致性包含两层：同一输入多次输出稳定，以及引用指向的块稳定。前者靠温度和结构化解码，后者靠快照和引用校验。不要用「连抽三次取众数」当线上方案，那是掩盖方差。

## 评测：一致率、引用稳定、任务成功

用同题多次的一致率和引用稳定率，加上无根据原子事实、过期活动引用、冲突是否被抹平。流畅度只能当辅助。多 Agent 或 Deep Research 会引入更多检索跳，停止和选块策略不当会进一步破坏一致，见 `xiaohongshu-deep-research-stop`。能固定快照的评测，才能把模板改动和检索漂移切开。秋招连问生成评测时：RAG 解决的是「缺知识」，不解决「检索错仍自信」；所以评测必须单列引用错误和冲突处理，别只看通顺。同一 query 换索引版本要当成新实验，不要和提示改动混在一个 A/B 里。

## 追问

- **RAG 能消灭幻觉吗？** 不能。检索错、切块丢、冲突被抹平仍会编，见 `xiaohongshu-hallucination-prompt`。
- **温度设 0 就一致了吗？** 不够。检索集合若漂，低温度只是稳定地复述错资料。
- **冲突时怎么保持一致？** 并列来源或升级澄清，禁止静默赢家。
- **线上如何复现某次回答？** 记录索引版本、top-$k$ ID、模板 release，否则无法复现。
