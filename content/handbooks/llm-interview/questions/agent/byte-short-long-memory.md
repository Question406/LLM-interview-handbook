## 真题记录

- 公司：字节跳动
- 岗位：AI Agent 开发；秋招一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“短记忆和长记忆分别存什么？怎么避免长记忆污染当前任务？”**

常见误区是：把整段对话、中间试错的错误假设写进长记忆，下次任务当事实用。短记忆是当前任务的工作状态，易变可丢；长记忆是跨会话仍成立的约束和已验证结论，写入必须过校验。隔离做错，污染会压过本轮证据。总览见 `agent-memory`，污染纠错见 `byte-memory-pollution`。

## 分别存什么

短记忆：本轮打开的文件、失败测试、未提交 diff、刚拿到的工具观察。生命周期等于这次会话或这次任务，任务结束可清空。组装当前上下文时使用这些信息，不把它们用于跨会话的长期检索。

长记忆：仓库规范、用户偏好、上次确认过的架构事实。每条带来源、时间和可失效条件（文件哈希、文档版本）。「本仓登录超时默认 30s，见 `config/auth.yaml`」可以进长记忆；「我觉得 `auth.py` 里那个函数没用」不能进。

适用条件是用户会回来、约束相对稳定的多会话 Coding Agent。单次问答、窗口已装得下全部证据时，不必硬拆两套存储。拆的目的是控制写入质量和注入范围，不是为了架构图好看。

## 怎么避免长记忆污染当前任务

当前任务优先短记忆加实时检索；长记忆只注入「已确认且仍有效」的约束，并且要经过检索命中，而不是每次把全部偏好顶进窗口。注入前校验哈希：文件已变则条目失效，见 `byte-memory-pollution`。

写入门槛：能指出证据，测试绿了、用户口头确认、文档哈希，而不是模型自己总结了一句。过程吐槽、失败栈、中间错误假设留在短记忆，最多写成「未验证」。长记忆检索应带任务类型过滤，修登录超时时不要把「前端组件库偏好」灌进来。

与检索增强生成（RAG）的区别是：RAG 按需取外部只读文档；Memory 是 Agent 自己沉淀的带 provenance 的状态。不要把对话摘要当 RAG 证据，也不要把检索 README 当长期记忆，见 `byte-rag-memory-context`。污染当前任务的另一条路径是「长记忆抢窗口」：即使用户这次在修无关模块，全量偏好列表仍把失败测试挤出 L0。注入要有预算，硬约束优先于软偏好；冲突时以本轮测试和 diff 为准，长记忆让路而不是相反。

例如修登录超时：短记忆留下当前改了 `auth.py`、pytest 第三条失败、diff 未 commit；长记忆最多写超时配置的路径与哈希。下次换任务短记忆清空，长记忆只在检索命中「超时 / 登录」时注入那一条。

## 失败模式

未验证结论入库，后面任务一直绕开正确入口；文件改了摘要没随哈希失效；短记忆过长被误写入长记忆。写入长记忆应走独立审核路径（规则或人审），不要在压缩回调里偷偷落库。压缩时要把过程吐槽和可检索笔记分开，见 `byte-three-level-compress`。评测看：约束是否保持、过期是否失效、错误结论被证伪后是否回滚。别只用「记忆条数」。

## 追问

- **对话摘要能不能当长记忆？** 摘要丢失证据指针，且常含错误假设。最多当短记忆的压缩，不能当跨会话事实。
- **长记忆和向量库是一回事吗？** 可以用向量做检索，但存储语义是带失效条件的状态，不是又一份文档索引。
- **用户改口了怎么办？** 新确认覆盖旧偏好，旧条目标废弃并留审计；不要两条相反偏好同时注入。
- **同面常接着问什么？** 记忆污染怎么纠、RAG 和 Memory 差在哪。三连问要能画清读写、失效和评测，而不是换三个同义词。
