## 真题记录

- 公司：小红书
- 团队 / 岗位：NLP / 多模态 / 大模型实习生
- 届别 / 流程：实习；一面
- 面试时间：2026-04-08 19:00
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“MMKG-RAG，如何分块，实体和关系的抽取与合并”**

MMKG-RAG 的分块、抽取、合并是一条链路，我的原则是每一步都保住证据：按版面和语义单元切块，实体和关系都要能指回证据，合并时冲突留多值。切错了，后面抽取再准，也只是半截证据。常见的错法是按纯文本 token 长度切笔记，或者让模型凭空补出「代言」「同款」这类边。

小红书笔记是图文混排的。比如一篇探店笔记里有一张价目表图片，图下写着价格；按 token 长度切，价格那行文字进了一块，图片和店名进了另一块，检索时就会召回一个不知道是哪家店的价格。图注离开图片、表格被横切，召回的都是半截事实。

分块时，笔记按段落加图片区域切，表格按行组切，视频按镜头关键帧配字幕。每块带模态类型、坐标或时间、权限。图注、OCR、价格条和对应的图片留在同一块，或者用显式的边连起来，不要把图注单独扔进文本索引。重叠部分用来保留跨图文的指代关系，没必要把整页重复复制。粒度的标准是「这块能否独立支撑一个槽位」：切太碎会丢关系，切太大召回噪声多。权限随块走，隐私图不能因为文本被召回就带出来。

抽取时，文本侧做 NER 和开放关系抽取，视觉侧做物体、OCR 和版面。每个实体带证据 span 或框；关系必须能指回证据块，「代言」「同店」这类高风险边不允许模型补。开放抽取要收口到业务的字段和类型规范（schema），比如商品、地点、价格、功效，否则图会膨胀到不可用。低置信的抽取先进待审，不直接进可检索图。功效和医疗主张默认不建边，和 hallucination 策略一致，见 `xiaohongshu-hallucination-prompt`。

合并时，用同名、别名词典、视觉相似和属性重叠做候选，按阈值交给人工或二次模型确认。笔记里同款、拼图、水印文案很多，视觉相似不等于同一商品，所以合并阈值宁严勿松；松了，图会把两个价格并成一个「真值」，到生成阶段就很难纠正。冲突（两个价格、两个产地）保留多值并打上来源，不要静默覆盖。图的更新要版本化。检索时，实体召回和文本块召回融合，再按槽位覆盖和多样性截断，选块和冲突处理见 `pdd-pick-relevant-chunks`。评测看实体对齐错误、无证据边的比例、冲突有没有被抹平，以及图文拆开后的召回失败。检索增强生成（RAG）的其他短板见 `xiaohongshu-rag-limits`。

## 追问

**为什么不能按固定 token 切？**
会切断图注、表格行和价格，半截事实会被当成完整证据。

**没有证据的关系怎么办？**
不入库。宁可不连，也不让生成阶段引用空想出来的边。

**同名商品怎么合并？**
先找候选再确认；属性冲突留多值，不用最高分覆盖。

**图更新了，旧边怎么办？**
版本化。检索绑定图版本，避免和生成模板各用各的快照，见 `xiaohongshu-rag-limits`。
