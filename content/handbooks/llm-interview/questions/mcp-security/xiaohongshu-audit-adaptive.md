## 真题记录

- 公司：小红书
- 团队 / 岗位：NLP / 多模态 / 大模型实习
- 届别 / 流程：一面；反问阶段谈业务
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：“开发与运营的价值观对齐：基于网信办、用户、公众、运营等各方群体的最大公约数”；“审核标准的自适应与动态变更”

审核标准的自适应，靠的是把政策版本化：新规先离线回放、再灰度、再全量，难例回流进下一版的标注池。模型是执行器，政策是外部输入，模型无权自己改规则。价值观对齐取各方的公约数：违法红线不可谈判，社区体验和商业是软约束；Agent 和工具也不能绕过当前生效的政策版本。

常见的错答是「让 reward 把模型自己变严」，或者把价值观答成个人品味。比如模型发现最近擦边内容很多，就自行加严，这种变化不可审计，奖励一旦可被 hack，它还会学到没有依据地拒绝正常内容。自适应的合法来源是运营修订和 case 回流。

## 自适应怎么落地

链路是这样的：政策文本版本化 → 金标集按版本切（同一条笔记在 v12 和 v13 下标签可以不同）→ 新规先离线回放历史流量，看漏放 / 误伤怎么变 → 灰度（按人群、品类、端）→ 全量。难例来自运营申诉、舆情和监管函，进下一版的标注池，在线改 system 输入提示（prompt）不能当发版。

日常可以讲成一个闭环。运营或法务改细则，出变更日志和生效时间；标注组按新规改金标，保留旧版本快照；离线回放近一周的流量，按品类、作者等级切片看漏放和误伤；小流量灰度，申诉工单当作活难例；最后全量，并冻结这一版的奖励模型。模型侧可以换 SFT 数据、调规则奖励的权重，但生效开关是政策版本，损失（loss）自己变了不算发版。

难例回流要防偏。只回流被投诉的笔记，会把模型推向「少杀」，漏放上升；只回流监管点名的，模型只会学到那一类。抽样要按漏放、误伤、争议三类分配配额。评测也必须同时报漏放（有害内容过审）和误伤（正常笔记被错拦），只优化一边不行，收紧了创作者出走，放宽了有监管风险。版本切换时还要回归旧金标，新规不该把上一版明确允许的笔记大批误杀，除非变更日志写明了。

## 跟谁对齐

原帖给了四方：网信办 / 监管、用户、公众、运营。我会分层答，四家意见平均成一个标量没法执行。最硬的一层是违法、未成年人、违禁品，任一触发即拒，不存在「用户爱看所以放过」。中间一层是社区体验，比如引战、低质、标题党，按运营细则处理，允许申诉。商业一层管广告标识和导流，服从平台规则，但不能压过硬约束。后训练（监督微调（SFT）/ 基于人类反馈的强化学习（RLHF）/ 规则奖励）拟合的是当前版本的金标和细则，抽象的「正能量」没法拟合。

分工上，开发别替运营发明红线。开发提供可执行的字段（是否涉及未成年人、是否有医疗功效宣称、是否隐形广告）和可回归的指标，运营提供阈值和例外。出现冲突，升级到有权改政策的人，别让审核模型「综合判断一下」。Agent 如果能调「放行」工具，调用必须带当前的 `policy_version`，过期就失败。这和 MCP 权限是同一个逻辑：工具不能绕过生效的规则。

## 追问

**模型能不能建议改规则？**
可以出难例报告和切片跌点，但不能直接改线上政策，也不能在奖励分数（reward）里偷偷加严。

**多模态怎么自适应？**
图文要用同一版本的细则，只审文会漏图，只审图会漏导流文案。切片按模态分别报漏放 / 误伤。

**灰度失败怎么回滚？**
切回上一个 `policy_version` 和对应的模型 / 阈值，金标集也回切，进行中的 Agent 调用一并失效。

**和价值对齐论文是什么关系？**
论文里的人类偏好是软信号；审核业务里监管红线排在偏好模型前面，「多数用户爱看」覆盖不了红线。

**关键词表为什么不够？**
黑话、谐音、图文分工都能绕过去。规则版本化以后仍然要模型 + 人工抽检，关键词表只是硬约束里的一层。
