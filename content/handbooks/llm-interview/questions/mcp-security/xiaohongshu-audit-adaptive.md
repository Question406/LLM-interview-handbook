## 真题记录

- 公司：小红书
- 团队 / 岗位：NLP / 多模态 / 大模型实习
- 届别 / 流程：一面；反问阶段谈业务
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“开发与运营的价值观对齐：基于网信办、用户、公众、运营等各方群体的最大公约数”**；**“审核标准的自适应与动态变更”**

这块容易直接答成「让 reward 把模型自己变严」，或把价值观答成个人品味。政策是外部输入，模型是执行器。多方对齐取公约数：违法红线不可谈判；体验与商业是软约束。Agent / 工具不得绕过当前生效的政策版本。

## 自适应是版本化规则，不是模型改政策

工程化链路：政策文本版本化 → 金标集按版本切（同一条笔记在 v12 与 v13 标签可以不同）→ 新规先离线回放历史流量，看漏放 / 误伤怎么动 → 灰度（人群、品类、端）→ 全量。难例回流来自运营申诉、舆情、监管函，进下一版本的标注池，而不是在线改 system prompt 当发版。

自适应的合法来源是运营修订与 case 回流；不合法的是「模型发现最近很多擦边就自行加严」。后者不可审计，也会在奖励可 hack 时学到乱杀。评测必须同时报漏放（有害过审）和误伤（正常笔记被杀）。只优化一边：收紧则创作者出走，放宽则监管风险。和 MCP / Skill 题连起来：工具调用也要带 `policy_version`，过期策略不能执行。

## 跟谁对齐：公约数，不是加权平均口味

原帖给的四方：网信办 / 监管、用户、公众、运营。答法是分层，不是把四家意见平均成一个标量：

- **硬约束**：违法、未成年人、违禁品，任一触发即拒，不存在「用户爱看所以过」。
- **社区体验**：引战、低质、引战标题党，用运营细则，允许申诉。
- **商业**：广告标识、导流，服从平台规则，不能压过硬约束。

后训练（SFT / RLHF / 规则奖励）拟合的是当前版本的金标与细则，不是抽象「正能量」。版本切换时要回归旧金标：新规不该把上一版明确允许的笔记大批误杀，除非变更日志写明。公约数落在分层规则 + 版本回归，模型没有立法权。

自适应的日常操作可以讲成闭环。运营或法务改细则 → 出变更日志和生效时间 → 标注组按新规改金标，旧版本快照保留 → 离线回放近一周流量，看漏放 / 误伤在品类、作者等级上的切片 → 小流量灰度，申诉工单作为活难例 → 全量并冻结该版本奖励模型。模型侧可以换 SFT 数据或调规则奖励权重，但生效开关是政策版本，不是 loss 自己变了。难例回流要防偏见：只回流被投诉的笔记，会把模型推向「少杀」，漏放上升；只回流监管点名的，会只学会那一类。抽样应对着漏放、误伤、争议三类配额。

多方公约数落地时，开发不要替运营发明红线。开发提供可执行的字段（是否未成年人、是否医疗功效宣称、是否隐形广告）和可回归的指标；运营提供阈值和例外。冲突升级到有权改政策的人，而不是让审核模型「综合判断一下」。Agent 若能调「放行」工具，必须带当前 `policy_version`，过期调用失败。这和 MCP 权限同一逻辑：工具不能绕过生效规则。

## 模型执行政策，不立法

自适应是新规版本化、金标按版本切、离线回放、灰度、难例回流，不是 reward 让模型自己变严。多方对齐取分层公约数：监管红线不可谈判，体验和商业是软约束，不能加权平均成一个品味分。漏放和误伤必须同时报，只优化一边会翻车。后训练拟合的是当前版本金标，切换时要回归旧集。Agent 工具带 `policy_version`，过期调用失败。开发提供可执行字段和指标，运营改阈值，冲突升级到有权改政策的人。关键词表不够挡黑话和图文分工，但仍是硬约束的一层。我会把「版本、回归、分层红线」说清，不空谈价值观。

## 追问

- **模型能不能建议改规则？** 可以出难例报告和切片跌点，不能直接改线上政策，也不能在 reward 里偷偷加严。
- **多模态怎么自适应？** 图文要同一版本细则；只审文会漏图、只审图会漏导流文案。切片按模态报漏放 / 误伤。
- **灰度失败怎么回滚？** 切回上一 `policy_version` 与对应模型 / 阈值，金标集也回切；进行中的 Agent 调用一并失效。
- **和价值对齐论文？** 论文里的人类偏好是软信号；审核业务里监管红线先于偏好模型，不能用「多数用户爱看」覆盖。
- **关键词表为什么不够？** 黑话、谐音、图文分工会绕过；规则版本化后仍要模型 + 人工抽检，表只是硬约束的一层。
