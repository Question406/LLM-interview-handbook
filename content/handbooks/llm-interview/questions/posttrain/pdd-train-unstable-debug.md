## 真题记录

- 公司：拼多多
- 团队 / 岗位：大模型算法日常实习
- 届别 / 流程：日常实习；二面
- 面试时间：原帖未披露；帖子发布于 2026-03-15
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“训练不稳定怎么排查”**

我会先把「不稳定」定义清楚，再按五层逐层排查，每次只改一个因素，并用固定小集复现。cross entropy loss（CE）或 RL 的损失（loss）是不是 NaN、grad norm 有没有尖刺、下游分是不是来回跳、还是只是曲线不够平滑，这几种处理方式都不一样。throughput 抖动（通信卡住、机器被抢占）也别和数值发散混成一句「训崩了」。一上来就「把 lr 再降一档」是最常见的错：mask 错、NaN、空组不会因为步长变小就变对，只会训得更慢。结论要落到「改哪一层」。

五层按诊断顺序排，从数据到奖励。

数据层先查空文本、超长截断、mask 错误（prompt 被打了 loss，或者回答没打上）、偏好对颠倒、突然混进了新模板或新语言。看 batch 的 token 长度直方图、空样本率和模板版本。比如数据换了一版模板，loss 会先跳一下，然后「看起来在学」，其实是在拟合新格式。

数值层看 bf16 溢出、loss scale、embedding 没绑定、LoRA $\alpha/r$ 过大、grad clip 没开。NaN 往往出在这一层，降 lr 没用。

并行层看 ZeRO 漏同步、drop-last 让有效 batch 跳变、不同 rank 的数据没对齐，表现是 loss 周期性尖刺，或者 rank 之间的 grad 对不上。优化层看 lr 预热不够、batch 太小、warmup 步数和峰值 lr 不匹配、clip 范围极端。

最后是 RL 层：奖励尺度跳变、组内全零优势、KL 突然被关掉、验证器（verifier）超时被当成 0 分。SFT 查前四层就够，GRPO/PPO 必须加上这一层。五层别一起改，这份清单是诊断顺序，别当成一次全打上的补丁包。

复现要守纪律。用固定小集加单卡（或者单数据并行）把尖刺复现出来，再恢复分布式。一次只改一个因素：先修 mask 再动 lr，先开 clip 再改并行。小集上能复现，说明不是偶发的通信问题；小集很稳、一上多卡就炸，才转去查并行和有效 batch。seed、数据切片、精度和并行配置都记下来，别靠「再训一次看看」。

也有些「不稳定」算不上事故。曲线不平滑但 holdout 很稳，可能只是 log 间隔或小 batch 的噪声。下游分来回跳，要看评测解析器、decoding 温度和模板是不是一起变了，那是评测不稳，跟训练无关。所以要把「不稳定」写成可观察的指标：哪条曲线、哪个 step、能不能复现，然后再进五层。

RL 有几个特有的问题。GRPO 组内全对或全错时优势为 0，有效更新变稀疏，曲线就会抖。奖励分数（reward）没 standardization 时，某一批难度突变会让优势爆炸。KL 系数被关掉或者 controller 过冲，策略会突然变成长篇空话，reward 看着很好，语言已经崩了。排查顺序是有效组比例、reward 直方图、KL / entropy，最后才谈算法，别先换 PPO。verifier 超时被当成 0 分会制造假负样本，表现为「突然不会做了」，先修超时和默认分，再怀疑策略。美团那张 reward 震荡卡里的监控项（KL、entropy、有效组）可以直接复用。

## 追问

**只降 lr 为什么不够？**
mask 错、NaN、空组不会因为步长变小就变对，只会训得更慢。先定位到层，再谈步长。

**怎么判断是并行问题？**
单卡小集稳、多卡同一份数据出尖刺，就查同步、drop-last 和有效 batch。rank 之间 loss 对不上是很强的信号。

**loss 很平滑，线上却在抖？**
查 decoding、模板开关、评测集里有没有混进训练模板。那是推理或评测的问题，别回头乱改优化器。

**和美团震荡卡怎么一起答？**
这张卡给分层清单和复现纪律，那张卡给 KL / 有效组这些监控项，结论都落到「改哪一层」，并给出复现实验，别只说「再训一次」。只说「RL 就是不稳」等于没答。
