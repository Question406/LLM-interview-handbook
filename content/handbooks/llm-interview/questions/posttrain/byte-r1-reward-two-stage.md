## 真题记录

- 公司：字节跳动
- 届别：26 届秋招；二面提及
- 原始措辞：**“Deepseek r1 里面的奖励（奖励函数和奖励模型），1阶段，2阶段如何开展”**

陷阱是背「1 阶段、2 阶段」编号，却说不清每段在修哪种失败。R1 公开叙述里，**奖励函数**和**奖励模型**不是一路货；阶段按失败模式拆，不按发布名拆。把 RM 直接接到数学 RL 上，是这条题最容易被追打的答法。面试官要听的是：什么信号可扩规模、什么信号会 hack、冷启动缺了会崩哪一类指标。

## 1. 规则奖励与奖励模型：覆盖范围和失败模式不同

**规则 / 可验证奖励（reward function）**：数学最终答案、代码测试、格式标签、工具是否成功，由 checker 或 sandbox 给出 $0/1$ 或分级分。噪声低、可扩规模，覆盖不了开放性文采与主观偏好。R1 路线的 reasoning RL 主信号就是这类 RLVR：正确性为主，格式为辅，避免用神经网络过程 RM 当推理主奖励——怕 CoT 被教成「看起来像推理」。

**奖励模型（RM）**：在偏好对上拟合标量 $r_\phi(x,y)$，适合 helpfulness、安全、拒答风格。标注贵，且政策会对着 $r_\phi$ 的漏洞刷分。开放域没有唯一 checker 时才需要它。合成时不要混：可验证任务用规则；开放对齐再用 RM 或 DPO。过程 RM 可以当辅助，但不能替代可执行 outcome。

规则奖励的失败：开放题无定义；格式分过重会刷标签；checker 泄漏（答案在 prompt 里、测试用例可猜）会让 RL 学捷径。RM 的失败：分布外给高分胡话、长度 bias、与业务偏好不一致。面试把这两种失败分开讲，比背「R1 不用 RM」更准——R1 是 **推理主路径不用易 hack 的神经奖励**，不是永远不用偏好模型。

## 2. 阶段按失败模式开展

公开路径可以概括成，而不是死记编号：

1. **冷启动 / SFT。** 人写或筛选过的长链，解决「不会长推理、格式崩、语言不可读」。没有这一段，纯 RL 也能涨分（R1-Zero），但可读性和稳定性差，解析失败会把有效奖励率打穿。Cold start 不是再做一遍全量指令微调，而是给后续 verifier 一个可解析的状态分布。
2. **大规模 reasoning RL。** 组采样加规则奖励，冲可验证正确率。解决的是「示范外的正确路径不会探索」。组内要能出现对错混合，否则 $\hat{A}=0$。奖励应尽量干净，格式只做轻量门控。
3. **视需要的对齐后处理。** 拒绝采样再 SFT、偏好对齐，补风格、安全和拒绝。解决的是「只会刷题不会说话 / 乱答」。这一段若丢掉可验证题，推理会从「会搜索」退回「会说得像在搜索」。

业务落地要补三件事：有没有可靠 verifier、组采样规模够不够、有没有崩溃监控（熵、长度、违规）。缺 verifier 时不要假装在做 R1 第二阶段。格式未稳就上 RL，解析噪声会把优势变成随机符号。

## 3. 和生产配方的对应关系

R1-Zero 证明的是存在性：强基座加可验证奖励，纯 RL 也能涌现长思考。生产仍常用多阶段，因为产品目标集合更大——可读、可解析、可对齐、通用能力不掉。字节面这题，往往还想听你会不会把「阶段」翻译成你们业务：字段抽取有 schema checker 就像规则奖励；客服话术没有 checker 就该走 RM / DPO，不要硬套 R1 编号。

两阶段若切错：冷启动做成大规模聊天 SFT，后面 reasoning RL 的信号被风格先验稀释；RL 做成刷格式；对齐做成只优化偏好、数学回退。门控要写成 go / no-go：格式率不达标不进 RL，pass@k 不抬不进下一阶段。

## 追问

- **R1-Zero 为什么能跳过 SFT？** 基座已有推理胚芽，且奖励可自动核验；代价是语言与格式更脏，不适合直接当产品。
- **过程 RM 能不能当主奖励？** 可以当辅助 dense 信号，主信号仍应可验证；否则 PRM 自己会被 hack。
- **你们业务对应哪一段？** 用失败模式答：不会格式 → 冷启动；正确率平台 → RLVR；风格安全差 → 偏好。不要报「我们做了第二阶段」。
- **规则奖励和格式奖励怎么加权？** 正确性为主，格式只做门控或小系数；格式权重大，模型会交空标签和套话。
