- 原始措辞：**“Pretrain 和 SFT 分别解决什么问题？”**

错法：把两段说成「都是 next-token，只是数据换了」。目标函数长得像，解决的失败不同：pretrain 解决「会不会语言 / 有没有世界知识」，SFT 解决「会不会按你的任务说话」。电商面试再往下会接偏好或 RL，那是第三阶段，不要和前两段混为一谈。SFT 也不能替代继续预训练去补全新领域知识，整块品类百科塞进对话对，模型往往只会背答案，换问法就空。三句话：pretrain 学无条件（或弱条件）语言分布，SFT 学指令条件下的任务映射，对齐学比较或奖励。只做前两段可以出基线，但遇到「同样正确但更短 / 更安全」时 CE 没有方向。

## Pretrain：建立语言与知识底座

目标是语言建模：在多样化语料上最小化 next-token loss，学句法、事实片段、推理雏形和长上下文统计结构。数据工作是清洗、去污、配比和质量过滤，评测看 perplexity 与通用下游探针。它不保证服从指令，也不保证输出合法 JSON 或电商业务字段，模型可能「会写」，但不会按客服槽位填，更不会在该拒的时候拒。

失败模式是知识空洞、语言不稳、长上下文统计没学够。这时加再多指令对也补不回底座；该走继续预训练或领域 corpus 配比，而不是把百科塞进 SFT 当对话。电商场景里，类目属性、活动规则若在 pretrain 里几乎没见过，SFT 只能教「怎么填字段」，教不会「字段里该填什么事实」。instruction pretrain 把指令数据提前混进配比，仍属底座阶段，不等于已经对齐到产品格式。

## SFT：把能力对准任务与格式

SFT 的目标是条件任务映射：给定 instruction / 业务上下文，生成符合规范的回答。它把预训练能力「对准」客服、导购、抽取、工具调用等格式，并补领域术语和话术。loss 通常只打在回答 token 上，prompt 做条件不回传监督。数据必须去模板化、防 train/test 泄漏，否则会上线只会套话、评测虚高。示范要覆盖该出现的格式，也要覆盖不该出现的乱格式的对照，否则模型只会复述高频模板。

失败模式是不听指令、格式乱、业务槽位错。底座够、示范不对，就会出现「什么都懂一点、字段对不上」。这不是再 pretrain 能单独修好的。SFT 假设单条 $y^\star$ 近似最优，多答案权衡要留给偏好或奖励阶段。

## 不能互相替代，后面才是对齐

SFT 不能替代继续预训练去补全新领域知识；pretrain 也不能替代 SFT 去学产品话术和可解析输出。电商场景常在 SFT 后再接偏好 / RL：多答案权衡、安全、可验证字段，那是第三阶段。面试把边界画清：知识大洞 → 继续预训练；格式和指令 → SFT；比较和探索 → DPO / RL。只报「我们做了 SFT」而不说缺的是哪一类失败，下一问就会被问穿。两段的评测也不同：pretrain 看探针和污染，SFT 看指令遵循、字段合法率和业务成功，不要用 perplexity 宣布 SFT 成功。

## 追问

- **SFT 要不要对 prompt 算 loss？** 通常不算。算了会把指令本身也拟合成「生成目标」，浪费监督还容易训推模板错位。诊断异常高起点时，先查是不是把 prompt 打进了 CE。
- **领域知识不够，加 SFT 行吗？** 少量术语可以；整块新知识应走继续预训练或检索，硬 SFT 容易背答案、换问法就空。
- **和 instruction pretrain 的区别？** 那是把指令数据提前混进 pretrain 配比，仍是底座阶段；不等于已经对齐到产品格式，也不等于可以跳过 SFT。
- **为什么后面还要 DPO/RL？** SFT 假设单条示范近似最优，表达不了「同样正确但更好」。见偏好对齐卡。可验证字段则走 RLVR，不要和前两段混名。
