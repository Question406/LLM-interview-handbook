- 原始措辞：**“Pretrain 和 SFT 分别解决什么问题？”**

Pretrain 解决「会不会语言、有没有世界知识」，SFT 解决「会不会按你的任务说话」。两段的目标函数都是 next-token，长得很像，所以很多人答「只是数据换了」，可它们修的失败完全不同。用三句话说：pretrain 学无条件（或弱条件）的语言分布，SFT 学指令条件下的任务映射，对齐学比较或奖励。电商面试往下还会接偏好或 RL，那是第三阶段，别和前两段混在一起。

先说 pretrain。目标是语言建模：在多样化语料上最小化 next-token 损失（loss），学句法、事实片段、推理雏形和长上下文的统计结构。数据上的工作是清洗、去污、配比和质量过滤，评测看 perplexity 和通用下游探针。它不保证听指令，也不保证输出合法 JSON 或电商业务字段。模型可能「会写」，却不会按客服槽位去填，更不会在该拒绝的时候拒绝。

pretrain 没做好，表现是知识空洞、语言不稳、长上下文统计没学够。这时候加再多指令对也补不回底座，该做继续预训练或者调整领域 corpus 的配比，别把百科塞进 SFT 当对话。举个电商的例子：类目属性、活动规则在 pretrain 里几乎没见过，SFT 只能教模型「怎么填字段」，教不会「字段里该填什么事实」。整块品类百科做成对话对塞进 SFT，模型往往只会背答案，换个问法就答不上来。instruction pretrain 把指令数据提前混进配比，仍然属于底座阶段，不等于已经对齐到产品格式。

再说 SFT。它的目标是条件任务映射：给定 instruction 和业务上下文，生成符合规范的回答，把预训练的能力对准客服、导购、抽取、工具调用这些格式，顺带补领域术语和话术。loss 通常只打在回答 token 上，prompt 只当条件。数据要去模板化、防 train/test 泄漏，否则上线后只会套话，评测分还虚高。示范要覆盖该出现的格式，也要有乱格式的对照，否则模型只会复述高频模板。

SFT 没做好，表现是不听指令、格式乱、业务槽位填错。底座够、示范不对，就会出现「什么都懂一点、字段对不上」，这种情况再做 pretrain 也修不好。SFT 还假设单条 $y^\star$ 近似最优，多个答案之间的权衡要留给偏好或奖励阶段，只做前两段可以出基线，可遇到「同样正确但更短、更安全」时，cross entropy loss（CE）给不出方向。

所以面试里我会说明各方法的适用条件：知识有大洞，走继续预训练；格式和指令，走 SFT；比较和探索，走 DPO/ RL。只报「我们做了 SFT」、不说缺的是哪一类失败，下一问就会被问穿。两段的评测也不一样：pretrain 看探针和污染，SFT 看指令遵循、字段合法率和业务成功，别拿 perplexity 宣布 SFT 成功。

## 追问

**SFT 要不要对 prompt 算 loss？**
通常不算。算了会把指令本身也当成生成目标去拟合，浪费监督，还容易造成训推模板错位。起点 loss 异常高时，先查是不是把 prompt 打进了 CE。

**领域知识不够，加 SFT 行吗？**
少量术语可以；整块新知识应该走继续预训练或者检索，硬做 SFT 容易背答案，换个问法就空。

**和 instruction pretrain 有什么区别？**
那是把指令数据提前混进 pretrain 的配比，仍然是底座阶段，既不等于已经对齐到产品格式，也不能因此跳过 SFT。

**为什么后面还要 DPO / RL？**
SFT 假设单条示范近似最优，表达不了「同样正确但更好」，这部分见偏好对齐那张卡。可验证的字段则走 RLVR，名字别和前两段混。
