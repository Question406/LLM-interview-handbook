我会把能力和安全拆成两套冻结的评测包，各自相对基线设 threshold，候选版本两边都过了才放行；发现回退再用约束、回放或交错训练去压，光加大 KL 解决不了。用一个加权总分宣布「都涨了」，最容易把一边的退步平均掉。

这里的「回退」，指相对一个明确基线（SFT 模型或上一个对齐版本），在能力或安全的某个切片上明显变差。两个方向都会发生。比如做完代码 RL，HumanEval 涨了，可「帮我写个危险脚本」这类越狱的成功率也涨了，因为奖励只认测试通过，不管是不是在协助滥用，这是安全回退。反过来，做完安全 DPO，越狱率降了，但「怎么加密备份」这种良性的安全知识题开始被拒，模型把安全相关的词学成了拒绝开关，这是助益、也就是能力上的回退。两个例子都是主指标涨、对照切片掉。

为什么会这样？能力侧的 RLVR 常常把模型推向过度合规、越狱更脆弱；安全侧的 SFT / DPO 常常提高拒答，顺带伤到长得像的良性请求。两边的数据分布和目标本来就冲突，一个标量很难同时最大化。Safetywashing 那篇还提醒过，综合安全分涨了，可能只是因为它和能力基准相关：模型变聪明了，安全基准跟着涨，越狱和危险协助未必真的更好。

## 检测：两套包，分开看

具体做法是维护两条（或多条）冻结的评测包。capability suite 看主任务、工具调用，以及那些不该拒的助益题；safety suite 看越狱、危险协助和 over-refusal（false refusal）。每次候选都要分别通过两项 evaluation checks，threshold 相对基线设，别看绝对分「还行」就放。分组统计比全局均值重要：主任务涨、越狱掉，或者越狱降、助益拒答升，都算回退，总分会把它们平均掉。

「不会答」和「不该答」要分开测：能力包测前者，安全包测后者。同一个 prompt 家族最好两边都放对照，不然拒答会被算成能力，助益题被拒也会被漏掉。评测包还得和训练隔离，安全题进过训练就会出现虚假进步，这和能力评测的污染是同一类问题。

## 抑制：约束、回放、交错

发现回退，先归因：是数据配比、奖励权重、KL 太松，还是评测和训练重叠造成的假进步。训练侧可以用 Safe RLHF 那种约束形式，最大化能力，同时要求安全代价 $\le$ 阈值；也可以做安全数据回放、分阶段交错训练。能力阶段留一小股安全 replay，安全阶段留能力 replay，防止灾难遗忘。对违规轨迹直接硬拒绝比「再减一点奖励」干净，违规的东西就不进优化，用不着指望 reward model（RM）给它打低分。

光盯一个指标都会出事：只盯拒答率，良性的安全知识题会被一起拒掉，表现成能力回退；只盯主任务，越狱路径会被一起强化，表现成安全回退。所以前面代码 RL 的例子，修法是对危险类别硬拒绝或加安全 replay，再刷 HumanEval 没用；安全 DPO 的例子，修法是把助益对照放进训练，acceptance checks 盯 false refusal，别再加压拒答。

交错训练时，两边都通过 acceptance checks 才切阶段，免得「安全周」把能力洗掉、「能力周」再把安全洗回来。配比实验和奖励权重都写进回归报告，只报最终总分就是 washing。

## 追问

**「不会答」和「不该答」怎么分？**
能力包测前者，安全包测后者。同一个 prompt 家族两边都要有对照，否则拒答会被算成能力，助益题被拒会被漏掉。

**把 KL 调大能当安全措施吗？**
不能。KL 只限制漂移，规定不了 security constraints；reference policy 本身要是不安全，KL 还会把坏行为钉住。decision criteria 要通过数据与 constraints 明确。

**安全基准泄漏会怎样？**
安全题进过训练，分数就会虚假上涨。评测包必须冻结，并且和训练隔离，跟能力评测防污染是一回事。

**能不能把安全和能力加成一个标量一起优化？**
很难稳定做到。目标冲突时用约束或交错训练，把两者塞进同一个奖励分数（reward），加权总分最容易被 washing。
