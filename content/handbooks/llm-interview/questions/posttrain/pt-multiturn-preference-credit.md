我会先找到两条会话从哪一轮开始分叉，把偏好信号只落在分叉之后的回合上，共享前缀当条件、不更新。用户通常只评整段 $A\succ B$，可导致胜负的可能是第 $t$ 轮一次错误的工具调用，也可能是第 1 轮的一个错误承诺。稀疏的终局偏好其实是延迟奖励，不把结果归因到相关步骤，早期那些正确的澄清会被一起误伤。

比如一段五轮的客服对话，用户因为第 4 轮乱承诺退款，选了另一条轨迹。整段 DPO 会把第 2 轮正确的身份核验话术也一起压下去；回合级更新应该集中在和承诺相关的那一轮。这题最容易栽的两处，一是把整段会话当成一条 completion 做 DPO，二是默认「最后一轮差评就只怪最后一轮」。

## 整段 DPO 为什么会把功过摊匀

会话写成 $H=(x_1,y_1,\ldots,x_T,y_T)$。如果损失对 $\log\pi_\theta(y_{1:T}\mid x)$ 整段 backpropagation，每个 token 拿到的都是同一个标量偏好间隔，第 2 轮正确的核验和第 4 轮的乱承诺被同一个符号更新。这和单轮里「序列级 advantage 把关键 token 抹平」是同一类问题，粒度错了，优化器再好也只会把功过摊匀。`pt-cispo` 关心的是 clip 别丢掉 token 梯度，这题在更上游，问的是优势本身有没有分到该负责的回合。不加 mask 的多轮 DPO，默认就是在误伤。

终局标签对中间回合还有偏置。用户中途改需求、插进来纠正、或者只在结束时点踩，早期按当时信息做得对的澄清，不该被后来才出现的约束追溯惩罚。两条轨迹前缀相同、只在分叉后不同的话，监督就落在分叉之后；对共享前缀做反向更新，只是把方差打到无关的 token 上。工具调用穿插在对话里时更是这样，一次 `search` 参数填错，可能两轮以后才表现成答非所问，所以回合级归因至少要能回溯到那次调用。

## 三种把信用分下去的办法

第一种是回合级偏好，只比较分歧的那一轮及其后续前缀，前面的共享上下文当条件，不更新，或者用很低的学习率保护起来。

第二种是把会话当 MDP，用终局偏好训一个 reward 或偏好模型，再对回合或 token 做 GAE：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t),\qquad
\hat A_t = \sum_{l\ge 0}(\gamma\lambda)^l \delta_{t+l}.
$$

中间步的 $r_t$ 大多是 0，只有终局才有偏好转换来的回报。$\lambda$ 接近 1，终局信号会一路传回很早的澄清，方差很大；$\lambda$ 太小，只打最后一两轮，早期的承诺还是学不到。回合级的 GAE 通常比 token 级稳，因为对话的决策单元是「这一轮说什么、调不调工具」，单个虚词并不是决策。

第三种是让裁判或者 attention 标出关键 span，只对局部做优化。越细越准，但也越贵，还会引入裁判的噪声，`fund-judge` 里讲的 position bias、冗长偏差会变成错误的 span 归因。

实现上对 assistant token 做 mask，共享前缀设 `requires_grad=False` 或者乘零，只让分歧段进 loss。用户改了需求，就把「需求变更」本身写成一个观测，让 $s_t$ 能区分开，不然 value 会把两种任务混成同一个状态。工具轨迹还要分清「选错工具」和「参数填错」，终局失败常常是前者，只更新最后一轮的道歉回答，归因还是错的。

如果只有会话级偏好、没有分叉标注，最低配的做法是用两条轨迹的最长公共前缀切开，只对后缀做 DPO 或 RL，前缀当条件。总之先定监督的粒度和哪些回合要 mask，再谈 DPO 还是 RL 的公式，粒度不对，换个 loss 名字也没用。

## 追问

**最后一轮拿到负反馈，就只更新最后一轮吗？**
不一定。错误可能出在第 1 轮的承诺，也可能是中间选错了工具。要拿两条轨迹或者标出的 span 对照着找，别默认怪到最后一轮头上。

**中间的澄清要保护吗？**
要。共享前缀和正确的澄清要 mask 掉或者降权，免得被终局偏好带偏。

**换成 token-level RL 能解决吗？**
要有正确时间结构的 advantage 才分得了信用。只把 DPO 换成 token-level IS（比如 `pt-cispo`），奖励的时间结构不改，照样摊匀。

**标注太贵怎么办？**
先做分歧回合检测，找到两条轨迹第一次分叉的地方，只标分叉之后的部分，全量 span 标注留给抽检。
