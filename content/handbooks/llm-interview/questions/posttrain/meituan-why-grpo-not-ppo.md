## 真题记录

- 公司：美团
- 团队 / 岗位：北斗；大模型
- 届别 / 流程：原帖未披露
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“为什么在项目中选择 GRPO 而不是 PPO 或 DPO?它解决了什么问题?”**

选 GRPO 是因为项目约束刚好对上它：奖励来自字段校验、代码测试或规则引擎，同一个输入提示能采出有对有错的回答组，显存又不够再训一个和 actor 同规模的价值评估模型（critic）。把这三条说清楚，选型自然就落在 GRPO 上。它解决的是显存和 baseline，理论最优并没有提高。所以这题我会先讲项目约束，再讲省了什么、补了什么、在哪些条件下会失败，答「GRPO 更新所以更好」会被追着问。

先和 PPO 比。PPO 要训 value / critic，和 actor 同步、占显存，长序列上 GAE 还要处理逐步的信用分配。如果奖励是可验证的终点分，比如校验通过、单测通过、规则引擎打分，同一道题多采几个回答就能构成对比：组均值 $\bar r$ 当 baseline，优势 $\hat A_i=(r_i-\bar r)/(\sigma_r+\varepsilon)$。这直接省掉了 critic 的显存，也避开了它和 actor 不同步的问题，这是相对 PPO 的主要理由。没有 learned value 不代表没有信任域，clip 和 KL 还要管一步更新的幅度和相对参考模型的漂移。

PPO 也没有过时。需要逐步价值估计、奖励稀疏又没法成组、或者已经有稳定的奖励模型和 critic 训练设施时，PPO 仍然更合适。开放域里只有连续的 RM 分、组内分数挤成一团时，组均值 baseline 噪声很大，critic 可能更稳。

再和直接偏好优化（DPO）比。DPO 吃离线偏好对 $(y_w,y_l)$，不在线采样，实现轻、迭代快。可字段抽取或推理的示范要是覆盖不全，DPO 只能在已有的 chosen / rejected 之间拉开差距，做不到「模型自己采到奖励更高的路径」。GRPO 用 online 采样补上这一块：verifier 打分，组内相对优势推动探索，示范里没写过的正确写法也能被强化。

DPO 也有它该用的场合。没有成对标注、也不想维护 rollout 和 verifier 时，DPO 就是对的选择。把 DPO 说成「弱于 GRPO」会失分，两者监督的对象不同，一个吃比较，一个吃可验证的标量。静态偏好对已经覆盖了产品要的权衡（语气、安全、长度）时，上 DPO 比硬造一个 checker 更诚实。

最后要主动讲 GRPO 的失败。组内全对或全错时方差为零，优势全是 $0$，这一步没有方向。难题上策略几乎采不到对的，会长期空转，要靠冷启动、降难度或动态采样，再降学习率没用。钻奖励规则的空子，比如套格式骗校验、刷长度，GRPO 比带 critic 的 PPO 更依赖 verifier 的质量，因为没有价值函数帮它平滑噪声。所以结论是：它解决了显存和 baseline，但稳定性更依赖验证器是否可靠、组内回答是否够多样。

## 追问

**它到底解决了什么？**
显存和 baseline：用同一道题的多个样本代替 learned value，理论最优没变。省下的是 critic 的卡和同步开销，数据一条也没省。

**组大小怎么选？**
太小，全同组多、方差大；太大，生成贵、样本之间相关。按有效组比例和难度做 sweep，别背一个魔法数。有效组太少时先改采样，再改 $G$。

**有 RM 还能用 GRPO 吗？**
能，但 RM 的漂移会被组标准化放大。可验证的 oracle 优先；用连续分的话，先校准、再看长度偏置。

**一开始 reward 大幅震荡怎么办？**
先查奖励尺度、空组比例和 KL，别急着换 PPO。秋招二面常会这样追问。奖励尺度跳变、有效组比例低、KL 突然关掉，都会表现成震荡。排查顺序是有效组、奖励分数直方图、KL / 熵，再谈换算法。能稳定复现的震荡才算算法问题，更多时候是奖励和组统计的问题，可以和震荡排查卡一起准备。
