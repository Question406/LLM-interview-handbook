- 届别 / 流程：实习；一面
- 面试时间：原帖未披露；帖子发布于 2026-02-12
- 来源类型与可信度：牛客候选人原帖，B（公司、实习性质、轮次与发帖时间明确，届别和面试日期未披露）
- 原始措辞：**“为什么还要多模型做微调 数据量是多少”**

多模型微调要先说清楚每个模型解决哪个瓶颈：路由、级联、教师生成、领域专用、蒸馏，还是做对照实验。数据量我报去重后的有效 token 数、任务覆盖和质量，不报样本条数。没有单模型基线和成本质量曲线，多模型只是维护负担，算不上体系。

面试官想听的是机制：为什么一个模型不够，第二个模型具体降了哪些成本或延迟，补上了哪些少见任务或领域能力。答成「多训几次更稳」，或者甩一个「几十万条」当数据规模，都说明不了这些。

常见的用法有四种，每种对一个瓶颈。按领域或语言路由，是为了不让通用 SFT 削弱领域专长：正向 KL 会学习数据里所有示范模式，见 `fund-kl-directions`，各领域混在一起，专业模式就不够突出。小模型打头阵、难例再级联给大模型，控的是 p95 和单位成功成本，和「都微调一遍」是两回事。教师生成、学生蒸馏，要看从谁那里采样：从教师分布采样对应正向 KL，倾向覆盖教师的多种输出，也可能突出不了少见模式；从学生分布采样（OPD）对应反向 KL，更偏向挑出高质量模式。不同基座做对照，是用来分清「是数据问题还是容量问题」，对照不是产品形态。

比如一个客服系统，通用问题交给小模型，置信度低的转给大模型，退款纠纷交给领域专用模型。这时统一输入的字段和类型规范（schema）、路由置信度、fallback 和版本兼容缺一项，上线就会出事：用户请求在模型之间丢字段，或者绕过了拒答。后训练要是再接 GRPO，每个专家要有自己的有效组，不能共用一个 $n$，见 `sys-rl-group-n`；路由错了，组采样就是在错误的专家模型上浪费生成预算。

数据规模要报一张白板上写得下的清单：去重后的有效 tokens，任务、语言、难度的覆盖，正负比例，人工和合成的来源，每个模型的样本数和 epoch，有没有和评测集隔离。然后在固定算力预算下，比较单模型、路由、多模型微调三种方案的 holdout success、p95 延迟、单位成本和维护复杂度。小而高质量的窄任务可以胜过大规模噪声，但要有 learning curve 指出饱和或遗忘的拐点，不然「高质量」只是口号。合成数据如果来自同一个教师，多个模型会复制同一个偏差，看着多样，其实是一份分布的拷贝。偏好优化和强化学习阶段另外算：DPO 看 pair 覆盖了哪些失败模式，GRPO 看非零优势组比例，别和 SFT 条数加在一起凑「总样本量」。

## 追问

**没有路由置信度行吗？**
不行。没有阈值、没有 fallback 的级联，会把小模型的错误放大到大模型那里，成本升了，正确率不一定升。

**数据量有行业标准吗？**
没有。以 holdout 的饱和点、遗忘曲线和单位成功成本为准，别背「十万 / 百万条」。

**蒸馏默认用哪个方向？**
教师采样是正向 covering，学生采样是反向 seeking。生成任务乱套正向，句子会变长、变散。

**多模型能省掉 RL 吗？**
不能。路由解决的是谁来答，解决不了可验证奖励上的探索，也提供不了组相对优势。

**每个专家的数据能共享吗？**
清洗流水线可以共享，同一份 SFT 数据别默认共享。混杂的共享数据可能削弱各模型原有的专业能力。
