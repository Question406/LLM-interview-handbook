## 真题记录

- 公司：腾讯
- 团队 / 岗位：大模型算法
- 届别 / 流程：26 届校招；二面（1 小时）
- 面试时间：原帖未披露；帖子发布于 2026-03-23
- 来源类型与可信度：牛客候选人原帖，A（公司、届别、岗位和轮次明确）
- 原始措辞：**“grpo的rollout是多少，为什么不用连续的奖励”**

GRPO 用连续奖励没问题，组内标准化对连续和离散的标量都适用；很多项目选离散奖励，是因为连续奖励模型（RM）更难信得过，跟算法本身的限制无关。至于 rollout 是多少，原帖没说是指固定的 group size 还是这位候选人项目里的配置，所以别编一个唯一的数字，要讲 group size 怎么在差异、成本和方差之间取舍。把「GRPO 不能用连续奖励」说成定理，是常见的失分点。

## group size 怎么定

同一输入提示采 $G$ 条。$G$ 太小，相对优势的方差大，也容易全组同分（全对或全错），有效组就少了。$G$ 太大，生成成本高，要等长尾，样本之间还会相关，温度不够时几条几乎一模一样。所以要按输入提示（prompt）的难度、可用的并行度、奖励方差和有效组比例去做 sweep，汇报时带上有效组的比例，光报一个 $G=8$ 不够。

如果「rollout 是多少」问的是每一步的新鲜度，那还要讲 policy 旧到什么程度才更新、是不是 on-policy 重采样。group size 和 freshness 是两件事，别用一个数字糊过去。

## 连续奖励照样能用

组内标准化之后，连续的 $r$ 照样得到 $\hat A_i=(r_i-\bar r)/(\sigma_r+\varepsilon)$。数学题的部分分、长度惩罚、RM 分数都能代进这个公式，GRPO 没有「只收 0/1」的限制。离散 oracle 受欢迎，是因为它可审计、尺度稳定，也更难被空话劫持。

取舍主要看奖励可不可信。数学或 API outcome 这类任务，优先用离散、可审计的 oracle。连续 RM 能表达细粒度的偏好，但要盯 calibration、漂移、长度偏置，还有钻奖励规则空子的行为：分数一漂，组标准化会把噪声放大成方向；越长分越高，模型就会灌水。比如用 RM 给回答打 0 到 1 的分，一旦它偏爱长回答，同组里最长的那条总拿正优势，训着训着回答就越来越长。两种也可以混用，可验证的部分用离散，风格部分用校准过的连续分，分别监控。所以「不用连续」应该讲成项目上的选择（RM 不可信），它不是 GRPO 的定义。

## 追问

**有没有标准的 $G$？**
没有。看有效组比例和成本，常见是从 4-16 开始扫，但别背成唯一答案。

**连续 RM 怎样才敢用？**
先校准，看长度偏置，留一份冻结的评测做对照；一旦漂移就退回 oracle。

**全用连续分、没有验证器（verifier）行不行？**
能跑，但这就更像 RM-RLHF 了，hack 风险也回到 PPO 那一套。

**怎么和「为什么选 GRPO」接上？**
主要原因是有可验证的标量、能成组采样。奖励连续还是离散是奖励设计的问题，算不上算法门槛。
