## 真题记录

- 公司：美团
- 团队 / 岗位：大模型算法；二面
- 届别 / 流程：原帖未披露；二面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“模型开启/关闭Thinking推理机制，对微调训练效果的影响”**

Thinking 会改训练分布本身，不是免费能力开关。开着时，监督微调（SFT） 目标里多了一大段中间 token，模型被示范「先算再答」；关着时，只拟合最终答案或结构化字段。别答「开了一定更强」。我会讲：监督写进了什么、线上会不会按同一模板解码、以及长度归一后业务是否真的更好。训推开关不一致，比「会不会推理」更先翻车：训练带 think 标签、评测截断、线上关标签，分数掉得比能力掉得更狠。先统一训练和部署的开关与截断规则，再比较开关对效果的影响。

## 开启：把很长的推理过程写进分布

开启 Thinking 时，示范通常带内部独白再给答案。难推理、多步工具规划、需要草稿纸的算术往往受益：中间步骤成为被监督的对象，而不是让模型直接背结论。同一题换数字时，有 think 段的模型更可能重算而不是复述训练集里的答案。这是开 Thinking 的正收益，也是很多人只报 raw acc 上涨的原因。

代价同样写进分布。序列变长，有效监督被稀释：同样 token 预算下，业务字段、最终答案见到的次数变少。模型容易模仿冗长套话和「看起来像推理」的格式刷分，步骤写得很完整，答案却不对，或步骤与答案对不上。评测若只看最终数字且允许任意长 think，长度和套话会变成免费资源。若评测或线上关 Thinking、截断 think 段、或换一套不带标签的模板，就会出现训推不一致：模型仍按很长的推理过程预算生成，或突然丢掉 think 后答案格式崩掉。

工程上要同时盯最终正确率、平均 think 长度、格式合法率，以及「关掉 think 后的回退质量」。只报开 Thinking 的正确率，等于把长度和模板当免费资源。可验证的 think 段（步骤能对上答案或工具轨迹）才值得高权；空话、固定开场白应降权或从示范里清掉。

## 关闭：更稳，但会丢掉中间计算

关闭 Thinking 时，SFT 只拟合最终答案或结构化字段。训练更稳、延迟和成本更低，适合字段抽取、短问答、强格式客服、要可解析 JSON 的槽位填充。没有中间 token，mask 更干净，过拟合套话的空间也更小。短板是需要草稿纸的题会变成背答案：训练集里见过的数字能对，换个数就不会。泛化差是因为目标里根本没有中间计算的监督，不是「没开 CoT 开关」。

这类任务不要硬塞 think 标签充长度。空 think 或固定套话会占掉有效 token，还可能把格式学歪：模型先输出一段无关独白，再把字段写错。关闭时也要保证训练、评测、线上同一套「无 think」模板，避免有人在评测时偷偷打开思考模式来刷分。

## 分组统计与训推对齐

落地按任务分组统计，而不是全局一个开关。推理、规划、多步工具调用带可验证的 think 段；抽取、闲聊、强 字段和类型规范（schema） 输出关闭。用显式标签或两套模板，保证训练、评测、线上同一开关、同一截断规则、同一停止符。评估同时看最终正确率、平均 think 长度、格式合法率，以及关 Thinking 后的回退。结论要落到「长度归一后的业务成功」，不要把「开 Thinking 分更高」当成无条件结论。

两套权重可以，但维护成本高。更常见是同一权重、两套模板，用路由决定是否带 think。路由错了，等于把关闭桶的数据用开启模板训，或反过来，都会把分布搅乱。分组统计实验要报两边 holdout，而不是只报开启桶的满分。

## 追问

- **线上关、训练开，会怎样？** 分布错位：模型仍按很长的推理过程预算生成，或突然丢 think 段导致答案格式崩。先对齐开关再谈能力。评测也必须用线上同一开关，否则你在优化一个不会上线的模式。
- **think 段要不要算 损失（loss）？** 要算才学得会推理；但要想清楚噪声步骤会不会被一起拟合。可验证步骤优先，空话降权或从数据里删。只对答案算 loss、think 当条件，等于没示范中间计算。
- **能不能两套模型？** 可以，但维护成本高。更常见是同一权重、两套模板，用路由决定是否带 think。路由规则要写进评测，避免线下乱切。
- **如何防格式刷分？** 看长度归一成功率和关 think 回退，抽查步骤是否与答案一致，不要只看带 think 的 raw acc。步骤很长但答案错，应按失败而不是「会推理」。
