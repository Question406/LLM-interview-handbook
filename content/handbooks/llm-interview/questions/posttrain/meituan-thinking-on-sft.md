## 真题记录

- 公司：美团
- 团队 / 岗位：大模型算法；二面
- 届别 / 流程：原帖未披露；二面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“模型开启/关闭Thinking推理机制，对微调训练效果的影响”**

Thinking 开关改的是训练分布本身，它算不上一个免费的能力开关。开着时，监督微调（SFT）的目标里多了一大段中间 token，模型被示范「先算再答」；关着时，只拟合最终答案或结构化字段。所以我不会答「开了一定更强」，我会讲三件事：监督里写进了什么、线上会不会按同一个模板解码、长度归一之后业务是不是真的更好。

最先翻车的往往是训推开关不一致，排在「会不会推理」前面。比如训练时带 think 标签，评测时把 think 截断，线上又把标签关掉，分数掉得比能力掉得还狠。所以先把训练和部署的开关、截断规则统一，再去比较开关对效果的影响。

先说开启。示范通常是一段内部独白再给答案。难推理、多步工具规划、需要草稿纸的算术往往受益，因为中间步骤成了被监督的对象，模型用不着直接背结论。同一道题换个数字，有 think 段的模型更可能重新算一遍，复述训练集答案的可能小一些。这是开 Thinking 的正收益，也是很多人只报 raw acc 上涨的原因。

代价也一起写进了分布。序列变长，有效监督被稀释：同样的 token 预算下，业务字段和最终答案被看到的次数变少了。模型容易模仿冗长套话和「看起来像推理」的格式来刷分，步骤写得很完整，答案却不对，或者步骤和答案对不上。评测要是只看最终数字、又允许任意长的 think，长度和套话就成了免费资源。而线上一旦关掉 Thinking、截断 think 段，或者换一套不带标签的模板，就会训推不一致：模型还按长推理过程的预算去生成，或者 think 段突然没了，答案格式直接崩。

所以工程上要同时盯最终正确率、平均 think 长度、格式合法率，以及关掉 think 以后的回退质量。只报开 Thinking 的正确率，等于把长度和模板当成了免费资源。能验证的 think 段（步骤对得上答案或工具轨迹）才值得给高权重，空话和固定开场白要降权，或者直接从示范里清掉。

再说关闭。SFT 只拟合最终答案或结构化字段，训练更稳，延迟和成本更低，适合字段抽取、短问答、强格式客服、要输出可解析 JSON 的槽位填充。没有中间 token，mask 更干净，过拟合套话的空间也小。短板是需要草稿纸的题会变成背答案：训练集里见过的数字能对，换个数就不会。泛化差的原因是目标里根本没有中间计算的监督，跟有没有打开 CoT 开关关系不大。

这类任务别硬塞 think 标签去凑长度。空 think 或固定套话会占掉有效 token，还可能把格式学歪：模型先吐一段无关的独白，再把字段写错。关闭时也要保证训练、评测、线上是同一套「无 think」模板，防止有人在评测时偷偷打开思考模式刷分。

落地时按任务分组，别全局一个开关。推理、规划、多步工具调用带可验证的 think 段；抽取、闲聊、强字段和类型规范（schema）的输出就关掉。用显式标签或者两套模板，保证训练、评测、线上是同一个开关、同一套截断规则、同一个停止符。分组实验要报两边的 holdout，别只报开启那一桶的满分，结论落到「长度归一后的业务成功」上。

## 追问

**线上关、训练开，会怎样？**
分布错位。模型还按长推理过程的预算生成，或者 think 段突然没了导致答案格式崩。先对齐开关再谈能力；评测也必须用线上的同一个开关，否则你优化的是一个不会上线的模式。

**think 段要不要算损失（loss）？**
要算，才学得会推理，但要想清楚噪声步骤会不会被一起拟合。可验证的步骤优先，空话降权或者从数据里删掉。只对答案算 loss、把 think 当条件，就等于没示范中间计算。

**能不能做两套模型？**
可以，但维护成本高。更常见的是同一套权重、两套模板，用路由决定带不带 think。路由要是错了，就是拿关闭桶的数据套开启模板去训，或者反过来，分布都会被搅乱，所以路由规则要写进评测，避免线下乱切。

**怎么防格式刷分？**
看长度归一后的成功率和关掉 think 后的回退，抽查步骤和答案是否一致，别只看带 think 的 raw acc。步骤很长但答案错，就按失败算，不能算「会推理」。
