- 原始措辞：**“如何做一套简单可执行的离线评测集？如何覆盖不同语言与类目？”**

「可执行」意味着每条样本有自动判定：精确匹配、schema 校验、引用是否落在给定商品字段、或脚本化 oracle。纯人工观感集可以当校准层，不能当日常回归的唯一门禁。覆盖看分层召回，不是被头部类目拉高的总分。更新时防泄漏（`data-contamination`），并保留新鲜业务 slice，避免调参集洗成训练材料。二面「不同语言与类目」不是把翻译题堆进去，而是每层有最小样本和独立通过率，空层就是下周的采集任务。

## 先契约，再分层抽样

从线上日志与业务表抽 query，按语言（中文 / 英文 / 东南亚等）、类目、价格带、意图和风险分桶；每桶保证最小样本，并显式加入长尾与对抗例（错别字、混语言、灰产）。标签与输入必须时间切分，且和训练集做 lexical / semantic 去重（`pdd-sft-template-dedup`）。多模态任务还要带图文金标，断言能自动落地（`pdd-multimodal-consistency`）。

简单可执行优先于「看起来很大」：先约一千条带 oracle 的分层集，再扩人工抽检。未知类目 / 未知语言要有降级行为标签（拒答、转人工、只检索不编造），否则覆盖表是假的。

## 覆盖率与版本怎么报

覆盖率用分层指标：每语言 $\times$ 类目的成功、校准和安全违规。报告还应包含未知桶的降级是否触发。集合版本化：`eval_version → 抽样规则 → 与 train 重叠表`。新增类目用独立 slice，不并进旧总分里洗历史。对照实验：只报总分 vs 分层最低桶；只总分过门、最低语言/类目崩，是失败门禁。离线赢、线上不动时，按 `data-offline-online-metric-gap` 查代理是否编码了成交/客诉，而不是先加同类好看题。

「简单可执行」在面试里可以落成一张表：列是语言 × 类目，格内是样本量、oracle 类型、当前通过率。空格就是覆盖缺口，下周补样，而不是先把已有格刷到满分。对抗例单独一列，避免被正常 query 平均掉。抽样要从日志按意图分层，不要从训练集再切 10% 当评测——那是最常见的假覆盖。二面收口：先契约和 oracle，再分层最小样本，再版本和泄漏表；平均分不是覆盖。

## 追问

- **为什么不要先做很大的人工集？** 日常回归需要 oracle；人工观感慢且漂。先小而可执行，再抽检校准。
- **覆盖是不是条数够就行？** 不是。看每层最小样本和最低桶指标，头部类目堆量假覆盖。
- **怎么证明没泄漏？** 与 train 的 n-gram / 语义近邻表 + 时间切分；说「随机切」不够。
- **新语言怎么加？** 独立 slice、单独过门，不并进旧总分；先保证降级行为，再谈该语言的成功率。
