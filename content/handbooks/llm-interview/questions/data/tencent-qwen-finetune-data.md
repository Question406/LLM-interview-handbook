## 真题记录

- 公司：腾讯 · 混元
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“Qwen 微调的数据怎么构造、怎么清洗、怎么配比？”**

我会先定目标行为，再按行为分桶造数据、按固定顺序清洗、用小规模实验扫配比，评判标准是目标任务涨的同时通用能力不塌。把爬来的对话原样拿去做监督微调（SFT），或者拍脑袋定一个 $1:1$，都是这题的减分答法。还有一种情况要先排除：模型已经对齐得很好、只差检索的任务，先试检索增强生成（RAG），再判断要不要 SFT。整条流水线的骨架见 `data-sft-pipeline`。

举个例子，做一个企业内部工具助手，目标行为是查工单、改配置、拒绝越权。数据分四个桶：指令遵循、拒绝 / 安全、工具轨迹、领域知识。构造路径是人写种子、模型扩写、人工抽检，比如人写约两百条种子，扩写后抽检。工具调用必须带真实的字段和类型规范（schema）和可执行轨迹，失败案例标成「应改参 / 应拒」，别假装成功。安全桶要有拒答，也要有可拒可不拒的边界，免得模型要么全拒、要么全答。

Qwen 基座有几点要专门考虑。Qwen 系列本身的指令和工具格式就比较强，微调是在改行为，不用从零教 chat，所以通用指令桶不能太小，否则容易把基座的拒绝和格式洗掉；领域桶也别只堆 FAQ 短答，否则长工具轨迹学不到。Chat template、tool XML / JSON 模式要和部署一致，训练用一份、推理用另一份，表现出来就是「数据没问题、上线全是格式错」。Qwen 的 tokenizer 对中英混合和代码比较稳，但明显的乱码、语言 ident 失败和超长粘贴日志照样要丢掉。

清洗顺序我建议这样：许可与 PII，近重复，评测泄漏，模板套话，长度，最后人工抽检。泄漏查的是评测题面 n-gram 和答案指纹（`data-contamination`），「我们没用过这个榜所以没事」不算检查。模板套话见 `pdd-sft-template-dedup`，「好的，作为 AI…」这类开场会让模型学到没有信息量的套话，交叉熵损失（CE）很好看、产品观感很差，所以要单独抽检「套话率」。合成扩写之后必须做语义去重，否则两百条种子可能扩成同一道题的大量表面改写，CE 下降、能力不升。

配比先给一个可复现的起点，比如领域 : 通用 : 安全 $=4:5:1$，然后小规模扫，看工单任务涨了没有、通用指令和拒答掉没掉。来源级配额的思路同 `kuaishou-sft-source-mix`，难易配比见 `meituan-easy-hard-sft-balance`。一次只改一类比例，锚点集（通用指令、安全）每次都要同时报，只看领域 holdout 会过拟合，把基座洗掉（`meituan-sft-overfit`）。只允许改一维的话，先动领域占比，再动安全，最后动合成温度。每次 run 写明 `domain:general:safety`、数据版本和冻结的评测哈希，配比实验期间评测集冻结，别边改数据边改题。目标任务涨 $2$ 个点、通用掉 $3$ 个点，不算成功。

SFT 和后面的 RL 要分开。被追问「和 RL 数据有什么不同」时我会说：SFT 示范正确轨迹，强化学习（RL）要可打分的难例和组内方差，两者别混成同一份 jsonl。SFT 之后还要接基于人类反馈的强化学习（RLHF）或 GRPO 的话，这份 jsonl 不要直接当 RL 的输入提示（prompt）池，要另外筛可验证的难例，原因见 `tencent-hunyuan-why-sft-then-rlhf`。Qwen 微调最常见的失败，就是把爬虫客服对话当金标：套话多、工具 schema 是假的、拒答口径和产品不一致。种子少、抽检严、配比可复现，比堆十万条没清洗的对话更像能上线的方案。

## 追问

**为什么不直接用爬来的对话？**
没有 schema、没有拒答口径，还常带 PII 和评测泄漏，交叉熵训练会让模型模仿这些噪声。爬虫数据最多当种子，验证过后再进训练集。

**$4:5:1$ 是标准吗？**
只是可复现的起点，要用 holdout 去调。最终比例由边际增益决定，没有行业常数。

**只差检索的话还要不要 SFT？**
先上 RAG 或改写。SFT 解决的是行为和格式，补知识库靠它不合适；知识会过时，检索不会把过时的内容写进权重。

**工具调用失败的轨迹怎么标？**
标成「应改参 / 应拒 / 应换工具」，别标成成功示范，否则 SFT 会教模型撒谎。

**怎么证明没把基座洗掉？**
通用指令和拒答集每次扫都要带上，只报领域任务的实验无效。
