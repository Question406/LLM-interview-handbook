## 真题记录

- 公司：腾讯 · 混元
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“Qwen 微调的数据怎么构造、怎么清洗、怎么配比？”**

错法：把爬来的对话原样当 SFT，或拍脑袋 $1:1$ 配比。先定目标行为（领域问答、工具调用、拒答口径），再采数据；已经对齐得很好、只差检索的任务，先 RAG 不要先 SFT。流水线骨架见 `data-sft-pipeline`；SFT 之后为何接 RLHF 见 `tencent-hunyuan-why-sft-then-rlhf`。SFT 与 RL 不要混成同一份 jsonl。

## 构造与清洗

桶：指令遵循、拒绝 / 安全、工具轨迹、领域知识。构造路径：人写种子 → 模型扩写 → 人工抽检。工具调用必须带真实 schema 与可执行轨迹；失败案例标成「应改参 / 应拒」，不要假装成功。清洗：近重复、语言 ident、PII、评测 n-gram 泄漏（`data-contamination`）、过短 / 过长、模板套话（`pdd-sft-template-dedup`）。「好的，作为 AI…」类开场会让模型学会水。

适用条件是把基座（Qwen）改成某个产品行为。例子：企业内部工具助手。人写约两百条种子（查工单、改配置、拒绝越权），扩写后抽检；配比先给可复现起点如领域 : 通用 : 安全 $=4:5:1$，小规模扫看工单任务升、通用指令和拒答是否掉点。来源级配额思路同 `kuaishou-sft-source-mix`，难易配比见 `meituan-easy-hard-sft-balance`。

## 配比扫什么、防什么

小规模扫的目标：目标任务升的同时通用能力不塌。只看领域 holdout 会过拟合把基座洗掉（`meituan-sft-overfit`）。一次改一类比例，锚点集（通用指令、安全）必须同时报。评测题泄漏会让你以为涨了；模板水会让 CE 降、产品观感变差。

追问「和 RL 数据有何不同」：SFT 要示范正确轨迹；RL 要可打分的难例和组内方差。配比实验冻结评测集，避免边改数据边改题。

## 针对 Qwen 基座的额外注意

Qwen 系列自带较强的指令与工具格式，微调是在改行为，不是从零教 chat。因此通用指令桶不能太小，否则容易把基座的拒绝与格式洗掉；领域桶也不能只堆 FAQ 短答，否则长工具轨迹学不到。Chat template、tool XML / JSON 模式必须与部署一致，训练用一份、推理用另一份会表现为「数据没问题、上线全是格式错」。Qwen 的 tokenizer 对中英混合和代码较稳，但仍要丢掉明显乱码、语言 ident 失败和超长粘贴日志。

清洗顺序建议：许可与 PII → 近重复 → 评测泄漏 → 模板套话 → 长度 → 人工抽检。泄漏查的是评测题面 n-gram 和答案指纹，不是「我们没用过这个榜所以没事」。合成扩写后必须语义去重，否则种子两百条会变成同一题的一万次换皮，CE 下降、能力不升。安全桶要含拒答与可拒可不拒的边界，避免模型要么全拒要么全答。

配比扫的记录方式：每次 run 写明 `domain:general:safety`、数据版本、冻结评测哈希。目标任务升 $2$ 个点、通用掉 $3$ 个点，不算成功。若只允许改一维，先动领域占比，再动安全，最后动合成温度。SFT 做完若还要 RLHF / GRPO，这份 jsonl 不要直接当 RL prompt 池，应另筛可验证难例（`tencent-hunyuan-why-sft-then-rlhf`）。Qwen 微调最常见的失败是把爬虫客服对话当金标：套话多、工具 schema 假、拒答口径与产品不一致。种子少、抽检严、配比可复现，比堆十万条未清洗对话更像能上线的方案。模板水会让 CE 很好看、产品观感很差，必须单独设「套话率」抽检。

## 追问

- **为什么不直接用爬虫对话？** 无 schema、无拒答口径、常含 PII 与泄漏，CE 会模仿噪声。爬虫最多当种子，过门再进 train。
- **$4:5:1$ 是标准吗？** 只是可复现起点，用 holdout 调；最终比例由边际增益决定，不是行业常数。
- **只差检索要不要 SFT？** 先 RAG / 改写；SFT 解决的是行为与格式，不是补知识库。知识会过时，检索不会把过时写进权重。
- **工具失败轨迹怎么标？** 标「应改参 / 应拒 / 应换工具」，不要标成成功示范，否则 SFT 学会撒谎。
- **如何证明没洗掉基座？** 通用指令与拒答集必须进每次扫；只报领域任务的实验无效。
