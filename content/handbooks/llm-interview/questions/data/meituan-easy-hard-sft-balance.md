## 真题记录

- 公司：美团
- 团队 / 岗位：大模型算法；二面
- 届别 / 流程：原帖未披露；二面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“SFT训练过程中，如何平衡简单任务与复杂任务的训练权重？”**

二面这题不要答「多加点难例」。简单任务条数通常远多于复杂推理 / 多工具轨迹，均匀按条采样会让梯度被短 JSON 占满；反过来把难例抄很多遍，又会过拟合那几十条。应先定义难度（步数、工具数、人工失败率、约束冲突数），再按任务桶分配有效 token，并用分层 holdout 看头部短任务有没有被牺牲。美团订单/到店助手里，短 JSON 是头部流量，长工具链是长尾高价值；平衡是两头都有红线，不是道德上照顾难题。定义不稳定，下周权重就不可复现，面试官会追「难度标签谁打的」。

## 分桶加权，别按条均匀

难例提高采样温度或有限重复，但仍保留一定比例的短格式样本当锚。字段抽取、拒答、标准 JSON 这些头部流量 offline 好看、线上掉了会很痛。loss 按长度归一，避免长 CoT 天然权重大。可用课程：先格式与必填字段，再冲突约束和长链推理。配比和过拟合防护（`meituan-sft-overfit`）必须一起做，否则加重难例只会背题。来源配比（`kuaishou-sft-source-mix`）是另一条轴，两轴都要有配额，不要只拧难度。

业务价值也要进权重：高客诉、高改写率的难桶优先；「难但低频」的竞赛式推理不要占满美团主路径。质量不过门的难例不加权重，先回流标注（`meituan-label-quality`）。

## 验收实验

对照：均匀采样、按难度升温、课程、长度归一。报告简单桶、困难桶、格式合法率、以及线上头部短查询延迟。简单桶掉、困难桶升，是失败配比，不是「模型更聪明」。不要把「多加点难例」当成唯一旋钮。先定义难度，再调权重，再看遗忘。Thinking 开着时更要防长链套话占满，难例权重上去之前先做模板去重。

美团场景里「简单」往往是高频短单：改地址、查券、填必填字段。这些条数多、loss 小，但线上占比大。平衡不是道德上照顾难例，而是让难例拿到足够梯度的同时，头部短单的格式和时延不掉。课程可以按天或按 step 提高难桶温度，而不是一上来 50% 长轨迹。若 holdout 显示简单桶格式合法率先掉，立刻把锚点配额加回去，再查是不是长 CoT 没做长度归一。二面我会补一句：难度有定义、权重有 ablation、简单桶有红线，三样齐才叫平衡。

## 追问

- **难度怎么定义？** 用步数、工具数、约束冲突、人工失败率分桶，不凭语感。定义不稳，权重不可复现。
- **难例是不是越多越好？** 不是。升采样要有上限，并和去重、早停一起做，否则过拟合那一小撮。
- **简单任务为什么还要留？** 当格式和头部流量锚。全难例会 JSON 崩、短查询变慢、遗忘通用指令。
- **和配比题怎么一起答？** 难度是桶内权重，来源是桶间配额；两张 ablation 表，不要混成一个比例。
