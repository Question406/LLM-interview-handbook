- 原始措辞：**“多模态场景怎么评估：如何检查「图文一致性／不编造信息」？优先加哪些自动化检查？”**

电商多模态幻觉常是「图里没有的颜色 / 件数 / 品牌被写进文案」。评估要把断言拆成可检查单元，别报一个平均 CLIP 分交差。价格、库存、促销必须来自结构化字段，不能看图猜。二面问「优先加哪些自动检查」，先上便宜高召回的规则，LLM-as-judge 放第二层，金标抽检放第三层。拼多多货不对板客诉贵，自动检查的第一优先是可购买属性有没有库/图依据，不是文案好不好读。

## 断言落地，别只看图文相似度

检测框或分割确认物体是否存在；OCR / 属性抽取核对规格；文本实体必须能在检测白名单、OCR 或商品库对上。优先自动检查：

1. 文本实体不在检测 / 类目白名单 → 标可疑；
2. 数量、尺寸与主图 OCR / 规格表冲突；
3. 无商品库依据的促销语、价格、件数拦截；
4. 图文 CLIP / 业务 embedding 低于阈值，只做召回。

编造可购买属性（颜色、件数、材质、是否含赠品）单独统计，不要被平均图文分稀释。切块若把规格表和图注拆开（`pdd-chunk-size-overlap`），一致检查会误杀，先修切块再调阈值。

## 分层评测怎么交差

离线集按类目、语言、是否有促销、是否多图分层（`pdd-offline-eval-coverage`）。对照：只 CLIP、规则三件套、规则+小模型、再加人工高风险审。报告精确率/召回按错误类型切，重点报「无依据可购买属性」。LLM judge 必须用独立于文案生成模型的教师，并抽检校准，避免 `data-teacher-bias`。线上用拦截率与客诉（货不对板）闭环，只刷离线图文分会和 `data-offline-online-metric-gap` 一样翻车。

优先自动检查的排序按「假阳性代价 × 出现频率」：无商品库依据的价格/件数/赠品最先拦，因为会直接导致货不对板；颜色材质次之；纯形容词（「超值」「爆款」）可以后置或走敏感词。自动检查要输出可解释证据（哪个实体、哪段 OCR、哪条库字段冲突），方便人工只审高风险，而不是再看一遍全文。一致性是断言能否落地，不是图文向量近；优先加能自动判真假的规则，CLIP 和 LLM 都是补召回，不是门禁。

## 追问

- **为什么不先上多模态 LLM judge？** 贵、慢、会跟生成模型共谋「文案好看」。先规则拦截高风险编造。
- **CLIP 低是不是一定不一致？** 不是。构图/背景差、多件商品主图都会拉低；CLIP 只召回，冲突以 OCR/属性为准。
- **价格能从图里读吗？** 主图角标不可靠。价格库存走商品库；图上数字最多当冲突信号，不当金标。
- **多图怎么查？** 按图分别落地断言，再汇总；把所有图拼成一张 embedding 会漏「某张图没有该颜色」。
