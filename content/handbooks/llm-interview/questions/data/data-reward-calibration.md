如果 judge 只用来每对二选一，排序正确率确实就是主指标；可工程里它常被拿去卡筛选阈值、做 best-of-N、给数据加权，或者直接当强化学习（RL）的奖励分数（reward）。这些用法读的是绝对分，「谁更高」排对了，「高多少、这个分代表什么」仍然可能完全错，所以还得看 calibration。

举个例子，RM 给一个回答打 0.9，下游就当它「十次里约九次是对的」，拿来决定拒不拒答，或者直接喂给 PPO 当奖励。如果这个 0.9 实际对应的胜率低得多，排序再准，过滤和训练也会一起跑偏。面试里别停在「再报个 ECE」，要讲清 accuracy 看不见的那类错误是怎么进训练环的。

## 排序对了，尺度不一定对

Rank accuracy 或 pairwise acc 统计的是 $s(y_w)\gt s(y_l)$ 的频率。对 BT 模型来说，这只约束了分数差的符号，既不约束绝对位置，也不约束「0.8 和 0.2 的差是否就是 80% 对 20% 的胜率」。常见的错位有三种：所有分数都挤在高段，best-of-N 基本是在噪声里挑；分数对长度、列表体、礼貌词过度敏感，序是对的，但分差都被风格占满了；不同域的分数不可比，却被拼进同一个 RL 奖励。

Calibration 问的是另一件事：按预测置信度分桶，桶内的预测概率是不是接近真实的偏好频率。Brier 和 log loss 会惩罚「很自信却常错」，所以 accuracy 可以很高、log loss 却很差，这正是「序对了、尺度不可用」。最好讲的是 reliability diagram：横轴预测置信度，纵轴经验频率，点落在对角线上，0.9 才真有九成把握。RewardBench 这类榜单主打 pairwise 能力，分很高也只说明静态 pair 上排序强，代替不了这张图，更代替不了在当前策略样本上画的那张。

BT 把胜率写成 $\sigma(s_w-s_l)$，对校准的要求是「分差对应真实胜率」，并不要求每个绝对分单独有物理含义。可阈值和 RL 用的恰恰是绝对分，或者 batch 标准化后的分。过自信会把 $\sigma$ 推到 0 或 1，要么梯度消失，要么过滤过头。所以 reward 只当 pairwise filter 用的时候，校准可以晚点做；一旦出现「分数 $\gt\tau$ 才入库」或者「$r$ 直接进 PPO」，校准就关系到结果对不对了。

## 分数进了决策环，错的就是动作

做阈值和拒答时，过自信会把好回答过滤掉太多，欠自信会放过坏回答；$\tau$ 选在校准后的概率上还是 raw logit 上，结果可以完全不同。做 best-of-N 和数据加权时，没校准的高分会把采样和重加权锁到同一个风格峰上，放大 length hacking；$N$ 越大，过自信的风格峰越会被系统性地抽到最前面，看起来像「RM 很准」，其实是在放大偏差，RL 再把这个偏差写进策略。做 RL 奖励时，PPO / GRPO 优化的就是分数本身：单调变换会改变优势的相对大小，仿射变换会改变它和 KL 项的相对权重。奖励模型（RM）没校准、又碰上和训练数据明显不同的分布外数据（OOD），给的奖励就可能靠不住。

所以「RM acc 高，可以上 RL」这个推理不完整，只看 RewardBench 分数就决定上 RL，是这题最常见的跳步。至少要看可靠性图、分桶 ECE 或 Brier，还有在策略分布上的校准，静态评测集上的不够。策略一变，RM 看到的是自己没校准过的区域，acc 数字会骗人。一个实用的检查是：把分数映射成预测胜率，先在 held-out 的人标 pair 上算 log loss，再在当前策略采样出来的 pair 上重测一遍。两次差很多，说明 RM 过拟合了训练分布，没法在所有分布上都当可靠的评价标准。

## 先切片，再决定能不能当 oracle

校准要按长度、语言、领域、格式、是否含列表、是否拒答、对抗样本和 policy 版本切片。全局 ECE 好看的时候，长回答那一组或者新策略那一组可能已经明显失效。高分回答要抽样做人工审计，看的是高分回答是不是真的是我们想要的，排序像不像倒是其次。套话、谄媚、注水经常排序正确但绝对分虚高，这只有人工看才能发现。

后校准（temperature scaling、isotonic）可以修好验证集上的尺度，但校准集必须独立，而且和部署分布相近，换到新域就要重做，旧温度不能当常数用。只用一个全局温度，等于假设所有切片的过自信程度一样，这在 LLM judge 上几乎从来不成立。如果 reward 只在训练分布上可靠，就别把它当没有边界的 RL oracle：要设 KL 护栏、定期人评，再加一条硬规则，proxy 在涨、人评不动就停。Calibration 管的是「分数意味着什么」，OOD 失效要另外从数据和模型上修，见 `pt-reward-ood-failure`。

## 追问

**只做 pairwise 的直接偏好优化（DPO），还要校准吗？**
对间隔本身的要求弱一些，但用 RM 筛 pair、设置信度阈值的时候仍然要。校准差的 RM 会系统性地丢掉某一侧的样本，造成覆盖偏差。绝对分一旦进了门控，校准就省不了。

**Accuracy 很高、ECE 很差，说明什么？**
序是对的，概率不能用。适合做排序展示，不适合做阈值和 RL。优先报 Brier / log loss 和可靠性图，并在当前策略的样本上重测。

**Temperature scaling 够不够？**
不够。它只能修验证分布上的全局过自信，修不了切片失效，也修不了和长度共线的偏差。它是后处理，不代表 RM 训好了，而且校准集必须独立。

**怎么验收一个能用于 RL 的 RM？**
要四样：静态 pairwise acc、分桶校准、当前策略样本上和人评的相关性、对抗和长度切片。缺后两样，就别把 RM 当奖励函数；上了以后，proxy 涨、人评不动就要停。
