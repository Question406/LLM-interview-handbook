离线偏好集常偏「好看 / 长 / 像标注员口味」，线上要的是完成任务、留存、投诉率。分布偏移（用户问题、工具可用性、展示位置）会让离线赢家线上翻车。这不是「A/B 不灵」，是 **代理指标 $\neq$ 效用**。发现 gap 不要立刻往离线集堆同类「好看」题，那会加重代理偏差。这块容易把 A/B 失败归咎于流量不够；先核对离线标签有没有编码线上成功定义，没有则再大的 AUC 也预测不了留存。

## 缺口从哪来

- **标签定义**：离线 win-rate 优化的是 annotator 偏好，不是会话成功。线上目标若没写进标签，离线不可能预知。
- **分布**：评测 prompt 是清洗过的单轮题；线上是多轮、工具失败、含糊意图。
- **偏差**：推荐式展示有位置偏差；对话有反馈延迟和选择性可见（只有抱怨的人才点踩）。
- **延迟与成本**：离线不管 P95 延迟和 token 成本，线上会因为变慢而掉转化。

先问：线上目标有没有进离线标签定义。没有就改标签或加任务成功率，而不是加同一个 AUC。这和 `data-reward-eval-flat` 要分开：那题是 reward 把评测刷平；本题是代理与效用不一致，即使 reward 没坏也会 gap。

## 闭环怎么设计

离线门禁（质量下限）→ 影子流量 / 反事实 OPE（IPS、DR，注意权重截断）→ 小流量 A/B → 守护指标（安全、延迟、成本、投诉）。Gap 分析按意图、长度、设备、是否用工具分层，不要只看全局均值。

OPE 实验要写清：日志策略覆盖了哪些动作、重要性权重是否截断、哪些切片方差爆炸。对话动作空间巨大时，IPS 往往不可靠，应改任务成功率 + 人工抽检，把 OPE 留给有明确展示日志的排序场景。对照实验至少报：离线代理、影子流量预估、线上主指标与守护指标四列；只报离线赢面，算没做完。

影子流量要按「同 query、同位置、同工具可用性」对齐，否则你比较的是流量差异不是策略差异。反馈延迟长的指标（次日留存、售后投诉）不能当周内停实验的唯一依据，应先看即时守护（拒答、幻觉投诉、延迟、成本），再等延迟指标。分层发现「只在工具失败 / 多轮含糊」上掉时，离线集就要补这类轨迹，而不是再堆单轮漂亮回答。最后我会补一句：代理没编码效用，刷 AUC 没有用；先改标签定义，再谈采样和 OPE。

## 追问

- **OPE 在对话上可靠吗？** 动作空间巨大、日志策略覆盖差时 IPS 方差爆炸。对话更依赖人工抽检和任务成功率，OPE 适合有明确展示日志的排序场景。
- **离线全赢、线上全输，先查什么？** 长度 hacking、拒答率、延迟、以及评测集是否泄漏进训练（`data-contamination`）。
- **和 `data-reward-eval-flat`？** 那题是 reward 把评测刷平；本题是离线代理与线上效用不一致，即使 reward 没坏也会 gap。
- **gap 出现后先加离线题吗？** 先核对标签是否编码了线上目标；同分布「好看」题只会把代理刷得更虚。
