## 真题记录

- 公司：小红书
- 团队 / 岗位：Hi lab；日常实习
- 届别 / 流程：一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“是否有评估训练后的收益”**；**“搜索引擎召回的top-k值是固定还是模型选择”**

这块容易报「平均分涨了」或让 Agent 自己决定无限加大 $k$。收益必须是 **对照实验**：同一 prompt、同一检索版本、同一解码，比训练前；分事实、多轮、安全桶；报告胜率置信区间和回归。没有冻结对照集的「感觉更好」不算收益。生成评测操作见 `xiaohongshu-gen-eval`；离线-线上缺口见 `data-offline-online-metric-gap`。原帖也强调落地重于背 DAPO 公式，算法对比见 `xiaohongshu-dapo-vs-grpo`。

## 训练收益怎么报

离线：冻结 golden，分能力桶看胜率，而不是一个总分。补回归集（通用指令、安全）。线上：护栏指标（投诉、人工打回、延迟）与业务采纳；影子流量或小流量，避免把评测集当调参集。覆盖不足会让桶外用户受伤（`pdd-offline-eval-coverage`）。多轮任务成功不能用单轮 CE 代替（`xiaohongshu-multiturn-split`）。

过拟合信号：dev 升、线上投诉升；换同分布新 query 骤降。对照要锁检索索引版本，否则「涨分」可能来自新语料，不是训练。

## top-k：默认固定，动态要有预算

起步固定 $k$，或按 query 类型分档（事实短答小 $k$，调研类大 $k$）。用 Recall@$k$ 与延迟曲线选默认，定义先对齐（`byte-recall-at-5`）。模型动态选 $k$ 只在「证据不足且预算未用尽」时扩召回，必须有上限。不计成本时，Agent 会学会刷上下文：多要文档总能提高「看起来有证据」的 judge 分，却伤延迟与噪声。动态策略要记入轨迹，才能把「多召回」和「真正会答」拆开。

失败模式：训练后只报平均分；$k$ 由模型选却没有 token / 延迟预算；检索改了却把账记在 SFT 上。

## 把收益和检索预算写成同一张实验

训练收益最小可发表结构：冻结 checkpoint A vs B，同一索引、同一 prompt、同一解码；分桶胜率 + 置信区间 + 回归桶 + 延迟 / 安全。平均分涨 $1$ 个点但安全桶掉，或只在标注员常用句式上涨，都算失败。对照必须锁检索版本，否则「涨分」可能来自新笔记入库。线上用影子流量或小流量看采纳与投诉，离线-线上缺口见 `data-offline-online-metric-gap`。算法从 SFT 换 DAPO/GRPO 之前，先保证这套尺子稳，见 `xiaohongshu-dapo-vs-grpo`。

top-k 是上下文预算，不是模型个性。固定 $k$ 或按 query 类型分档，用 Recall@$k$（定义先对齐，`byte-recall-at-5`）对延迟作曲线，选拐点。动态 $k$ 的合法触发是「当前证据不足以支撑断言且延迟预算未用尽」，并设硬上限。实现上把 $k$ 写入轨迹，才能分析「多召回是否真提高任务成功」。不计成本时，Agent 会学会要更多文档来哄 judge，噪声进入生成，幻觉不一定降。调研类 query 可以默认更大档，ID / 精确字段类用小 $k$ 甚至 BM25 直达。

原帖把收益评估和 top-k 放在一起问，就是在考你：后训练的增益不能和检索改动混账，检索超参也不能让政策自己无限加上下文。收益报告里检索版本、prompt 版本、解码参数必须并列写出。动态 $k$ 若上线，还要报扩召回触发率、平均 $k$、延迟 P95 和任务成功率的联合曲线：触发很多但成功率不升，就是在刷上下文。固定分档可以按 query 分类器走，分类错误时宁可偏小 $k$ 再澄清，也不要默认拉满。训练收益的统计要给置信区间，小 golden 上的 $1$ 个点可能是噪声，不能当发版理由。

## 追问

- **收益最小报告长什么样？** 分桶胜率 + 回归 + 延迟 / 安全护栏，相对冻结 checkpoint。没有对照集的主观感受不算。
- **动态 $k$ 何时值得做？** 漏召可测、扩 $k$ 有明确增益且延迟预算允许；否则固定分档更稳。
- **和 DAPO/GRPO 题怎么接？** 先能测收益，再谈算法；测不准时换目标函数没有意义。
- **平均分涨、投诉也涨怎么办？** 先看安全与长尾桶，再查是否过拟合 golden；不要继续加训。
- **$k$ 和切窗谁优先锁？** 两者都进同一配置单（`xiaohongshu-multiturn-split`），一起做训推差分。
