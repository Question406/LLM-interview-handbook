## 真题记录

- 公司：百川智能
- 团队 / 岗位：大模型实习
- 届别 / 流程：实习；一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“如果我不需要对所有的数据都训练，只需要对每一部分有权重的取数据怎么做？”**；追问在线调试

我会在线按权重抽样：各域保留可随机访问的 shard，每一步先按 $p_i$ 抽域、再在域里抽样本，权重写在配置里随时能改。原帖里面试官否掉了「先按比重切一刀」的纯离线答法。离线把文件切死也能加权，但每改一次 $p$ 就要重切，实验慢，同一次 run 里也没法热更新。

比如跑到一半发现代码探针一直不涨，想把代码域的权重调高。在线混合改一下配置就生效；离线切法得停下来重切全库，切完还说不清过滤之后的真实占比是多少。「不训全量」时 shard 一个都没丢，只是被抽到的期望次数按 $p$ 降了下来。

## 怎么抽、记什么

记域 $i$ 的目标概率为 $p_i$（$\sum_i p_i=1$）。每步做多项式抽域，或者用温度 $p_i\propto q_i^{\,1/\tau}$ 把头部大域压一压。另一个等价的办法是给样本损失（loss）乘域权重，但梯度尺度会变，要和全局 lr 一起报。

热更新 $p$ 之后，日志必须记**实际消耗 token 占比** $\hat p_i$，因为过滤、长度、packing 都会让 $\hat p\neq p$。$\hat p$ 跟不上目标的话，先修过滤器，别继续加大目标权重。种子、epoch boundaries、去重状态（Bloom / 已见表）都要能复现，不然分不清效果来自「调了权重」还是「换了遍历顺序」。

## 怎么验证调得对

实验一次只改一个域的 $p$，看这个域的探针有没有涨、general-capability regression data 有没有掉。域级 perplexity 和下游探针一起看，防止某个源被饿死，或者被污染：低质量数据源的 $p$ 很高，探针表现却在下降。

要比较两种做法，就在同一个目标 $p$ 下对比预先按比例切文件和在线多项式抽样，报改一次 $p$ 的周转时间和 $\hat p$ 的跟踪误差。面试里重点讲在线这种：配置热更新，不用重切全库。

## 追问

**为什么面试官否掉离线切一刀？**
改权重要重切，没法在线调，也很难复现过滤后的真实占比。

**loss 加权和抽样等价吗？**
期望上近似，但有效 batch 的组成不一样，数值上要单独调 lr。我更倾向抽样，$\hat p$ 更好控。

**怎么发现某个域被饿死了？**
域级 ppl 不降、探针崩、$\hat p_i\to 0$。先对日志，再改 $p$。
