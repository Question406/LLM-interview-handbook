陷阱是把 MinHash 去重当成治理，或声称「模型已经训完，删语料就等于遗忘」。没有 provenance 就无法响应删除、版权质询和评测泄漏追查（`data-contamination`）。流水线必须在入库时写入：URL / 数据集 ID、采集时间、license、是否含用户私有数据、标注协议版本。评委要听的是定位能力与分级 SLA，不是「我们很重视合规」的口号。

## 入库时写清血统，而不是事后猜

每条可训练样本带不可变 lineage：源站、许可证、同意范围、是否用户日志、工具轨迹 ID。PII 用规则加模型检测，对会话日志、检索片段、agent 工具返回尤要小心——电话、地址、账号会藏在 JSON 字段里，只扫正文会漏。版权侧尊重 robots 与许可文本；书籍、歌词、新闻全文等高压类别默认拒绝，而不是靠「公开网页就可以训」。合成数据还要记教师版本，否则自污染（`data-synthetic-self-contamination`）无法追到第几代。

训练语料治理和推理时 RAG / 记忆中的用户数据是两套生命周期：前者走数据集版本与再训；后者走会话过期、索引删除和访问控制。混成一条「都删了」会在面试里被拆穿。

## 删除要分级，已训模型只能近似遗忘

删除请求按影响面分级：

1. 从可训练语料移除，并阻止进入未来 mix。
2. 从检索索引、缓存、特征库删除，避免推理时又读回来。
3. 已训模型：评估近似遗忘、限制生成，或触发再训。Who's Harry Potter 表明可以用针对性数据让模型在目标语料上「表现得像没见过」，这是工程上的近似，不是密码学保证。面试里要主动说：不能证明参数里比特级擦除，SLA 应写清再训窗口、生成侧拦截和抽检协议。

定位依赖 provenance：没有样本 ID 到 shard / 索引的映射，删除只能整桶重做，成本会把 SLA 撑爆。高压版权类别一旦误入，优先整源下线，而不是逐条人工翻。近似遗忘要同时报目标语料熟悉度下降与锚点保持，例如约束 $L_{\mathrm{anchor}}$ 不升、目标抽取成功率掉到接近未训基线；只报「问哈利波特答不上」却把邻域事实一并抹掉，是伤能力不是遗忘。

## 审计怎么交差

抽一批删除与版权工单，演示：能指出受影响 hash、哪些 checkpoint 吃过、索引是否已清、生成侧是否拦截。对照「只从磁盘删 jsonl、模型照出原文」——那叫没做完。评测泄漏追查也走同一套血统：时间切分加源站黑名单，比事后相似度阈值更硬。面试收口：provenance 是删除与审计的索引；PII / 版权在入库卡死；已训模型只能近似遗忘加拦截，再训才是硬删除。

## 追问

- **去重能不能代替 provenance？** 不能。去重减重复，不回答「这条有没有权利用、能不能删」。没有 lineage，删除只能重训全量。
- **已训模型如何响应 Right to be forgotten？** 先清语料与索引，再评估近似遗忘 / 生成拦截，并给出再训 SLA。不要承诺参数级擦除。
- **训练语料和 RAG 用户数据为何不能同一套流程？** 语料走数据集版本与再训；用户记忆走会话 TTL 与访问控制。混用会把「用户要求删聊天」做成「下周重训基座」。
- **工具轨迹的 PII 怎么漏？** 参数、URL query、截图式 OCR 文本里都有。要对结构化字段单独扫，而不是只扫最终答案。
- **和评测泄漏检测怎么共用？** 同一套源站、时间戳、license 元数据；`data-contamination` 查的是见过评测，本题查的是有没有权用、能不能删。
