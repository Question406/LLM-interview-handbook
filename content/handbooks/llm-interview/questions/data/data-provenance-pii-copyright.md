这题的关键是定位能力：每条样本入库时就带上来源、license、同意范围和处理历史，删除请求来了能查到它在哪些 shard、索引和 checkpoint 里，再按影响面分级处理。已训模型做不到参数级擦除，只能近似遗忘加生成侧拦截，要硬删就得再训，这些都要写进 SLA。说一句「我们很重视合规」，面试官是不会买账的。

举个例子，用户要求删掉自己的数据，团队从磁盘上删了那份 jsonl，结果模型还能把原文吐出来，检索索引里也还留着。这就是没做完。常见的误区有两个：把 MinHash 去重当成治理，或者说「模型已经训完了，删语料就等于遗忘」。

## 入库时记下来源和处理历史

流水线在入库时就要写进 URL / 数据集 ID、采集时间、license、是否含用户私有数据、标注协议版本。没有 provenance，删除、版权质询和评测泄漏追查（`data-contamination`）都响应不了。每条可训练样本都带一条不可变的 lineage：源站、许可证、同意范围、是否来自用户日志、工具轨迹 ID。

PII 用规则加模型来检测，会话日志、检索片段和 agent 工具返回的内容尤其要小心，电话、地址、账号经常藏在 JSON 字段里，只扫正文会漏。版权这边，遵守 robots 和许可文本，书籍、歌词、新闻全文这类高压类别默认拒绝，「公开网页就可以训」过不了这关。合成数据还要记教师版本，不然出了自污染（`data-synthetic-self-contamination`）追不到是第几代。

训练语料的治理和推理时检索增强生成（RAG）或记忆里的用户数据是两套生命周期。语料走数据集版本和再训；用户数据走会话过期、索引删除和访问控制。混成一句「都删了」，在面试里会被拆穿。

## 删除要分级，已训模型只能近似遗忘

我会把删除请求按影响面分三级。第一级，从可训练语料里移除，并且挡住它进入以后的 mix。第二级，从检索索引、缓存、特征库里删掉，免得推理时又被读回来。第三级是已训模型，要么评估近似遗忘，要么限制生成，要么触发再训。Who's Harry Potter 那篇表明，用针对性的数据可以让模型在目标语料上「表现得像没见过」，但这只是工程上的近似，没有密码学意义上的保证。所以面试里要主动说明，参数里的比特级擦除证明不了，SLA 应该写清再训窗口、生成侧拦截和抽检协议。

定位全靠 provenance。没有样本 ID 到 shard 和索引的映射，删除只能整桶重做，成本可能超出 SLA 允许的范围。高压版权类别一旦混进来，优先整源下线，逐条人工翻太慢。近似遗忘的报告要同时看两头：目标语料的熟悉度下降了，regression performance 也得到保留，比如约束 $L_{\mathrm{anchor}}$ 不升，目标抽取成功率掉到接近未训基线。只报「问哈利波特答不上来」，却把周边的事实一起抹掉了，那是伤了能力，算不上遗忘。

验证流程的时候，抽一批删除和版权工单来演示：能指出受影响的 hash、哪些 checkpoint 吃过这些数据、索引有没有清掉、生成侧有没有拦截。评测泄漏追查也用同一套来源记录，时间切分加源站黑名单，比事后卡相似度阈值更可靠。

## 追问

**去重能不能代替 provenance？**
不能。去重只是减少重复，回答不了「这条有没有权利用、能不能删」。没有 lineage，删除就只能全量重训。

**已训模型怎么响应 Right to be forgotten？**
先清语料和索引，再评估近似遗忘或生成拦截，同时给出再训的 SLA。参数级擦除别承诺。

**训练语料和 RAG 用户数据为什么要分两套流程？**
语料走数据集版本和再训，用户记忆走会话 TTL 和访问控制。混在一起，会把「用户要求删聊天记录」做成「下周重训基座」。

**工具轨迹里的 PII 会从哪儿漏？**
参数、URL query、截图 OCR 出来的文本里都有。结构化字段要单独扫，只扫最终答案不够。

**和评测泄漏检测怎么共用？**
共用同一套源站、时间戳、license 元数据。`data-contamination` 查的是模型有没有见过评测，这题查的是有没有权用、能不能删。
