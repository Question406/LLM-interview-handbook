## 真题记录

- 公司：小红书
- 团队 / 岗位：Hi lab 日常实习
- 届别 / 流程：日常实习；一面
- 面试时间：原帖未披露
- 来源类型与可信度：牛客候选人原帖，B
- 原始措辞：**“多轮对话轮数，说明多轮训练数据拆分的 trick 和原因，训推一致吗”**；还问多轮截断与记忆优化

我会把一条会话拆成多个样本，每个样本的标签是某一个助手轮，前面的 user、tool 和历史助手轮只当条件（mask 掉、不算 loss），太长就分窗并保留结构化的状态摘要；训推一致靠一张共用的配置单和差分测试来保证。整段会话当一条样本算 cross entropy loss（CE），模型会去背早期轮，而且会话长短不一，短会话会被淹没；训练从来不截断、线上却滑窗，也是同样的错位。同类的切分思路见 `sensetime-multiturn`。

切点有一条硬规则：工具调用必须 `user → call → result` 成组，不能在 observation 中间切开。observation 是环境给的条件，不是模型该预测的 token，切开了，模型会学到「没看到结果就往下说」，在没看到结果时编造。

会话太长就切窗，原则是保留做决策需要的状态，丢掉闲聊的 token。状态包括用户已经确认的约束、没完成的子目标、最近一次工具结果，以及安全相关的拒答理由；闲聊和重复的致谢优先丢。比如用户开头说过「我对花生过敏」，聊了很多轮之后让模型推荐菜谱，这条约束必须还在，丢了就是安全事故。所以摘要要结构化（键值），别生成一篇散文让模型再去读，散文摘要自己就会丢字段。摘要模型和主模型的定义要一致，记忆摘要的键要和线上读取的键同名，免得训练写 `constraint`、推理读 `用户要求`。记忆的写入和检索见 `byte-short-long-memory`、`agent-memory-retrieval`，把猜测写进长期记忆这类污染要单独防。

轮数本身不是越多越好。训练里出现过的最大轮数要覆盖线上 P95，超长尾靠记忆，别往无限上下文里硬塞。只训最后一轮省算力，但中间轮的助手话术会变弱，线上又要求中间轮也能答；全轮都算 loss，早期轮会被反复看到。这个选择要写进方案，并用多轮任务成功去验证，单轮 CE 说明不了。

训推一致写成一张配置单：chat template 哈希、最大 token、从哪一侧截断、是否保留失败的工具轮、Thinking 开关、工具 schema 版本、检索 top-k。截断超参（最大轮数、token 预算、摘要策略）也在这张单子里，训练脚本和 serving 共用一份。Thinking / 工具 XML 标签的版本必须和线上一致，训练开 Thinking、推理关，等于条件分布整体错位。原帖还问检索 top-k 固定还是由模型选，这也要放进配置单，它改变的是每一轮的上下文分布，和切窗是同一类训推问题，展开见 `xiaohongshu-posttrain-gain`。

验证时把同一段会话分别过一遍训练打包器和线上预处理，比对 token 化之后的 prefix，对不上就当 bug。常见的不一致来自系统提示差异、工具字段和类型规范（schema）里的字段顺序、截断从左还是从右、是否保留失败的工具轮。差分测试要覆盖两类会话：带工具的长会话，查工具对有没有被切开；纯闲聊的短会话，查有没有把致谢当状态留下。Serving 多了一档压缩或者换了 tokenizer，要重跑同一套差分，否则训推一致只在实验室里成立。收益用多轮任务成功来评（中途澄清之后还能不能完成）；单轮 loss 降了、多轮任务成功率却降了，说明切分或截断协议错了。

## 追问

**历史助手轮都要算 loss 吗？**
可以都算，数据利用率高，但早期轮会被重复看到；只训当前轮更贴近线上逐步生成。要在数据量和一致性之间写明选了哪个。

**切窗会不会丢约束？**
会，所以要做结构化记忆，光丢中间句不够。「用户说过过敏」这种约束丢了就是安全事故。

**怎么证明训推一致？**
打包器差分测试加同一个模板哈希。口头说一句「我们用了 chat template」不算证明。

**Thinking 标签不一致会怎样？**
训练有、推理没有，条件分布整体错位，表现为乱插标签或者漏掉推理。
