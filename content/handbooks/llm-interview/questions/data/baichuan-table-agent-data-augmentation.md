- 原始措辞：**“agent 表格数据如何增强的 数据量是多少”**

表格 Agent 的数据我会从真实表结构出发做可执行的增广，每条都让表格引擎重算校验；数据量用去重后的有效任务数和学习曲线来回答，先报一个整数没有意义。

一条有效样本是个可执行的四元组：用户指令、起始工作簿、工具轨迹、能用引擎重算的目标。常见的错法是报个「十万条」，或者同一个模板换几个列名，分别放进训练集和测试集。比如「按地区汇总销售额」把列名「地区」改成「区域」，公式依赖和目标都没变，放进测试集就是泄漏。所以我会先从脱敏真实表里提取字段和类型规范（schema）、公式依赖图和操作分布，再做增广，答案不能写在注释或指令里。

## 增广要能被引擎打回

有效的变换包括列名 / 单位改写、插入空值与异常、日期货币格式、跨 sheet lookup、汇总 / 排序 / 透视、公式修复、多步编辑。每条都由 spreadsheet engine 重算，检查目标单元格、公式范围、合计行、外键这些原本应该保持的约束，过不了验证器（verifier）的合成轨迹直接丢掉。切分按表结构族、操作类型、长度、难度来做，同一个模板禁止同时出现在 train/test。失败轨迹也留一些专门训纠错，但要标成 `repair` 桶，免得污染成功分布。表格任务的过程奖励分数（reward）也必须能被同一个引擎重放，不然增广会变成没法验证的轨迹模仿。

## 规模看学习曲线

我会报去重后的可执行任务数、各类任务覆盖率、验证器通过率，以及有效动作 token 数。扩样往长尾结构族加数据：留出集的任务成功率还在涨、固定评测任务也没退步，就继续加；边际增益 $\lt$ 阈值就停。对照实验每次只开一类增广，比如只加空值，看这一类涨没涨、日期类有没有掉，避免数据条数增加了能力却没提升。

面试里我会把规模说成「先把操作×结构族的格子覆盖满，再沿学习曲线往长尾加」。同一个帖子里的线上指标构造见 `baichuan-online-eval-data`：离线增广解决覆盖，线上事实表解决分母。

## 追问

**数据量到底是多少？**
没有通用数字。用去重后的可执行任务数和覆盖率来回答，再拿出学习曲线。

**换个列名算新样本吗？**
公式依赖和目标都没变的话，放进测试就是泄漏。要按结构指纹去重再切分。

**没有引擎能不能合成？**
不能当正样本用。没有 verifier 的轨迹只进候选，抽检之后再用。
