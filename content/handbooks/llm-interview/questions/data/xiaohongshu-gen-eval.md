## 真题记录

- 公司：小红书
- 团队 / 岗位：大模型算法
- 届别 / 流程：秋招；一面
- 面试时间：原帖未披露；帖子发布于 2025-12-11
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“大模型生成内容的评测方式有哪些，具体如何操作？”**

这块容易只报 BLEU / ROUGE，或把 LLM-as-judge 当金标。开放生成没有唯一参考句，n-gram 重叠既惩罚合理改写，也奖励套话。我会拆维，再加分层 golden，最后和线上闭环。Judge 校准见 `fund-judge`；业务侧成功见 `xiaohongshu-agent-business-eval`；事实题构造见 `xiaohongshu-factoid-data`。同面一致性、幻觉、多智能体是同一棵树：先定义「错」，再谈抑制。

## 拆维与自动指标

任务拆维：事实忠实、指令遵循、安全、多样性、业务成功（收藏 / 不投诉 / 不删改）。自动层只承担可程序化的轴：引用是否落在证据里、毒性与违禁、重复 n-gram、长度异常、格式 schema。有检索时把 retrieval 与 faithfulness 拆开，避免「召回对了但生成胡编」被平均分掩盖（同类拆分见 `ali-rag-eval`）。没有证据的创意内容，自动指标只能做护栏，不能定高下。

覆盖不足时，离线集看起来很好、线上长尾崩，见 `pdd-offline-eval-coverage`。Golden set 按品类、敏感主题、笔记类型分层；提示词迭代时 **冻结评测集**，否则自己刷自己。

## Judge、人工与线上

LLM-as-judge：固定 rubric、固定解码、校准集上报告与人工一致性；定期换校准样本防 judge 漂移。人工：分层抽样，开放创意、口吻、是否「像社区」只在这里定高下。线上：采纳率、投诉、人工打回与影子流量；离线涨、投诉升就是过拟合或奖励黑客。提示词改动与模型改动分开记账，否则说不清是谁的功。

失败模式：用同一批生成去调 prompt 再在同一批上评分；BLEU 优化出模板水；judge 与产品口径不一致却当唯一 KPI。

## 社区生成场景的操作细节

小红书类 Feed 生成还要加「像社区」和「可发布」：是否像笔记口吻、是否空泛鸡汤、是否违规营销。这些几乎无法用 n-gram 自动定高下，必须进人工 rubric，并和业务成功（收藏、不投诉、不审核打回）对齐。自动层仍有用：重复 n-gram 抓套话，毒性与违禁抓安全，引用偏移抓幻觉。操作时固定解码参数，保存完整 prompt + 模型版本 + 检索快照，否则下周无法复现这条分数。

Golden 分层建议：品类（美妆 / 美食 / 攻略）、敏感主题、是否依赖检索、长短文。每层都要有最低样本量，避免平均分被大品类带走。Judge 校准：抽 $200$ 条左右人标，报 Spearman / 一致率，低于约定阈值就停用该 judge 版本。提示词迭代时评测集冻结；模型迭代时提示词也冻结一次，做交叉对照，才能说清涨分来自谁。线上闭环把投诉和人工打回回流成 hard case，进下一轮 SFT / 偏好，而不是只改提示词把仪表刷绿。

同面若问幻觉、一致性、多智能体，先指回这套「错」的定义：无证据断言、自相矛盾、工具结果未落地。没有定义就谈抑制，是空话。社区场景还要把「可发布」写成可抽检条款：违禁、引战、虚假促销、过度医疗承诺。自动毒性模型只能当第一层，误杀和漏杀都要人审切片。Judge 分数与收藏率若长期反向，说明 rubric 没对齐产品，应改口径而不是继续用 judge 选 checkpoint。提示词、检索、模型三者交叉对照：每次只动一个，否则无法归因。Golden 要定期轮换，旧集降为回归，防止全组围着那几百条笔记刷口吻。

## 追问

- **为什么不用 BLEU？** 无唯一参考，且与社区口吻无关；可作重复/抄袭辅助，不能当主指标。
- **Judge 和人工谁说了算？** 人工定义 rubric；judge 是廉价回归器，必须校准。一致率掉了就换 judge 或改 rubric，不要继续刷分。
- **如何防评测过拟合？** 盲测 holdout、定期换 query、线上护栏，见 `xiaohongshu-posttrain-gain`。
- **检索改了分数涨算生成进步吗？** 不算。要锁索引版本，或把 retrieval 与 faithfulness 拆开报。
- **开放创意能不能全自动评？** 不能定高下，只能做安全与重复护栏；高下留给分层人工。
