## 真题记录

- 公司：小红书
- 团队 / 岗位：大模型算法
- 届别 / 流程：秋招；一面
- 面试时间：原帖未披露；帖子发布于 2025-12-11
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“大模型生成内容的评测方式有哪些，具体如何操作？”**

我会把「生成得好不好」拆成几维分别评：能程序化的交给自动指标，开放质量交给人工 rubric，LLM-as-judge 校准之后当便宜的回归器，最后拿线上的采纳和投诉去核对离线结论。只报 BLEU / ROUGE 不行，开放生成没有唯一参考句，n-gram 重叠既惩罚合理的改写，又奖励套话；把 LLM-as-judge 直接当金标也不行。

维度一般拆成事实忠实、指令遵循、安全、多样性、业务成功（收藏 / 不投诉 / 不删改）。小红书这类 Feed 生成还要加两条：「像社区」和「可发布」，也就是像不像笔记口吻、是不是空泛鸡汤、有没有违规营销。比如一篇攻略笔记读着通顺，但满篇「绝绝子、闭眼入」，一条具体信息都没有，BLEU 不一定低，人一看就不合格。这类判断几乎没法用 n-gram 自动定高下，要进人工 rubric，并和业务成功（收藏、不投诉、不审核打回）对齐。「可发布」也要写成能抽检的条款：违禁、引战、虚假促销、过度医疗承诺。

自动层只承担能程序化的轴：引用是否落在证据里（引用偏移抓幻觉）、毒性和违禁、重复 n-gram 抓套话、长度异常、格式是否符合字段和类型规范（schema）。有检索时把 retrieval 和 faithfulness 拆开，免得「召回对了、生成胡编」被平均分盖住（同类拆分见 `ali-rag-eval`）。没有证据的创意内容，自动指标只能当护栏，定不了高下。自动毒性模型也只是第一层，误杀和漏杀都要拿人审切片去看。

Golden set 按品类（美妆 / 美食 / 攻略）、敏感主题、笔记类型、是否依赖检索、长短文分层，每层有最低样本量，免得平均分被大品类带走。覆盖不足时，离线集很好看，线上长尾任务却会明显失效，见 `pdd-offline-eval-coverage`。事实题怎么构造见 `xiaohongshu-factoid-data`。Golden 要定期轮换，旧集降为回归集，防止全组围着那几百条笔记刷口吻。

LLM-as-judge 的用法是固定 rubric、固定解码，在校准集上报和人工的一致性，比如抽 $200$ 条左右人标，报 Spearman 或一致率，低于约定阈值就停用这个 judge 版本，并且定期换校准样本，防止 judge 漂移（`fund-judge`）。人工评分负责开放创意、口吻、像不像社区这些只有人能定高下的地方，分层抽样。judge 分数和收藏率长期反向，说明 rubric 没对齐产品，这时要改口径，别继续拿 judge 选 checkpoint。

操作上还有几条纪律。固定解码参数，保存完整 prompt、模型版本和检索快照，否则下周没法复现这条分数。提示词迭代时冻结评测集，否则就是自己刷自己；模型迭代时也把提示词冻结一次，提示词、检索、模型三者交叉对照，每次只动一个，才说得清涨分来自谁。线上看采纳率、投诉、人工打回和影子流量，离线涨、投诉也涨，就是过拟合或者奖励黑客。投诉和人工打回要回流成 hard case，进入下一轮监督微调（SFT）或偏好训练，光调提示词让仪表上的分数变好没用。业务侧的成功怎么评见 `xiaohongshu-agent-business-eval`。常见的失败有三种：用同一批生成去调整输入提示（prompt），再在同一批上评分；优化 BLEU 优化出一堆模板水；judge 和产品口径不一致，却被当成唯一的 KPI。

同一面如果接着问一致性、幻觉、多智能体，我会先指回这套「错」的定义：无证据的断言、自相矛盾、工具结果没有落地。先定义「错」，再谈怎么抑制，没有定义就谈抑制是空话。

## 追问

**为什么不用 BLEU？**
没有唯一参考答案，也和社区口吻无关。可以当重复或抄袭的辅助信号，当不了主指标。

**Judge 和人工谁说了算？**
人工定义 rubric，judge 是便宜的回归器，必须校准。一致率掉了就换 judge 或者改 rubric，别继续刷分。

**怎么防评测过拟合？**
盲测 holdout、定期换 query、加线上护栏，见 `xiaohongshu-posttrain-gain`。

**检索改了、分数涨了，算生成进步吗？**
不算。要锁住索引版本，或者把 retrieval 和 faithfulness 拆开报。

**开放创意能全自动评吗？**
定不了高下，自动指标只能做安全和重复的护栏，高下留给分层人工。
