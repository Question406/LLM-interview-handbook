## 真题记录

- 公司：快手
- 团队 / 岗位：大模型算法
- 届别 / 流程：26 校招；一面
- 面试时间：原帖未披露；帖子发布于 2025-12-30
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“在 SFT 阶段，你们如何设计不同来源数据（如通用指令、垂域问答、CoT 数据）的配比？依据是什么？”**

配比是优化问题，不是审美。一面若先报「经验上 1:1:1」或「CoT 多一点更好」，评委会追依据。先写清 SFT 要保住的能力：通用指令、垂域事实、推理格式、安全拒答。每类建独立 holdout，训练中看该类升多少、其他类掉多少。依据必须能复述：ablation 表、遗忘曲线和业务 slice。没有这张表，任何比例都只是口味。快手这种内容+搜索场景，还要防止垂域事实源把通用闲聊和安全锚挤掉。遗忘比「垂域分又高了一点」更先暴露线上事故。

## 两层配比：覆盖缺口 × 有效 token

1. **覆盖驱动**：哪一类 holdout 最差、线上错误桶最大，就提高该类有效 token，而不是原始条数。短 FAQ 一万条可能抵不过两百条可验证 CoT。
2. **质量与难度**：高置信人工 / 强 verifier 样本权重大；过长 CoT 和模板改写降权，避免占满梯度。质量门见 `meituan-label-quality`。

通用指令当锚，防止垂域 SFT 后不会聊天；CoT 只给真正需要中间计算的切片，避免所有短问答被拉长。安全与格式样本单独留配额，不跟业务抢。用 temperature mixing 或 curriculum 比一次拍死比例更稳：先格式与通用，再提高垂域和难例温度。这和美团难易配比（`meituan-easy-hard-sft-balance`）是同一套分桶思想，只是轴从难度换成来源。

## 实验怎么交差

对照至少：等比例、按缺口加权、按质量加权、curriculum。每组报各 holdout、遗忘（通用/安全是否掉）、以及平均完成长度。条数涨但某桶 holdout 掉，说明配比在稀释而不是补洞。SFT 管线（`data-sft-pipeline`）的 source-level ablation 就是这张表：$\Delta$ 能力 / $\Delta$ token，而不是「这源看起来更像业务」。过拟合防护（`meituan-sft-overfit`）要一起做，否则提高某源只是在背那一批模板。

快手业务上还要把「看起来像垂域」和「真能答对站内事实」分开：垂域问答若没有可核对的字段或检索依据，加再多也只是在蒸口吻。CoT 源要先过可验证门（计算、代码、规则），再进配比；过不了门的长推理按低质源降权，不要因为「有思维链」就抬温度。比例是结果，不是出发假设。

## 追问

- **为什么不用固定 1:1:1？** 条数不等于有效梯度。短模板会淹没难例；要用 holdout 缺口和 token 效率调。
- **CoT 是不是越多越好？** 不是。只给需要中间计算的切片；全量拉长会伤短问答延迟和格式。
- **垂域加太多会怎样？** 通用指令和安全锚先掉。先看遗忘曲线，再加垂域温度。
- **依据面试官还要什么？** 能画出「加该类 token → 该类升、邻类掉多少」的 ablation，而不是经验比例。
