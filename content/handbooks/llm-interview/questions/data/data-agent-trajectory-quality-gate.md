Agent 轨迹入库前我会设五道门：静态校验、可回放、过程异常、结果可验证、脱敏，失败轨迹再按类型分桶决定怎么用。只存 $\mathrm{reward}\gt 0$ 的轨迹，或者觉得成功率数据越干净越好，都会出问题。

成功的轨迹也可能是脏的。比如一条轨迹最后通过了检查，回头一看，它其实是从环境里读到了评测脚本的标准答案，或者碰上 flaky 环境偶然放行。反过来，失败轨迹整条扔掉，学生模型就学不会恢复。`arl-trajectories` 讲了为什么只用成功轨迹在状态分布上不够，这题是把那套想法落成入库门禁：静态校验、可回放、过程异常、失败分组统计。AgentBench 一类评测已经表明，环境噪声和工具失败是常态，训练数据只留完美演示，线上一走偏就开始空转。

## 成功轨迹先过五道门

第一道是 schema 和权限：工具名、参数类型、是否越权，非法 call 不能当监督微调（SFT）的正样本。第二道是环境一致性：在同一个环境 hash 下重放能复现，过期 API、flaky 通过的要丢掉或重标。第三道看过程异常：反复调同一个工具、没有进展的空转、靠虚高步数刷奖励。第四道要求答案能被独立的 checker 或单元测试核对，停在「看起来像做完了」不算。第五道是脱敏，日志、检索片段、截图 OCR 里的 PII 出库前清掉。

过了这五道，还要看关键证据能不能追溯，没引用到的文件、没真正读到的页面，按泄漏或投机降权。隐藏状态泄漏是 agent 数据特有的坑：轨迹里出现用户看不见的 oracle、内部 ID 或评测脚本的标准答案，模型学会的是「抄环境」，用工具的本事一点没长。所以入库时要把 thought 和观测结果（observation）分开扫，命中隐藏字段就整条拒收。Verifier 过不了的轨迹（`data-verifier`）也别靠人工「感觉对」放行。

合成轨迹还要多查自污染和教师偏差（`data-synthetic-self-contamination`）。教师把答案写进 thought，学生再学会「先看答案再演戏」，整个 agent 池都会被污染。

## 失败轨迹按类型分桶

失败按类型分组：工具 API / 字段和类型规范（schema）错、规划错、感知错、环境超时、权限拒绝。只有可学习的失败才进训练：near-miss 和 recovery 做成正的修复后缀，first-error 当 rejected；回放不了的、纯环境故障进诊断集，不进 SFT。这和 `arl-trajectories` 的切法一致，整条失败轨迹做行为克隆会模仿错误动作。难度标签（步数、工具数、当前 policy 的 pass@$1$）要写进元数据，不然配比没法按错误类型分别统计和调整。

## 门禁效果怎么报

至少报四列：原始成功率、过门后的条数、各失败桶占比、重放一致率。只报「过滤后 win-rate 更高」，可能只是把难例删光了。评测时要主动注入 first-error 看恢复率，只回放教师的成功路径看不出来。门禁是为了留下可学习的信号：成功要能追溯，失败要能切片，空转的长轨迹就算最终成功也该降权，别为了提高过滤后的成功率把难例全删掉。

## 追问

**只存成功轨迹为什么不够？**
部署时走偏一步就进了分布外数据（OOD，即与训练数据明显不同的数据），模型没见过怎么恢复。只用成功轨迹做模仿学习会有 compounding error，详见 `arl-trajectories`。

**成功了但步数很长，怎么处理？**
降权或者当效率负例，免得学到不必要的重复操作。最终结果对不等于过程对。

**合成轨迹要多过哪几道门？**
查教师版本、有没有把答案泄漏进 thought、和真实来源的重叠（自污染），以及去掉教师提示后能不能重放成功。

**失败轨迹能一律当直接偏好优化（DPO）的 rejected 吗？**
不能。环境故障和规划错误的 credit 不一样，先标 first-error，再决定用 prefix、recovery 还是整条丢掉。

**和配比题怎么衔接？**
过了门才有资格进 mix。脏的成功轨迹占满 batch，后面再讲 curriculum 也只是在优化噪声。
