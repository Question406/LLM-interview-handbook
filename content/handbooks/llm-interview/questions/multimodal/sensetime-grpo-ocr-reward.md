## 真题记录

- 公司：商汤
- 岗位：多模态大模型算法实习；一面
- 原始措辞：**“GRPO 奖励怎么设计的”**；相关追问含反思验证、OCR 过拟合、可验证纠错

这块容易直接答成给「输出了反思段落」打分。GRPO 吃的是组内相对奖励，奖励一 hack，整组都在比谁更会写套话。OCR / 反思场景必须让奖励能被规则或二次校验器复现：识别准不准、字段对不对、反思有没有把错改对。一次前向容易在复杂版面自信地错；可验证循环把「改」变成可打分动作。

## 把奖励拆成可复现的项

建议拆成四项，全部能自动算：

1. **最终正确性**：相对金标的字段级精确匹配或归一化编辑距离；金额、证件号用精确匹配，地址可用受控编辑距离。不要只用整页 CER，会掩盖「号码对、姓名错」。
2. **过程 / 反思**：比较反思前后同一字段的对错。仅当「前错后对」给正分；前对后错、前后都错，给 0 或负分。需要结构化输出（字段 JSON），才能自动比对。
3. **负向**：无错误仍大改、引入新错、空反思模板刷步数、编造校验器没看见的「依据」。
4. **结构 / grounding**：关键字段是否落到合理框或单元格（IoU 或单元格 id）；乱报未出现的栏位扣分。

组内相对化之前先把这几项加权成标量。权重要写进配置，便于回归：只优化过程项会奖励「改来改去」。版式 OOD 集做门禁，训练版式满分、换字体 / 光照崩，说明奖励在拟合模板而不是阅读，见 `sensetime-ocr-overfit`。

## 为何必须可验证，以及常见 hacking

若奖励只给「有反思段落」，模型学空洞 CoT：先抄一遍 OCR，再写「我检查过了」，字段不变。GRPO 没有 learned $V$，组越大方差越小，但 hack 的奖励在组内仍然一致升高，分不出真假进步。可验证纠错的最低标准：存在程序能判断「改对了没有」。电话十一位、身份证校验位、价税勾稽、正则日期，都是现成校验器；没有校验器的自由描述字段，不要勉强上过程奖励。奖励 = 字段正确 + 改对才加分 + 乱改 / 空反思扣分；OOD 集决定能不能上线。

权重怎么定要能讲。最终正确性应占大头，过程项是稀疏加成：只有「前错后对」才触发，避免模型为了刷过程分而先故意写错再改对，这是典型 reward hacking，要靠「首次可读就对」的辅助项或对「先错后对」降权来堵。负向项要有上限，免得一条空反思把整组优势打崩。GRPO 组内减均值之后，若一组全在写套话且字段都错，优势全接近 0，看起来「没 hack」，其实没学；所以监控要看字段 F1，不要只看 reward 均值上升。OOD 门禁用和训练同 schema、不同外观的图：换字体 / 光照 / 印章，F1 掉多少写进上线标准。grounding 项（框 IoU）能减轻背模板：位置对了才给满字段分，换版式后框偏会暴露过拟合。

和 CoT 过度设计同一原则：奖励不买文风。反思段落可以很短，甚至只是结构化 `before/after` 字段。商汤若追「为什么要反思」，答：一次前向在复杂版面容易自信地错；把第二次阅读变成可打分动作，而不是多生成形容词。

## 追问

- **没有金标的线上流量？** 只用校验器当弱奖励，金标集离线标定权重；不要用另一个 VLM 当唯一奖励，那会师生同谋。
- **反思步数要不要奖励？** 不要。步数是延迟，不是质量。只奖励「改对了」。
- **和 SFT 的关系？** SFT 先教会字段 JSON 格式，GRPO 再优化对错；格式都乱则奖励估不准，优势全是噪声。
- **组大小 $n$？** 太小 advantage 噪，太大浪费 rollout；先保证奖励不可 hack，再调 $n$。全对 / 全错组要单独监控零优势比例。
- **先故意写错再改对怎么办？** 加「首次输出正确」项，或对「前错后对」降权；过程分不能高于最终正确性。
