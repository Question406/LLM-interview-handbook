## 真题记录

- 公司：商汤
- 岗位：多模态大模型算法实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：“为什么要做思维链，这里会不会涉及到过度设计”

做思维链，是因为有些任务一步前向会跳步，比如多栏表格对位、跨页字段、价税勾稽，需要先对齐几处视觉证据再下结论。判断是不是过度设计，看简单集和复杂集的准确-延迟曲线：复杂集涨点、简单集的延迟可以接受，才值得留；简单集变慢、复杂集持平，就是过度设计。中间过程必须能自动打分，打不了分的链就删掉。

拿增值税发票来说，「价税合计」要和「金额 + 税额」对上。这里 CoT 有用：定位三个字段 → 检查 $\text{金额}+\text{税额}=\text{价税合计}$ → 对不上再重读模糊的格子。印刷体的「发票代码」是十二位数字，直接读出来再用正则校验就行，硬生成一段「我先观察版式再思考」只会加延迟。面试时给出这一正一反就够了：价税勾稽要链，十二位代码不要链。

商汤这一面同时问了 OCR 过拟合和 GRPO 奖励，所以别答「CoT 一定更好」或者「多写首先 / 然后就能涨分」。奖励如果只看有没有套话，模型就会刷步数。

## 什么时候要 CoT

要 CoT 的信号，是必须对齐多个视觉证据才能下结论，或者中间的假设需要被检查，典型就是多栏表格对位（「这一格对应哪一列」）、跨页字段和价税勾稽。不要 CoT 的信号，是正则能抽的日期、单字印刷体、OCR 已经高置信的固定栏位。能用规则校验的步骤，别硬生成很长的推理过程，校验器比自然语言便宜，也更稳。说到底，CoT 的价值在于给容易跳步的任务提供一个可检查的中间状态，模型会不会写议论文无关紧要。

延迟账也要会算。多生成 200 个推理 token，输入预填充（prefill）和逐 token 生成（decode）的成本都会增加，证件核验的 SLA 往往比开放 VQA 紧得多。能用正则和算术校验解决的，就别买这段延迟。

## 怎么判断过度设计、奖励怎么打

过度设计的信号有三个：简单字段变慢；分布外数据（OOD）上准确率不提高；模型模板化地写「我再检查一下」，字段却没变。OOD 上 CoT 不涨点，说明这条链并没有真正读图，只是训练模板。和 OCR 过拟合连起来看，套话链在固定版式上拿满分，换成有印章遮挡的版式，它仍然先写「我再检查一下」，再输出同样的错字段，这段反思没有任何视觉证据支撑。要求中间步骤带上框或单元格 id，CoT 才算 grounded，纯文字的过程证明不了模型看了哪一格。

过程奖励必须能自动判定，比如字段有没有改对、勾稽有没有通过，别打在「写出了思维链」上。这和反思验证是同一个原则：把「改」变成可对比的动作，多一段散文不算改。同面的 GRPO 卡也说了，空反思、没错却大改都要扣分。

数据配比上也能看出过度设计。如果训练里每条样本都强制很长的推理过程，模型会把「先观察版式」当成格式奖励，简单题也被拖长。课程要分流：简单字段走短答案 + 校验器，复杂题才要求列出定位步骤和勾稽式。评测也别只用带 CoT 的复杂集，加一个「发票代码 / 日期」的短字段集，看延迟和准确率有没有被很长的推理过程拖坏。商汤问「会不会过度设计」，要的就是这道门禁，哲学讨论用不上。

## 追问

**奖励怎么设？**
打在校验通过和字段正确上，不按「首先 / 然后」计数。空链、假检查都扣分。

**隐式 CoT、不输出过程行不行？**
延迟更低，但没法审计。高风险字段仍然要有可验证的步骤或工具痕迹。

**和工具调用怎么配合？**
计算器、校验器比让模型心算合适。CoT 只负责决定调谁、读哪一格，并写清 grounding 的位置。

**过拟合会不会更严重？**
会。套话 CoT 在训练版式上很好看，换了版式就只剩套话，见 `sensetime-ocr-overfit`。

**必须输出自然语言的链吗？**
不必。结构化的中间态（字段 JSON + 框 + 勾稽布尔）比散文更好打分，也更不像过度设计。
