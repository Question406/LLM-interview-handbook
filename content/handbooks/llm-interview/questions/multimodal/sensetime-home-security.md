## 真题记录

- 公司：商汤
- 岗位：大模型算法应用实习；二面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：“设计智能家庭安防管家，识别入侵、火灾、老人跌倒、宠物破坏等事件，并路由到报警、通知、开灯、联系家属等流程。还要考虑视频、声音、传感器时效不同下的渐进式响应，以及用户用自然语言配置规则，比如外卖员放门口不报警”

我会把它做成事件状态机加编译好的规则。烟感、燃气、跌倒穿戴这类传感器先走短链路发预告，视频和声音晚到之后再升级或撤销；用户的自然语言规则编译成带时间、地点、例外的可执行约束，冲突时安全规则优先。VLM 负责确认事件、解析用户的话，执行哪些规则由程序决定。

为什么不画一个端到端 VLM「看完再决策」：烟感、跌倒穿戴往往比摄像头先到，等视频确认再动，火灾和跌倒都会晚。另一个容易栽的地方是，用户说「外卖员放门口不报警」，就把入侵检测关了。这句话应该变成一个带时间窗和地点的例外槽位，过期自动失效。

先说渐进响应。事件按危害 $\times$ 证据时效分级。烟感 / 燃气、跌倒穿戴先出预告（声光、推送），高延迟的视频不作为最先触发响应的依据。每类事件一个有限状态机：空闲 → 预告 → 确认 / 撤销 → 处置 → 复盘。预告阶段只允许低成本动作，比如开灯、室内提示；确认之后才允许外呼、开门、报公。渐进响应写成状态，别写成「模型再看一眼」。摄像头和声音随后到达，是新证据，前面传感器的结论不作废：视频看到是烧糊的锅可以降级，看到明火就升级到 119，并给出切断建议；跌倒后人已经起身，可以撤销强呼。传感器和视频的时间戳对不齐是常态，融合用时间窗，别「等齐再判」。声音（玻璃碎、烟感蜂鸣）当一条独立的证据通道，和画面互相印证。确认阶段用多模态 grounding，人、烟、倒地姿态要落到时间和空间上，比如人在门口还是院外、是否倒地、能不能看见烟雾，输出结构化标签，别写一段「画面异常」的安防散文。

路由按成本走：火灾走应急和切断，跌倒走家属 / 社区，宠物破坏只发通知不强呼，入侵在例外槽没命中时才报警。权限和误报成本写进策略，老人跌倒宁可误报，宠物抓沙发不能半夜打 110。

再说自然语言规则。用户的话解析成结构化记录 `{event, time_window, location, object, exception, action}`，落库、可测，不能每句话现场让 LLM 自由发挥。不能用自然语言关掉烟感。外卖员这个例外绑定时间窗、门口区域，可选绑运单或人脸，离开窗口自动失效，不会变成永久的「门口不报警」。编译失败就澄清，比如问清「外卖员」的时间、地点、包不包括代收点，缺槽位就不生效，别静默丢掉条件。同一地点有多条规则，用优先级表定，不让模型临场仲裁。例外命中时也记审计日志，方便事后发现有人用社会工程滥用它，比如每天声称有外卖，借机关掉门口检测。这和审核自适应是一个思路：规则要版本管理，模型不能自己改规则，安全红线也不能被用户一句话关掉。

评测要专门构造几类场景：传感器先到、视频后到；例外过期之后来了真入侵；规则互相矛盾。主指标是漏报（尤其火灾 / 跌倒）和误报（尤其夜间入侵），再加规则冲突数和「例外是否按窗口失效」，演示视频好不好看不算数。

## 追问

**视频坏了怎么办？**
高危害事件仍走传感器短链路，视频只负责确认，不是唯一开关。坏了就停在预告或转人工，不能当成「没事件」。

**宠物和小孩怎么区分？**
确认阶段用尺寸、姿态和家庭成员库；不确定就只通知不强呼，跌倒通道优先用老人画像。

**规则谁来改？**
用户改例外槽，平台改安全红线，后者不能被前者覆盖。两者冲突就升级处理，不交给模型仲裁。

**隐私怎么处理？**
视频默认端侧或短时缓存，上传云要用户显式同意，规则引擎用不着每帧出网。日志记事件类型，不记原片。

**外卖员例外被滥用怎么办？**
加时间窗、地点和频次上限，过期失效，命中了也审计，不能让它变成永久关闭入侵检测。
