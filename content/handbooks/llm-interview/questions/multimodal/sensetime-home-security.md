## 真题记录

- 公司：商汤
- 岗位：大模型算法应用实习；二面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：“设计智能家庭安防管家，识别入侵、火灾、老人跌倒、宠物破坏等事件，并路由到报警、通知、开灯、联系家属等流程。还要考虑视频、声音、传感器时效不同下的渐进式响应，以及用户用自然语言配置规则，比如外卖员放门口不报警”

常见误区是：画一个端到端 VLM「看完再决策」。烟感、跌倒穿戴往往比摄像头先到；等视频确认再动，火灾和跌倒会晚。另一处容易栽的是：用户说「外卖员放门口不报警」就把入侵检测关掉。例外是带时间窗和地点的槽位，过期自动失效。评测用误报率、漏报率、规则冲突数，不是演示视频好不好看。

## 渐进响应：先短链路，后到的模态可升级或撤销

事件按危害 $\times$ 证据时效分级。烟感 / 燃气、跌倒穿戴走短链路：先出预告（声光、推送），不把高延迟视频当第一道门。摄像头、声音随后到达，状态机允许「预告 → 确认 → 取消」：视频看到是烧糊的锅可以降级，看到明火则升级到 119 与切断建议；跌倒若人已起身可撤销强呼。晚到模态是新证据，不是把前面传感器作废。路由按成本：火灾走应急与切断；跌倒走家属 / 社区；宠物破坏走通知不强呼；入侵在例外槽未命中时才报警。权限与误报成本写进策略：老人跌倒宁可误报，宠物抓沙发不可半夜 110。多模态 grounding 用在确认阶段：人 / 烟 / 倒地姿态要落到时间和空间，而不是一句「画面异常」。

## 自然语言规则编译成可执行约束

用户话术解析成结构化记录 `{event, time_window, location, object, exception, action}`，落库可测，不能每句现场让 LLM 自由发挥。冲突时安全规则优先：不能用自然语言关掉烟感。例外（外卖员）绑定时间窗、门口区域、可选运单 / 人脸；离开窗口自动失效，不会变成永久「门口不报警」。编译失败则澄清，不要静默丢条件。同一地点多规则用优先级表，而不是模型临场仲裁。评测构造：传感器先到视频后到、例外过期后的真入侵、规则互相矛盾。主指标是漏报（尤其火灾 / 跌倒）和误报（尤其夜间入侵），外加「例外是否按窗失效」。状态机 + 版本化规则，VLM 负责确认事件和解析用户表达，执行哪些规则由程序决定。

渐进响应要写成状态，不要写成「模型再看一眼」。每类事件一个有限状态机：空闲 → 预告 → 确认 / 撤销 → 处置 → 复盘。预告阶段只允许低成本动作（灯、室内提示）；确认后才允许外呼、开门、报公。传感器时间戳和视频时间戳不对齐是常态，融合用时间窗而不是「等齐再判」。声音（玻璃碎、烟感蜂鸣）当独立证据通道，和画面互证。VLM 做的是确认阶段的 grounding：人在门口还是院外、是否倒地、是否可见烟雾，输出结构化标签而不是一段安防散文。自然语言规则编译失败必须澄清「外卖员」的时间、地点、是否含代收点，缺槽位就不要生效。例外命中时仍记审计日志，便于事后发现被社会工程滥用（每天宣称有外卖从而关掉门口检测）。和审核自适应同一思想：规则需要版本管理，模型不能自行修改规则；安全红线不能被用户一句话关掉。

## 追问

- **视频坏了怎么办？** 高危害事件仍走传感器短链路；视频是确认，不是唯一开关。坏了就停在预告 / 人工，而不是当成「没事件」。
- **宠物和小孩怎么区分？** 确认阶段用尺寸 / 姿态 / 家庭成员库；不确定则通知不强呼，跌倒通道优先老人画像。
- **规则谁来改？** 用户改例外槽，平台改安全红线；后者不可被前者覆盖，冲突升级而不是模型仲裁。
- **隐私？** 视频默认端侧或短时缓存；上传云需显式同意，规则引擎不需要每帧出网。日志记事件类型不记原片。
- **外卖员例外被滥用？** 时间窗 + 地点 + 频次上限；过期失效；命中仍审计。不能变成永久关闭入侵检测。
