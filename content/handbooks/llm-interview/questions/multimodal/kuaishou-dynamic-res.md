## 真题记录

- 公司：快手
- 团队 / 岗位：大模型算法实习
- 届别 / 流程：实习；二面
- 面试时间：原帖未披露；帖子发布于 2026-01-08
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：“现在的多模态大模型，动态分辨率一般都是怎么做的，位置编码怎么设计”

常见误区是：「先 resize 到 $224\times 224$ 再走固定 ViT」。电商价签、直播弹幕、商品文字会被裁掉或糊掉。动态分辨率要保留长宽比，按 patch 大小得到可变 $H\times W$ 网格；位置编码必须跟网格走，不能把图块当成一维句子。

## 可变 patch 数，而不是固定格子

流程：保留或分组统计原始长宽比 → 按 patch（如 $14\times 14$）得到 $H\times W$ → 视觉编码器输出可变长度的 token 序列 → 投影进 LLM。任意分辨率会让序列长度差一个数量级，所以工程上常做：最短边 / 最长边分组统计、面积上限、或 AnyRes 式切块再拼接。Qwen2-VL 一类用 Naive Dynamic Resolution：不强制正方形，token 数随图变。直播 / 电商要额外设 token 预算：超清图先切块再池化或抽 token，否则预填充（prefill）的计算量和 KV 缓存都会过大。和时延题连起来：先控视觉 token 数，再谈并行解码。

固定 224 的失败模式是 grounding / OCR 一起坏：小字价签占不到几个 patch，模型可能依靠语言先验编造价格。动态分辨率的收益主要在文字与小物体，不是风景图更好看。

## 位置编码：二维坐标随网格变

每个 patch 给整数坐标 $(h,w)$，视频再加 $t$。常用分解 RoPE / M-RoPE：把旋转频率分到时间、高、宽，文本三轴共用同一 1D 下标，视觉则拆开。绝对 1D 序号（光栅扫描 id）在分辨率一变就错位：同一物体换图尺寸后「句子位置」变了，空间邻居却应不变。因此编码必须是网格坐标的函数，不是序列下标的函数。面试先讲「模态各编各的，再进同一注意力」，细节数字以当时公开报告为准，不要编层数。还要说清：不压缩则视觉 token 吃光上下文，动态分辨率需要与 token 合并配合，例如像素 shuffle 或池化，共同控制序列长度。

快手场景把收益说具体。直播截帧和商品主图都是高密度文字：价格、规格、倒计时。固定短边 224 时，价签可能只占一两像素，VLM 只能靠语言先验瞎报，这是 grounding 失败而不是「生成不稳」。动态分辨率让价签区有足够 patch，再靠二维位置让「左上价签」和「右下销量」不要在注意力里挤成邻居。预算策略可以按任务：OCR / 价签用更高上限；开放描述、封面美学用更低上限。训练要混多种面积桶，否则模型只在某一种网格上见过 RoPE，上线一变分辨率位置外推就可能不稳定。视频再加一维：同一空间格子不同 $t$ 应能区分「上一秒的价格」和「这一秒的价格」，否则倒计时 OCR 会串帧。

和时延题的连接：视觉 token 数近似按面积线性涨，prefill 是 $O(n^2)$ 注意力。先设硬顶 $N_{\mathrm{vis}}$，超出则降采样或切块+局部再融合。并行解码救不了已经膨胀的 KV。可变网格、二维（加时间）位置、token 预算，三句话缺一不可。

## 追问

- **为什么不能只用 1D RoPE？** 行末与下一行首在 1D 上相邻，空间上不相邻，OCR 对位和框选都会乱。
- **切块边界怎么处理？** 重叠窗口或边界 pad，避免字被切成两半却没有跨块注意力；必要时对跨块字段做二次拼接。
- **视频怎么控预算？** 先降帧再动态空间分辨率；时间轴用 $t$ 或显式时间戳 token，倒计时类 OCR 尤其要锁帧对齐。
- **和 Qwen3-VL？** 仍是网格坐标 + 多轴 RoPE，频率改为交织，见 `meituan-qwen3-vl-pos`。
- **奖励怎么配？** 价签 / OCR 任务按字段准确和框的交并比（IoU，即两个区域的交集与并集之比）打分，不要只打开放描述的流畅度，否则模型会减少 token 却忽略文字准确性。
