## 真题记录

- 公司：美团
- 团队 / 岗位：大模型算法
- 届别 / 流程：27 暑期；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“介绍Qwen3-VL多模态模型的位置编码方案”**

这块容易直接答成把视觉 token 当成一维句子做标准 RoPE，或背一堆未公开的层数。文本仍是 1D；视觉带网格坐标；动态分辨率下位置跟 $H\times W$ 走。Qwen3-VL 公开报告写的是 Interleaved M-RoPE，不要编具体 head 切分数字，除非你读过当时的技术报告。

## 三层：文本、视觉、融合

1. **文本**：标准 RoPE。Qwen 系 M-RoPE 对文本令 $t=h=w=$ 同一递增下标，退化回 1D，纯文本能力不被视觉坐标打乱。
2. **视觉**：每个 patch 有行 / 列（视频再加时间）坐标。Qwen2 / 2.5-VL 把旋转频率按维切成 $t,h,w$ 三段；报告指出这种切法频谱不均，长视频吃亏。Qwen3-VL 改为 interleaved M-RoPE：把 $t,h,w$ 交错写进高低频，让三轴都吃到低频。空间上相邻的 patch 旋转更近，比光栅扫描 1D 更利于 grounding / OCR 对位。
3. **融合**：视觉 token 投影进 LLM 隐空间后，同一注意力里同时看见文本位置与视觉网格位置。分辨率变则网格变，坐标必须重算，不能复用固定 224 的序号。

视频侧 Qwen3-VL 还把「用位置编码对齐绝对时间」改成显式时间戳 token，位置编码不再独自承担时钟。面试若被追问，说「时间接地从 T-RoPE 走到文本时间戳」，不要把层数编出来。

## 动态分辨率与 grounding

高清图切更多 patch，1D 序号会把「同一物体换了尺寸」当成完全不同的句子位置。网格坐标让「上 / 下 / 左 / 右」可区分，字段框、价签、按钮点击才有几何意义。token 预算仍要控：位置编码再好，视觉序列把上下文吃满，OCR 也没地方放。DeepStack 等跨层视觉残差不增加上下文长度，和位置编码是另一条线，被问到再说，不要主动堆名词。细节以 arXiv:2511.21631 为准。

白板可以先画三个整数轴，再说明文本退化。图像 token 的 position id 是三元组 $(t,h,w)$，同一帧 $t$ 恒定，$h,w$ 走网格；文本 token 是 $(n,n,n)$。注意力里的旋转差：空间相邻 $\Delta h=0,\Delta w=1$ 的两块，与光栅扫描下相距 $W$ 的 1D 差，完全不是一回事。这就是 grounding 要二维位置的原因，「把价签框出来」依赖邻域，不依赖「它是第 137 个视觉 token」。动态分辨率下 $W$ 会变，1D 序号方案立刻错；网格坐标方案只改 $H,W$ 的取值范围。Qwen3 相对 2.5 的可讲变化就两句：频率交织，减轻长视频偏科；时间从位置轴部分改到显式时间戳，事件定位更像「对齐到字面时间」而不是「对齐到某个 RoPE 段」。不要把 DeepStack、损失改成 $\sqrt{}$ token 平均当成位置编码的一部分。

美团若追问点选 / 框选，补坐标空间：模型输出的点要落在当前网格对应的原图像素，而不是某个固定 224 画布。分辨率桶一变，后处理映射也要变，否则 grounding 指标全假。这和桌面 GUI grounding 同一坑：逻辑像素和截图像素不是一回事。

## 追问

- **文本三轴相同会不会和图像冲突？** 文本没有独立 $h,w$ 语义，三轴同值就是 1D；图像三轴不同才编码平面。冲突来自实现写错 id，不是公式本身。
- **为什么要交织频率？** 分段 M-RoPE 把低频几乎分给某一轴，长程时间建模偏科；交织让 $t,h,w$ 都吃到低频。
- **和绝对可学习 2D 表？** 表绑定固定 $H\times W$；动态分辨率下 RoPE 外推更干净，也省一张随分辨率爆炸的表。
- **坐标用相对还是绝对格子？** 实现是格子下标进 RoPE；相对关系由旋转差体现，不需要再加相对偏置表。
- **输出 bbox 怎么对齐？** 按当前 patch 网格反投影到原图；换分辨率必须换映射，不能写死 224 标定。
