堆更多图文对并不等于有数据引擎。CLIP 一类工作已经说明：规模有效的前提是过滤、对齐与版本化，而不是把网图原样入库。这块容易直接答成只讲爬虫和标注员人数，不讲每阶段门槛、失败回流和近重复。多模态引擎必须是闭环：采集 $\to$ 质量 / 安全过滤 $\to$ 自动加人工标注 $\to$ 训练 $\to$ 错误挖掘再入库。没有回流，你在用易例把 grounding 刷绿，线上图标和扫描件仍然挂。产物要版本化：数据集 digest、过滤规则版本、标注指南版本，否则「加了数据」无法归因。

## 采集与过滤：先丢掉不该进模型的

采集要记来源、许可、时间、语言、分辨率，而不是只有 URL。过滤至少：模糊 / 过压缩、图文低相关、近重复、PII、有害、水印广告、以及 caption 与像素明显不匹配。相关度可用 CLIP 分数设下限 $s(I,T)\ge\tau$，但 $\tau$ 不能当唯一门；高分也可能是模板水印配万能文案。过严则有效规模塌缩：若过滤后 $|D'| \lt \beta |D|$ 且下游召回不升，说明 $\tau$ 切掉的是长尾而不是垃圾，应改规则而不是继续加严。安全过滤与质量过滤分列：有害漏放率和低相关删除率都要报，合并成一个「清洗率」会藏漏放。PII 走检测加人工抽检，不要指望 caption 里没有名字像素里也没有。许可证与版权来源写进 provenance；训不进的数据不要「先用着再补协议」。

## 标注、门槛与回流

标注任务拆开，不要一张图一个万能 caption：grounding 框、OCR、UI 动作、文档 layout、视频关键帧状态，各有指南和 IAA。自动预标 + 人工校准；争议样本进黄金集。每阶段门槛量化：近重复率、有害漏放率、框 IoU、OCR 字段 F1、动作轨迹可执行率。训练后按失败类型回流：grounding 偏、OCR 串行、图标无文本、扫描倾斜，而不是再堆「好看」的自然图。回流占比应有下限，例如失败挖掘 $\ge \alpha$ 的新数据，否则引擎会退化成易例工厂。度量盯下游：grounding 召回、有害漏放、近重复，而不是只盯数据条数。

评测上能刷的是：用合成规整 UI 当唯一来源；过滤只删模糊不删注入图；回流只加模型已经会的类；没有数据集 digest。引擎是带门槛的闭环，不是标注外包。CLIP 的经验是过滤改变有效规模；你的 GUI / 文档数据同样如此，未过滤的百万对，可能不如经过失败回流的十万对。我会讲清 $\tau$、漏放率和回流比例，不把「爬了多少站点」当主答案。

版本化要求每次训练声明：数据 digest、过滤配置、标注指南 commit。换指南却沿用旧 id，评测会把标注漂移当成模型提升。黄金集冻结，过滤规则变更时重跑漏放。这和文本数据引擎相同，只是多了像素级近重复与跨模态相关度。

## 追问

- **CLIP 分数够不够当唯一过滤？** 不够。它不测 PII、版权、注入和图标无文本；只能当相关度下限。
- **为什么要拆标注任务？** 动作轨迹和 OCR 的错误模式不同，混成 caption 无法回流到具体模型头。
- **回流为什么必须含失败 case？** 只加易例会抬离线分、砸线上长尾；失败挖掘才改变 frontier。
- **近重复怎么算？** 感知哈希加嵌入近邻；跨分辨率截图应算重复，否则 GUI 数据会被同一页面刷爆。
