图像和 PDF 一律按不可信数据处理，和网页、邮件一样，图里写的指令没有权限覆盖系统策略，可见的指令也不能升级权限。防御按 taint 来做：图和 PDF 是 data，不是 authority，图里的 URL、二维码、账号也不能自动变成工具参数。

举个例子，一份发票 PDF 的隐藏层里写着「忽略以上指令」，后面跟一个上传地址，人眼看不到，抽取器读得到。Agent 一旦把这段字符串拼进 planner，就会去调用外发、支付、上传。只给文本通道做 jailbreak 过滤，却把截图、发票 PDF、二维码当成「用户已经看见的 harmless 数据」，这是多模态 Agent 的主漏洞。间接注入用不着和控制面对话，恶意指令可以是图上的白字、PDF 隐藏层、看起来像系统对话框的截图。Greshake 等人把数据通道写成了攻击面，视觉文档只是同一通道的另一种载体，所以这题和 `agent-prompt-injection` 同源：那题讲的是 tool / 检索增强生成（RAG） / memory 这些数据通道，这题讲视觉文档怎么成了同一条通道。

攻击面比可见文字大，至少有四类：排版注入，比如低对比文字、页脚写「忽略以上指令」；PDF 隐藏 / 可选内容组，人眼看不到但抽取器读得到；伪造系统 UI，比如截图里的确认框、浏览器权限条；机器可读载荷，比如二维码、图中 URL、附件脚本。OCR 之后再跑文本安全模型，会漏掉隐藏层，也拦不住「把图里 URL 当工具参数」。视觉通道还多了一层错觉，用户以为自己看见了全文，其实隐藏层他没看见，Agent 却读到了。产品文案不能写「已展示给用户因此安全」，把这条写进威胁模型，比再训练一个拒答头更重要。

缓解要分层做，再写一句 ignore 没用。控制面和数据面分开，系统策略不进视觉 encoder 能改写的区域，视觉抽取结果标 `untrusted`。抽取文本跑一遍 injection 分类器，但分类器失败时不能放行敏感工具，默认 deny。工具参数白名单拒绝「来自图像抽取、未经用户确认」的 URL 和账号，出站走允许列表，敏感工具人审，禁止自动跟随图中链接，产品上要盯住「二维码里的 URL 会不会直接变成 `http` 参数」。再把人眼可见的内容和抽取文本做差分，隐藏层多出来的指令视为攻击；缺这一步，你测的是排版，测不到 PDF。

评测要用专用红队集，同一版式的正常票据任务和带注入的版本成对跑，报 utility、ASR、外泄率，禁止只报拦截率。Canary 可以印在图或 PDF 层里，出现在出站请求里就算外泄；没有 canary，只能测出模型有没有骂攻击者。攻击成功只算环境副作用真的发生了：$\mathrm{ASR}=n_{\mathrm{effect}}/n_{\mathrm{atk}}$，同时正常任务成功率要满足 $\mathrm{U}\gt U_{\min}$，否则拒答一切也能刷拦截。容易误导的做法有：只把直球的「忽略之前的指令」印在图上；不测隐藏层；把 OCR 清洗当充分条件；模型嘴上说「我拒绝」，其实已经请求了图中 URL。落地清单就是 taint 标记、隐藏层差分、出站 allowlist、敏感工具确认、canary、成对评测。

## 追问

**OCR 之后再做文本过滤够吗？**
不够。隐藏层、二维码和伪造 UI 不一定会进 OCR 结果，工具参数还是可能直接吃到图中 URL。

**评测怎么和 `cu-security-evaluation` 接上？**
把视觉注入并进那边的成对任务，用 canary 衡量注入有没有在环境里得逞，拒答话术说得好不好不算。

**用户说「按图里的做」怎么办？**
图中的 URL、账号照样不能自动授权；高风险参数要系统确认，图只提供建议。
