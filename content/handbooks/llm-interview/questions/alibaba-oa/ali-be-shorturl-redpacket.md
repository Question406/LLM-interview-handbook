## 题目描述

面经只给出短链/红包设计方向，以下功能与示例是手册练习约定。

### 场景与目标

分别设计短链接服务和拼手气红包服务，两题独立回答。短链接把长 URL 变为可分享入口；红包在固定总金额和份数内供多人领取。

### 需要满足的功能

- 短链：创建短码、解析跳转、支持约定的过期/撤链与访问统计，可讨论自定义短码。
- 红包：创建金额和份数，用户领取并查询结果，处理重复领取、领完与账户入账状态。
- 明确定义每个请求的成功、重复和失败返回语义。

### 约束与交付物

短码碰撞或恶意跳转不能破坏正确性；红包同一用户只能领取一次，所有领取金额总和不能超过原额，金额按最小货币单位处理。规模和时延属于需要澄清的设计参数，不把某种缓存或数据库当成题目要求。

请说明 scope 和 constraints、对外接口及返回语义、核心数据对象、主要请求的完整生命周期、故障与恢复行为，以及能验证设计是否达标的指标。题目不预先指定数据库、模型或调度算法；需要解释自己作出的选择与代价。

### 请求与结果示例

短链 S 指向 URL U，过期前解析 S 得到 U，过期后返回约定的失效结果；一个总额 100 分、2 份的红包，无论如何并发领取，已领取金额总和不能超过 100 分。

## 解题思路与参考答案

两题的热点形态正好相反。短链是一次生成、千万次打开的读放大，主要矛盾是缓存和安全；红包是很多人同时抢 $N$ 个名额，主要矛盾是写冲突和资金正确。两者都要幂等和审计。阿里校招系统设计常考短链、红包和限流这几道。

短链把长 URL 映射成短码，用一次跳转换来可分享的入口。写路径是发号或哈希得到短码，写进映射表；读路径按短码查原链，返回 $301$ 或 $302$。$301$ 会被浏览器和 CDN 永久缓存，省回源，但改指向很难；$302$ 每次回源，方便统计和撤链。分层上，发号层保证唯一；MySQL 做权威存储，Redis 存热映射；接入层做黑名单和循环检测（A→B→A）；观测层把点击丢进 MQ。用户自定义短码要加唯一约束，并禁用保留字。拿长 URL 的哈希摘要当短码要处理碰撞，冲突就加盐再哈希，或者退回发号。另外还要处理过期和点击统计。

红包是一个红包 $N$ 个名额、总额固定。写路径是原子扣名额、记下领取、再异步入账。预热时把剩余份数放进 Redis；抢的时候 `DECR`，小于 $0$ 就回补并返回抢完；成功了才写领取记录，用户加红包做唯一键，已经领过的直接返回原结果；入账走 MQ，失败重试，最终回补名额。金额要么预拆，发红包时就把每份算好，适合晚会这种固定场次；要么实时随机，像微信式拼手气，但要守住剩余人数和剩余金额的约束。二倍均值法是实时算法：第 $i$ 个人从 $(0, 2 \times \text{剩余}/\text{剩余人数})$ 里随机，期望公平，也不会过早把余额抽干；最后一份不随机，直接给剩余，保证总额分完。防刷靠验证码、设备、同一用户限频和风控分。

| | 短链 | 红包 |
| --- | --- | --- |
| 主矛盾 | 读放大、安全 | 写冲突、资金正确 |
| 存储 | 映射表 + 缓存 | 库存令牌 + 领取记录 + 账户 |
| 发号 | 号段 / 雪花 / 哈希 | 红包 ID + 用户维度唯一 |
| 失败 | 404、拦截钓鱼 | 抢完、重复抢、入账失败回补 |
| 统计 | 异步点击，不挡跳转 | 异步入账，reconciliation checks |

## 放到阿里的场景里

淘宝分享商品、会场、直播间都会生成短链。读路径极热，大 V 一条链接被转发，CDN 和 Redis 必须挡住映射查询。统计「这个会场带来多少点击」不能同步写 DB，否则跳转变慢，分享体验先受影响。钓鱼是合规红线：生成时校验域名白名单，跳转页可以加中间提示。循环短链会把服务自己打爆，要检测跳转深度。过期的活动链用 TTL，避免映射表无限膨胀。

红包出现在年货节、直播打赏、天猫乐园。和秒杀的差别在于，秒杀是同一价格、同一 SKU；红包是总额约束下的随机切片，还要防止最后一个人分到 0.00，或者把余款独吞。入账进钱包是资金操作，必须异步且幂等，不能在抢的锁里调支付。直播间红包比普通红包更热，名额先预分到多个 Redis 桶，再在桶内 `DECR`。

审计方面，短链留生成者、原链和拦截记录；红包留每笔领取的金额、时间和入账流水。资金差错靠流水回放来查，当时内存里的状态靠不住。

## 追问

**短链用 62 进制，多少位够？**
$6$ 到 $8$ 位通常够亿到百亿级，按发号空间 $62^n$ 来算。

**为什么不直接哈希长 URL？**
有碰撞，也没法递增扫描；发号更好控制。

**$301$ 改不了指向怎么办？**
活动链用 $302$，品牌短链才用 $301$。

**入账失败回补名额，会不会超发？**
不会，只要回补和领取记录在同一个状态机里，已入账的禁止回补。

**短链和红包能共用秒杀那套架构吗？**
排队和原子减可以借鉴；短链不需要预减，红包必须管住金额约束。
