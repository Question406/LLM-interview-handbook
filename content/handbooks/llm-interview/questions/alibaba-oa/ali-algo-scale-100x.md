## 真题 / 考点说明

- 来源：校招面经常在手撕后追问「搜索纠错 / Top-K / 流量 $\times 100$」

这题不写代码。考的是：你刚写的单机正确算法，哪一维复杂度会先爆，以及如何分层换挡。不要一上来「上 Kubernetes」。先量化，再降载，再水平扩，最后才改算法近似。

## 分层方案

**L0 先量化。** 100 倍是读 QPS、写 QPS、数据量、候选集，还是存储？P99 还能否同步算编辑距离 / LCS？一致性是必须精确，还是允许近似、脏读、最终一致？

**L1 单机降载。** 热点缓存、请求合并、批量、异步化、限流、降级到粗召回。把在线路径从「每次精确算」改成「查表 + 少量重算」。

**L2 水平扩展。** 按 key 分片，每片继续用刚才的堆 / LRU / 滑窗。分片挂了要有降级：少返回、返回缓存、返回近似。

**L3 算法换挡。** 精确 LCS / 全词典编辑距离改倒排 + 只打 Top 候选；全量排序改堆；精确去重改 Bloom / HyperLogLog。正确性从精确变成近似时，先说评估指标怎么守。

## 例子

**搜索纠错（编辑距离）。** 原复杂度大约 $O(|q|\cdot|D|\cdot|w|)$。QPS $\times 100$ 时：用 ngram / 倒排先召回一两百个词，只对这批算编辑距离；query 结果加本地缓存；P99 超时返回拼音粗纠错。词典先验和语言模型打分放在重排，不进 DP。

**推荐 Top-K。** 原快选要随机访问整段数组，流式数据直接不适用。候选 $\times 100$：每个分片维护大小为 $k$ 的小顶堆，定期 merge；带 TTL 的分数惰性删除。不要「先全局排序」。

**LRU。** 单机哈希 + 链表在 100 倍并发下先爆锁。单机改分段锁；跨进程用 Redis `maxmemory-policy`，本地再叠一层热点缓存。淘汰语义从进程内精确 LRU 变成集群近似 LRU，要主动说出来。

**合并区间 / 滑窗。** 单机 $O(n\log n)$ / $O(n)$ 在数据量 $\times 100$ 时：按时间或 key 分片扫，窗口状态做成可合并的摘要（max、count），而不是把 100 倍原始事件拉回一台机器。

## 边界与追问

1. 读多写少和写多读少换挡不同：前者堆缓存，后者堆分片与异步落地。先问读写比。
2. 精确变近似之后，用什么指标守门：纠错用 Top-1 准确率，Top-K 用 Recall@$k$，缓存用命中率与过期错误率。
3. 分片挂了怎么降级：Top-K 用剩余分片合并并标明不完整；纠错回退词典缓存；不要假装结果仍全局精确。
