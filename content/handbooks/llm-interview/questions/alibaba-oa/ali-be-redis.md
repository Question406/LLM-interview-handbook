## 真题记录

- 岗位：阿里校招后端

## 定义

缓存是把高频读从 DB 卸到内存。可以按 key 不存在、热点 key 过期，以及大量 key 同时失效来区分。穿透：查询一个缓存和 DB 都不存在的 key，每次都打穿到 DB。常见于乱猜商品 ID 或爬虫。击穿：一个热点 key 刚好过期，瞬时所有请求去 DB 重建，单点把库打满。雪崩：大量 key 同一时刻过期，或 Redis 进程宕掉，流量集体回源。分布式锁是另一条线：在多个进程之间互斥执行临界区，Redis 实现的最低标准是 `SET key token NX PX ttl`，释放时用 Lua 比较持有者 token，再删除锁，避免删掉别人续上的锁。

空值缓存是短 TTL 的负缓存，防穿透但不该永久占内存。逻辑过期是「值还在、过期时间写在 payload 里」，由少数线程异步刷新，读请求始终命中，用脏读换稳定。锁的 TTL 必须大于临界区，否则要看门狗续期；续期失败要当没锁到，不能继续写。

## 对比 / 分层

| 问题 | 现象 | 首选手段 | 加强 |
| --- | --- | --- | --- |
| 穿透 | 随机 / 空 key 打 DB | 空值短 TTL | 布隆 / 布谷过滤器挡在网关 |
| 击穿 | 单热点过期 | 互斥锁重建 | 逻辑过期 + 单飞 |
| 雪崩 | 同时过期或缓存挂 | TTL 加随机抖动 | 集群、多级缓存、限流降级 |
| 锁误删 | TTL 到期被别人抢走 | token + Lua 删 | Redisson 看门狗 |
| 热 key | 单 key 打满网卡 / CPU | 本地缓存、分片复制 | 读写分离、拆 key |

一致性分层：Cache-Aside 是业务先读缓存，未命中读 DB 再回填，更新时先改 DB 再删缓存；双写缓存容易和并发读交错出脏数据，删缓存比更新缓存更常见。锁分层：单 Redis 实例的 `SET NX` 在主从 failover 时可能丢锁（主没同步完就切换），校招说到这层即可。Redlock 有争议，别当标准答案背。热 key / 大 key 单独一层：大 value 拆字段，避免 `KEYS *`、避免无界的 `HGETALL`。

## 阿里场景

商品详情是穿透和击穿的经典现场。下架或根本不存在的 itemId 被刷，没有空值缓存就会把商品库打穿；爆款在整点改价，缓存一齐失效，重建查询又重，就是击穿。做法：不存在的 ID 缓存 $30$ 秒空对象；布隆过滤器在接入层丢掉明显非法 ID；爆款用逻辑过期，后台线程刷新。双十一还会叠一层本地 Caffeine，把最热的 SKU 挡在单机内存，Redis 只收第二层。

锁的场景是库存预扣或优惠券超发。`SET lock:coupon:{id} {requestId} NX PX 3000`，Lua 校验 `requestId` 再 `DEL`。临界区只做「读库存、判断、写库存」，IO 不要放锁里。看门狗续期适合「下单要调三个下游」这种长临界区，但下游超时必须停续期并回滚。阿里云上更多是 Tair，语义接近 Redis，面试用 Redis 命令讲即可，提一句生产可能是 Tair。

雪崩在发布窗口也常见：有人把活动商品 TTL 都设成整点 $00$:$00$，零点集体失效。TTL 改成基准加上 $0$ 到 $300$ 秒随机。Redis 集群挂了要有降级：只读本地缓存、关闭个性化、保下单主路。

## 追问

- 先删缓存再更 DB 行不行？并发读会把旧值填回来，更稳是先 DB 再删，或延迟双删。
- 布隆过滤器误判怎么办？误判只会造成「可能存在」去查 DB，不能用来当「一定不存在」的反面而漏掉真数据。
- 锁过期了业务还在跑？必须带版本 / token，过期后禁止再写；或用看门狗并监控续期失败。
- Redlock 为什么有争议？多实例独立超时，时钟和 GC 暂停会破坏互斥假设。
- 热 key 怎么发现？慢日志、`hotkeys`、网卡打满、单分片 CPU。
- `KEYS *` 为什么禁用？阻塞主线程；用 `SCAN`。
- 缓存和 DB 长期不一致怎么修？对账任务按主键重放，删缓存强制回源。
