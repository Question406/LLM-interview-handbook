## 真题记录

- 公司 / 场次：淘天算法岗 2025.08.16
- 操作：选 $i\neq j$，把 $a_j$ 加到 $a_i$ 上并将 $a_j$ 置 $0$。目标最大化 $\sum_k \max(a_1,\ldots,a_k)$。
- 样例：$[3,2,-1]\to 15$；$[-1]\to -1$。
- 文档 Part III 标明该场「宝石合并」公开页公式以图片存在、文本索引不完整。下面按已有复盘写，不假装有官方完整数据范围。

## 题面

（公开复盘等价转述）给定长度为 $n$ 的整数数组 $a$。一次操作选择两个不同下标 $i,j$，执行 $a_i\leftarrow a_i+a_j$，再令 $a_j\leftarrow 0$。操作次数不限。完成后计算

$$
\sum_{k=1}^{n}\max(a_1,a_2,\ldots,a_k)
$$

求这个值的最大可能值。

公开复盘给出样例 $[3,2,-1]\to 15$、$[-1]\to -1$。$n$、$a_i$ 的精确上下界未在可引用文本中完整公开；实现按 $O(n)$ 写即可。

输入：第一行 $n$，第二行 $n$ 个整数。输出一个整数。

## 思路

操作是把一颗宝石的能量全部转移到另一颗，并在原位置留下 $0$。反复做下去，等价于把能量重新分配到若干位置，其余位置为 $0$。能量总和守恒，但负数可以被转移到某处后，再被别的正能量「吃掉」，也可以被挪走从而在前缀里留下 $0$。

前缀最大值序列单调不降。要让它们的和尽量大，应让尽量多的前缀最大值变成尽量大的正数。最大能堆出来的正能量是所有正数之和 $P=\sum_{a_i\gt 0}a_i$（负数不必加入这个堆，加进去只会变小）。

把 $P$ 放到下标 $1$：之后每个位置的前缀最大都至少是 $P$，总和为 $nP$。放到更靠后的位置，前面若干个前缀最大会变成 $0$ 或负数，一定不更优。

若没有正数：

- $n=1$：无法操作，答案就是 $a_1$（可能为负或 $0$）
- $n\ge 2$：可以把某个负数挪到另一个位置，让下标 $1$ 变成 $0$，于是每个前缀最大都是 $0$，答案为 $0$

正能量全堆到最左，前缀最大被钉在 $P$；负数清零不会降低已经得到的 $P$。不必真的模拟多次融合。

## 参考代码

```python
import sys


def max_prefix_max_sum(a):
    n = len(a)
    if n == 0:
        return 0
    pos = sum(x for x in a if x > 0)
    if pos > 0:
        return n * pos
    if n == 1:
        return a[0]
    return 0


def main():
    data = list(map(int, sys.stdin.read().split()))
    if not data:
        return
    n = data[0]
    a = data[1:1 + n]
    print(max_prefix_max_sum(a))


if __name__ == "__main__":
    main()
```

边界：全 $0$ 时 $P=0$ 且 $n$ 任意，答案 $0$；只有一个负数无法消掉；`[0,-1]` 本身已是 $0$。乘积 `n * pos` 在其他语言里用 64 位。

## 复杂度

时间 $O(n)$，额外空间 $O(1)$。

## 易错 / 面试追问

- 真的写循环模拟融合，既慢又容易在负值上选错吸收位置。
- 把负数也加进 $P$，或把 $P$ 堆到数组最大值所在下标而不是最左边。
- $n=1$ 的负数被误做成 $0$。
- 追问「操作改成只能向相邻位置合并」：不再能任意重分配，要改成区间 DP，公开题面不是这个版本。
