陷阱是把「多员工同时用」答成全局限流：QPS 一满就随机 429，忙的业务线被闲的业务线饿死。租户是配额、账单和数据隔离的单位；应用是同一租户下的产品面（不同 Agent / 工作流）。一个员工打满内部平台，应打到**该租户的桶**，而不是整集群一起拒绝。限流、排队、降级是三层，不要混成一个开关。任务链自己的超时熔断是另一题，见 `xiaohongshu-agent-timeout-circuit-breaker`：限流防邻居，熔断防依赖病了还打。

## 真题记录

- 公司：小红书
- 团队 / 岗位：AI Agent 算法
- 届别 / 流程：一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“如果很多员工同时用，会不会有一些限流或者降级策略”**；**“有不同租户、不同应用，这个概念是怎么理解的”**

## 租户和应用不是一层

租户：账号体系、数据权限、账单、QPS / 并发 / token 日预算。应用：同一租户里的不同 Agent（客服、创作、审核）。隔离要两头做：数据上不能串索引、串对话、串笔记权限；配额上不能让创作 Agent 把审核 Agent 的时延打穿。员工 $\neq$ 租户：同一部门共享一个租户桶时，还要有用户级公平（weighted fair queue），否则一个人开 50 个会话仍会挤掉同事。多租户不是「多个 API key」，是失败域：一个租户的重试风暴不应用尽共享 vLLM 的 KV。关键路径（审核、安全）单独保活池，和尽力而为的闲聊分开，否则降级时审核会跟着创作一起变慢。面试把「租户」说成隔离和配额的边界，把「应用」说成产品面和 SLO 档位，两层主键都要出现在限流键里：`tenant_id + app_id`，必要时再加 `user_id`。只有全局 QPS，答这道概念题就算没分开。

## 限流、排队、降级的顺序

令牌桶按租户（再按应用拆子桶）：先限制入站 QPS 和在途并发，再限制 token / 分钟。Agent 长上下文常先碰到 token 预算，短问答先碰到并发，两个桶都要。过载顺序建议：关多 Agent 并行 → 缩短检索 top-k → 换小模型 → 只检索不生成 → 排队带超时 → 最后拒收并给明确错误。反过来先拒收，用户会立刻重试，形成风暴。排队必须有 deadline，否则队列本身变成内存泄漏，也把熔断的剩余预算吃光。观测按租户报 p95、拒绝率、降级率和 token 消耗，避免集群平均值掩盖某一业务线被饿死。降级要打点「用了哪档模型 / 是否跳过检索」，关键应用禁止降到只检索。和任务链熔断配合：租户桶满了是限流；工具依赖错误率高了是熔断。主键不同，动作都是 fail-fast + 可恢复，但不要用同一套阈值。内部员工场景还要防「友善的重试」：前端超时后自动重打，会把租户桶瞬间打满。所以限流响应必须带 retry-after，客户端必须尊重；写操作必须带幂等键，否则排队成功两次就双发。多租户的观测如果只看集群 p95，创作线把审核线拖慢也不会报警——看板的分组键要和限流键一致。面试把概念题和策略题绑在一起答：先定义租户 / 应用 / 员工三层，再按层放桶，再规定过载时先降哪一档、最后才 429。答完「会限流」却说不清主键，这道题只对了一半。

内部平台还有一层「友情流量」：同一租户里的定时任务、评测回放、员工调试会和在线会话抢桶。不为这些流量单独开低优先级子桶，限流看起来公平，实际是评测把在线打挂。子桶权重按 SLO 分，不按谁先到。面试补上这一句，多租户就从概念答到了运营。

## 追问

- **为什么不能只做全局限流？** 忙租户会占满配额，闲租户被误杀；审核等关键应用要单独保活。全局 429 是最省事也最不公平的答法。
- **员工和租户哪个是限流主键？** 主键是租户；用户级公平是桶内的第二层，防止单个会话打满部门配额。键上再挂应用，避免创作挤审核。
- **降级会不会变成静默质量事故？** 会。必须打点档位，并对关键应用禁止降到只检索。用户侧最好能看见「已降级」。
- **token 预算和 QPS 哪个先碰到？** Agent 长上下文常先碰到 token；短问答先碰到并发。两个桶都要，只设 QPS 挡不住 128k 上下文。
- **排队超时后做什么？** 明确 429 / 排队失败，不要把请求再丢回模型重试；让客户端带 backoff。重试不带 idempotency 会把写操作打双份。
- **和熔断怎么分工？** 限流是邻居占用；熔断是依赖不健康。一个租户被限流不应打开全局 circuit，否则把好租户也停了。
- **观测的分组键是什么？** 和限流键一致：`tenant_id + app_id`。只看集群 p95 会把被饿死的审核线平均掉。
- **429 之后客户端该怎样？** 尊重 retry-after，写操作带幂等键。不尊重就会把限流变成重试风暴，桶永远空不下来。

- **评测回放为什么要单独子桶？** 它和在线会话抢同一租户配额，不降权就会把在线打挂。权重按 SLO 分，不按谁先到。补上友情流量，多租户才从概念答到运营。
