## 真题记录

- 公司：商汤
- 岗位：大模型算法应用实习；二面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“多模型如何动态路由，比如不同模型适合不同视频场景时，怎么根据视频特征、任务特征、成本、延迟和效果选模型”**；**“所有模型超时或故障时怎么兜底，什么时候规则引擎，什么时候人工，服务恢复后怎么回切”**；**“能不能让系统自动发现问题、尝试策略、验证效果，并自动生效和回滚”**

多模型路由要按场景需要的能力和服务预算选模型，再用历史误报、漏报和在线对比修正。比如夜间红外可以走低光模型，远距离小目标可以先检测、裁剪再识别，时延紧的任务优先小模型。模型名字本身解释不了这些取舍。

视频里的硬安全任务，例如烟感或入侵，还要有规则与人工兜底。模型超时先降级，恢复后通过影子流量和灰度回切确认误报、漏报恢复到基线。自动调参也要有金标回放和一键回滚，避免一次错误调整影响全部流量。Serving 层需要用 admission 和模型池先保障 SLA，再选质量。

## 路由：规则打底，效果做探索

先规则：夜间红外走低光模型 A，高清人脸走 B，低分辨率/远距走检测+裁剪再识别，时延预算紧走蒸馏小模型。特征包含场景标签、目标框大小、FPS、是否含人脸/车牌等合规约束。再用在线效果做小流量探索：同一路视频影子打到候选模型，比较漏报、误报、延迟、GPU 成本。路由表要版本化，key 是特征桶而不是「模型 v3」。成本约束写进路由：贵模型只给高价值任务（人脸核验），巡检理解用便宜模型。不要让大 VLM 默认吃所有路，队列一满，所有场景一起超时。

和 LLM 网关类似：小请求小模型，难请求大模型；这里难的是低质量画面和高风险任务，不是 token 长度。

## 兜底与回切

分层：规则引擎管硬安全（烟感、门磁、绊线），模型全挂时物理规则仍在。模型管视觉理解。人工管不确定与法律后果（误报封门、漏报责任）。超时链：主模型 deadline → 小模型 / 轻量检测 → 规则告警或「降级中」工单 → 人工。不要等大模型 30 s；视频是流，晚到的框没有意义。熔断按模型实例，不要一条坏 GPU 拖垮路由。

回切：服务恢复后先影子流量对比误报/漏报，再按百分比放量。指标回不到基线就停。版本和路由表一起回滚。缓存的检测结果要带模型版本，回切后不能把旧框当新结果。



「自动发现问题、尝试策略、验证、生效」可以做，但生效必须有：金标回放、影子对比、小流量、一键回滚、变更审计。这些检查让探索过程中的错误能在小范围内被发现和撤回。验证窗口要覆盖昼夜和天气，否则白天调好的阈值可能在夜间产生大量错误。

## 追问

**为什么不能只看模型名字？**
同一名字换版本、换量化、换分辨率适配，效果都会变。应按场景标签、目标尺寸、时延预算、历史误报漏报路由。特征桶要版本化，才能回放和回滚。
**规则和模型谁优先？**
硬安全（烟感、门磁、绊线）规则永远可兜底，模型全挂时闸门还在。模型提高理解和召回，但不能当唯一闸门。法律后果不确定时交给人工。
**全超时怎么办？**
主模型 deadline → 小模型或轻量检测 → 规则告警或降级工单 → 人工。视频是流，晚到的框没有意义，不要阻塞等大模型几十秒。熔断按实例，坏 GPU 不要拖垮路由。
**回切为什么要影子流量？**
恢复后的输入分布、阈值、权重可能已变。先对比误报/漏报与基线，再按百分比放量。路由表和模型版本一起滚。指标回不到基线就停。
**自动生效最危险的是什么？**
没有回滚的全量推送。探索可以自动，上线必须有金标回放、小流量和一键回滚。验证窗口覆盖昼夜和天气，否则白天调好的阈值可能在夜间产生大量错误。
