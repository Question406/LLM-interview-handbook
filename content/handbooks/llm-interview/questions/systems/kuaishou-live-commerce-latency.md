## 真题记录

- 公司：快手
- 团队 / 岗位：大模型算法实习
- 届别 / 流程：实习；二面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“场景题：目前有一个带货的直播间，设计一个方案，商品比较多怎么降低时延”**

这块容易答成「商品多所以换更大模型 / 更长窗口」。商品多是检索问题，不是 context 问题。直播带货的 SLA 在秒级首包：弹幕/话术要对上讲解中的 SKU，不能把全店目录塞进 prompt，更不能对每个商品跑一遍 VLM。我会先把链路拆成召回 / 缓存 / 生成，再谈 serving（连续 batch、前缀缓存、视觉 token）。指标报首 token、整轮 p95、以及「推荐错品」护栏，而不是只报吞吐。错品比慢更伤转化。

## 检索把「看全目录」拿掉

弹幕或主播话术 → 商品库稀疏（标题/类目）+ 稠密（embedding）检索，只留几十个候选。在播 SKU、货架标签、库存状态做硬过滤。HNSW / IVF 选型同向量卡：要的是短名单延迟，不是全库精确。热卖款可以常驻内存倒排，冷款走向量。禁止把全店 JSON 拼进 prompt：prefill 随 $N$ 变贵，中间商品会被淹没，见 `pdd-window-not-always-better`。

召回之后才是模型：只看短名单 + 当前问题 + 近几轮记忆。讲解稿、卖点可以预计算，不要现场让模型从零写。多商品对比用「先检索再读相关字段」，不要上 128K 硬看全目录。

## 缓存与并行：商品卡不是每轮现查

标题、卖点、讲解稿、类目属性预计算进 Redis；库存、价走短 TTL 或并行 RPC。热卖 SKU 常驻。工具 fan-out：库存、券、物流能并行就并行，见 `kuaishou-tool-chain-latency`。超时降级到检索卡（无生成），总比卡住不返回。会话 KV / prefix cache 复用系统提示和本场直播间模板；key 要带商品集版本，上架变更不能复用旧前缀。

视觉侧：不要对货架全图每帧跑完整 VLM。动态分辨率、只 crop 主播手持区域、关键帧而不是每帧，压视觉 token。讲解中的 SKU 用检测/条码/OCR 对齐商品库，比让 VLM 从全图「找一下」稳且快。

## Serving 与护栏

生成侧：continuous batching 吃弹幕尖峰；限制 max tokens，讲解回复要短。小模型路由简单问句（「多少钱」走检索卡），复杂对比再上大模型。错品护栏：类目不一致、无货、价格超阈值则拦截或改检索卡。验收：首 token p95、整轮 p95、错品率、降级率。商品多不是上更大模型的理由，是上检索和缓存的理由。

直播间的流量形状是尖峰：秒杀、主播报款、弹幕齐问「多少钱」。模型池若按平均 QPS 扩容，尖峰时排队会先于生成变慢。所以检索短名单和商品卡缓存要能单独抗尖峰，生成只处理需要话术的请求。「多少钱 / 有货吗」走检索卡，不占大模型。视觉链路更要节流：不是每一帧都值得做 VLM，检测手持商品、OCR 价签、对齐 SKU 之后，生成只看三五张商品卡。会话记忆只留本场已讲解 SKU 和用户追问，不要把历史弹幕全塞进窗口。prefix cache 的公共前缀是直播间人设和讲解模板，商品集一变就失效。错品护栏要在生成后、上屏前：类目不一致、无货、价格漂移则改展示检索卡。面试按「检索 → 缓存并行 → 短名单生成 → 护栏」讲，并报首包和错品，而不是报模型参数量。商品多时延迟下降，靠的是少看，不是看更快的大模型。

## 尖峰怎么抗

秒杀和报款时弹幕齐问，模型池按平均 QPS 扩容会先排队。检索短名单和商品卡缓存必须单独抗尖峰；「多少钱 / 有货吗」走检索卡，不占大模型。视觉不是每帧 VLM，检测手持、OCR、对齐 SKU 之后生成只看三五张卡。会话只留本场已讲 SKU。错品护栏在上屏前拦截类目/无货/价格漂移。延迟下降靠少看，不是更大模型。

## 追问

- **为什么不把全店塞进长窗口？** prefill 和 KV 随 $N$ 涨，中间 SKU 易丢（Lost in the Middle），错品风险上升，直播 SLA 也撑不住。先稀疏+稠密检索再生成，窗口只留短名单和近轮记忆。
- **每个商品跑 VLM 行不行？** 不行。视觉 token、队列和费用会把秒级首包打爆。先检测/条码/OCR 对齐 SKU，模型只对 top-k 商品卡做话术。动态分辨率和关键帧，不要每帧全图。
- **库存实时性怎么保证？** 展示缓存短 TTL 抗尖峰；下单回主库。生成用的价/库存带时间戳，过期则降级到检索卡，不要用过期缓存编话术。
- **前缀缓存注意什么？** 公共直播间人设和讲解模板可复用；商品集、活动、价格带一变必须换 key，否则旧卖点续进新场。这和 Redis 商品卡缓存是两层。
- **成功标准是什么？** 首 token p95、整轮 p95、错品率、降级率。tokens/s 不是直播指标。降级到检索卡算可用，卡住或错推算失败。
