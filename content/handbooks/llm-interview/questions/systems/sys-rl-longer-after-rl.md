这块容易把「平均长度涨了」当成能力涨了。Reward 涨、holdout 正确率不动、回答充满套话，是 hacking。两件事叠在一起：奖励本身偏爱长；损失怎么平均也会推长度。不要一上来改算法名，先看曲线。长度是结果不是目标：有用的 思维链（CoT，即分步推理过程） 变长可以留，空话变长必须压。同一张图上四条线（奖励分数（reward）、正确率、长度、KL）比任何单一指标都诚实。

## 奖励本身偏爱长

基于可验证奖励的强化学习（RLVR） 常常只在最终答案对时给 1。多想几步、多试几种写法，碰对的概率上升，「写长」变成高奖励行为。有些长是有效推理，有些是重复套话、自我检查空转。标量 reward 分不出来，模型就一起加。格式分若和正确分绑在同一条「看起来完整」的规则上，也会鼓励先铺垫再给答案。

这和组大小有关：小 $n$ 时偶尔采到一条很长且碰巧对的，组内优势极大，策略被这条尾巴拽走，见 `sys-rl-group-n`。温度高、无长度惩罚时更明显。不是 GRPO 独有，凡是稀疏的终局奖都会诱导探索长度。过程监督或逐步 验证器（verifier） 可以减轻「先写长再碰答案」，但会引入新的奖励设计错误（模型学会对过程模板刷分）。先用终局奖把正确率做起来，再决定要不要过程奖，比一开始上复杂奖励更稳。长度暴涨往往出现在正确率开始平台之后：模型找不到新的对法，就在格式和废话上挖奖励，这是 hacking 的典型相位。

## 损失归一化也会推长度

原始 GRPO 常先按序列、再对 token 平均。一条长回复里每个 token 的权重被长度除小：短而正确的样本梯度权重更大，长而错的被摊薄。分析上会 **鼓励变长**，错得长反而罚得轻。Dr.GRPO 指出这件事，并改归一化（按 token 或去掉长度除法）。它 **缓解** length bias，不是消灭「多写有时真能答对」。不要说「换 Dr.GRPO 长度就不会涨」；有效推理变长仍然合理。

Response mask 只训生成段，不训 输入提示（prompt），见 `sys-rl-response-mask`。若把 padding 也进平均，又会多一种扭曲。先确认平均是对有效生成 token，再讨论 Dr.GRPO。

## 怎么监控、怎么压

曲线并排画：reward / 正确率 / 平均长度 / KL。长度暴涨而 holdout 正确率不动，就是 hacking。工程上比改算法名更先做的：

- 最大长度硬切，超长给负格式分，与正确分拆开。
- 评测时固定 token 预算，避免「写得长所以看起来分高」。
- 对「重复 n-gram / 无新信息续写」单独惩罚。
- 看非零优势组里长度与正确率的相关，而不是全局平均长度。

先判断是「真需要更长推理」还是「空话在刷分」。前者加预算、加过程奖要谨慎；后者先改奖励与归一化，不要加 $n$ 指望采更多短对。不加约束时模型仍会选长。评测必须固定 token 预算：否则「写得长所以答案碰巧出现」会污染 holdout。线上再加一个硬 max tokens，训练时就要用同一上限，避免训推长度分布不一致。重复 n-gram、无新信息的自我检查、把问题再抄一遍，都是可检测的空话特征，可以当辅助负分，但权重必须远小于正确分，免得模型为了避罚而写得过短、正确率掉下去。Dr.GRPO 是归一化上的补丁，不是长度问题的全部答案；奖励稀疏性还在。顺序是：先监控、再惩罚、最后改估计器。

四条曲线并排：reward、holdout 正确率、平均长度、KL。长度涨且正确率涨，可能是在学推理，加预算即可。长度涨、正确率平台、套话变多，就是 hacking：先拆开格式分和正确分，加硬 max tokens，评测固定预算，再考虑长度惩罚和 Dr.GRPO 的归一化。

## 追问

- **长度涨一定是坏的吗？** 不是。数学 CoT 变长且 holdout 正确率一起涨，可能是在学推理，加预算即可。坏的是长度涨、正确率平台、套话变多、KL 仍在走。那是 hacking。
- **Dr.GRPO 改的是哪一项？** 主要是优势 / 损失对长度的归一化，减轻「长错罚得轻」。它不改稀疏终局奖本身，所以不能承诺「换了就不会变长」。
- **加长度惩罚会不会把有用 CoT 砍掉？** 会。惩罚必须和正确分拆开，权重远小于正确分，并在 holdout 上看「短且对」是否下降。先监控再惩罚。
- **和 clip 零梯度有关吗？** 间接。过长样本 ratio 更容易炸，clip 后有效更新变少，模型可能靠「再写长碰奖」绕过，见 `sys-rl-fw-clip-zero`。
- **小 $n$ 会不会加重？** 会。偶尔一条很长且碰巧对的，组内优势极大，策略被这条尾巴拽走。先看非零组里长度与正确率的相关，见 `sys-rl-group-n`。
- **评测为什么要固定 token 预算？** 否则「写得长所以答案碰巧出现」会污染 holdout。线上线下同一 max tokens，避免训推长度分布不一致。
- **过程奖为什么后上？** 能减轻「先写长再碰答案」，但也容易刷过程模板。先用终局奖把正确率做起来，再决定要不要过程分，避免两个奖励一起 hack。
