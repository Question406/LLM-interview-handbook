## 真题记录

- 公司：商汤
- 岗位：多模态大模型算法实习；一面
- 来源类型与可信度：牛客候选人原帖，A
- 原始措辞：**“你们刷了哪些benchmark”**；**“在该业务场景下，主流的解决方案是什么”**；**“项目是否落地，有没有遇到什么困难”**

陷阱是报一串没跑过的公开集名字，或把综合分当成落地证据。商汤这面连着问 OCR 过拟合、GRPO 奖励、思维链是否过度设计——benchmark 题要落到**字段级与拒答**，不是「我们刷了 MMBench」。没跑过的名字不要编。

## 公开集对标什么，业务集对标什么

公开文档 / OCR 集（按你真实用过的说：版式理解、表格、场景文字）用来对标感知与结构恢复，方便和论文比。它们解决不了三件事：训练语料污染、和线上证件 / 发票 / 快递单分布差、以及「刷分但不落地」——综合分涨了，关键字段仍错。

业务集必须自建，并按字段拆开报：

- **CER / 字段 F1**：号码、金额、姓名分开，不要只报整页编辑距离；
- **拒答率**：低置信或校验失败应拒，而不是瞎补；
- **版式 OOD**：换字体、印章、歪斜、跨页，用来抓过拟合（见 `sensetime-ocr-overfit`）。

报告结构：公开集给感知基线 → 业务字段集给上线门禁 → OOD 集给泛化。只报一个综合分，面试官会默认你在掩盖「地址炸了、号码还行」。

## 主流方案不是端到端瞎看图

证件 / 票据关键字段当唯一真相时，主流是流水线：版面分析 → OCR / 结构恢复 → 规则或 VLM 抽字段 → 校验（金额勾稽、身份证校验位、电话位数）。端到端 VLM 适合开放描述和脏版式补全，不适合单独当金标。检索或模板库能先缩小版式空间，再让生成器填槽。

落地困难通常不是「缺一个更大模型」，而是长尾版式、隐私不能外发、延迟预算、以及运营规则变更。和同面其他题对齐：过拟合用 OOD 门禁抓；奖励打在字段正确与可验证纠错，不打在「看起来像在读图」；能规则校验的步骤不要硬上长 CoT。面试收口：公开集对标、业务集门禁、流水线加校验，端到端只做补位。

落地叙事按失败而不是按模型名讲。长尾：少见发票联次、折叠扫描件、手机竖拍裁边，公开集几乎没有，必须在业务集里按频率分层抽样，否则平均 F1 被高频模板带着走。隐私：证件照不能随便上传公有云评测接口，要离线包或脱敏合成；「我们刷了某某榜」若数据出过境，合规先不过。延迟：版面模型 + OCR + 校验的流水线比单次 VLM prefill 更可拆；哪一段超预算就优化哪一段，不要一上来换 72B。运营规则变更：字段从「要识别」变成「不确定就拒」，门禁指标也要从召回偏向精确，这是产品约束，不是 benchmark 没刷到。

主流方案里检索 / 模板库的位置也要说清。先按版式分类或检索相似模板，再在对应栏位上 OCR，等于把 grounding 从整页搜索收成局部阅读。端到端 VLM 适合开放备注、印章文字、非模板收据；和流水线是互补，不是替代。面试被问「你项目用了哪个公开集」时，只报自己真正跑过、能说出 CER / 字段切片的那些；编 DocVQA、OCRBench 分数会被追实现细节。

## 面试收口：公开集对标，业务集门禁

商汤连着问落地和困难，benchmark 不能停在报榜。公开集用来证明感知和版式理解不是随机猜；业务字段集用来决定能不能上线；OOD 扰动集用来抓过拟合。主流方案是版面 → OCR / 结构 → 抽字段 → 校验，端到端 VLM 做开放描述和脏图补位，不当证件金标。没跑过的集名不要编，跑过的要能说出 CER 和字段切片，而不是一个综合分。落地卡点按长尾、隐私、延迟、规则变更讲，每一项对应你用哪张表、哪段流水线，而不是「再换大模型」。和同面 OCR 过拟合、GRPO 奖励、CoT 过度设计对齐：刷分而不切片，就是这题的失败模式。收口：对标、门禁、流水线加校验，三句话，不要报一串论文标题。

## 追问

- **污染怎么防？** 业务集与预训练 / 微调语料做近重复扫描；评测图不能进训练，合成器也不能复制评测模板。
- **为什么不端到端？** 关键字段要可追责、可校验；纯生成无法证明没幻觉补全，出事时无法指到哪一步错。
- **项目没落地怎么答？** 讲卡在隐私、延迟或长尾的具体点，以及你用哪张切片表证明，不要编上线数字。
- **和 grounding 的关系？** 字段抽取本质是把文字框 / 单元格 ground 到 schema；bbox 或单元格 id 比自由生成更可测。
- **只报综合分会被追什么？** 按字段、按版式 OOD、按拒答分开；综合分涨、关键字段掉，就是刷分不落地。
