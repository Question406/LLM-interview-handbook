- 原始措辞：**“Token 是如何划分的？为什么 strawberry 在部分模型中会被拆成多个 Token？”**；**“为什么大模型以 Token，而不是字符或完整单词作为基本处理单位？”**

陷阱是把 tokenizer 当成「对人类单词的对齐」，再推论模型能按字母数 r。模型看见的是子词 id 序列，不是字形列表。`strawberry` 被拆，不是 bug，是 BPE 合并优先级的结果。

## 字符、单词、子词各牺牲什么

- **字符级**：词表极小、无 OOV，但序列长度按字膨胀，注意力是 $O(n^2)$，长依赖更难建。中英文混排、空格、标点都变成超长串。
- **单词级**：英文可空格切开，但词表巨大；新词、拼写错误、SKU、表情全是 OOV。中文还要先分词，分词器错误会直接写进 id。
- **子词（BPE / Unigram）**：按语料频率把高频片段合并成词表项，低频词退回更短片段。压缩比介于字符与单词之间，开词汇：没见过的词仍能用已知子词拼出来。

BPE 训练是迭代合并：初始为字符（或 byte），每次把当前语料里出现最多的相邻对合成一个新符号，直到词表到 $V$。编码时用同一合并表做贪心：能合就合，合不上就停。因此「一个英文单词几个 token」由训练语料统计决定，不是语言学规则。

## 为什么 `strawberry` 会被拆，以及业务含义

该整词在词表里的合并优先级不够，或带前置空格 / 大小写变体（`strawberry` vs `Ġstrawberry`），编码器走了更短的子词路径，例如 `str` + `aw` + `berry`。模型前向从未看见「完整单词形态」，更没有隐式字母列表，所以「数 r」类题容易失败——失败在表征，不在「不会数数」。

业务上：SKU、快递单号、emoji、中英混排、拼音缩写都会被切碎。评测长度、上下文窗口、计费都按 token，不是按字或按词。同一句话换 tokenizer，长度和切点都会变，不能跨模型比「多少 token」。面试补一句：换词表等于换离散空间，embedding 与输出头都要重训，不是后处理能对齐的。

「数 r」类题要主动拆开两层。第一层是切分：模型输入是 id 序列，没有字母列表，除非你把词再拆成字符特征。第二层是计数能力：即便切成整词，自回归模型也不保证能做精确计数，这是算法能力，不是 tokenizer 的锅。面试只把失败归因于拆词，会被追问「那换成整词就能数对吗」。更完整的答法：拆词解释了为什么形态不可见；要数对，需要显式字符级工具、程序，或在数据里教过计数格式。Agent 岗还要落到 SKU / 券码：检索和工具参数应按规范化字符串，而不是按「看起来像一个单词」的 token 边界做切分。BPE 不会按业务字段切，字段抽取要自己定边界。

中文场景再补一句。空格分词对中文几乎不可用；字作为「单词」则词表和序列都不经济。子词把高频词（的、是、可以）收成短 token，把人名、品牌、错别字退回更碎的片段。这解释了为什么同一模型对常见书面语压缩很好，对直播口播和商品标题却 token 暴涨——统计不在词表的高频合并路径上。评测集若和预训练语料切分习惯差很远，长度预算和计费预估都会偏。

## 面试收口：单位是统计片段，不是单词

为什么不用字符：序列太长，$O(n^2)$ 先爆。为什么不用单词：中文难切、新词 OOV、词表爆炸。子词是压缩和开词汇的折中，BPE 按语料频率贪心合并，所以 `strawberry` 完全可以不是一个 id。模型看见的是子词向量，没有隐式字母表，这解释了一部分「数 r」失败，但不要宣称「换成整词就一定能数对」——计数还是算法问题。业务上 SKU、券码、表情、混排都会碎，计费和窗口都按 token。Agent 岗把这句话落到工具参数：规范化字符串自己定边界，不要幻想 tokenizer 按字段切。换词表等于换离散空间，embedding 和 lm_head 都要重来。现场能画「字符太长、单词太闭、子词折中」三行，再举一个切碎的英文词，这题就够用。

## 追问

- **Byte-level BPE 解决什么？** 任意 Unicode 都能落到 byte，彻底消灭「未知字符」；中文常被切成多个 byte 再合并，词表不必为每个汉字单列。
- **能按空格强制不拆吗？** 可以加 special token，但会膨胀词表，且只覆盖你枚举过的词；新品牌下周又 OOV。
- **Unigram 和 BPE？** Unigram 用语言模型打分选切分，BPE 是贪心合并；面试先讲 BPE 合并表即可，被追再补 Unigram 的多次采样切分。
- **和 embedding 的关系？** 每个 token 一个向量；拆开后「词」的语义要靠多层注意力拼回来，没有免费的整词槽位。
- **预分词（jieba）再 BPE？** 早期中文常见，但分词错误会写进 id，且和新词冲突；现代多语词表更常直接 byte/unicode BPE。
