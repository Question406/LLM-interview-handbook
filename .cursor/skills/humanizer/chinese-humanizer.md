# 中文自然人话改写

适用于中文答案、说明和交流。让正在学习的人读得懂：直接说结论，解释原因，必要时用例子讲清步骤。不要为了显得口语化而牺牲技术含义。

## 去掉套话，保留具体含义

删除只用于装饰的“深入探讨、赋予、彰显、助力、重塑、赋能、协同、沉淀、拥抱、穿透、打通”。用具体动作说明做了什么。

“画卷、缩影、试金石、双刃剑、里程碑、新篇章、护城河、细分赛道”等比喻，若没有增加信息，直接删掉。“构建、矩阵、闭环、链路”要看语境：矩阵乘法、构建索引、实际反馈闭环等有准确含义时保留，并解释具体过程。

删除“不可否认的是、值得注意的是、毋庸置疑、不言而喻、不可或缺、举足轻重”等空修饰。去掉“这不仅是 X，更是 Y”“为未来奠定坚实基础”“让我们拭目以待”等无信息的升华。真实的技术对比和纠错要保留。

少用“此外、值得一提的是、总而言之、综上所述、不仅如此”等模板连接词。需要连接时可以用“另外、不过”，也可以直接进入下一句。不要机械地换成“其实、话说回来”，更不要每段加一次。

## 把句子讲完整

- “通过……的方式，从而实现……”通常可以改成“用……做到……”，或直接说结果。
- 减少修饰词和连续的“的”。句子太长就按意思拆开，长短交替，不强行全部改成碎句。
- 术语堆在一起时，补出主语、动作和因果关系。说明谁比较谁、程序检查什么，以及检查结果会怎样影响下一步。
- 英文术语第一次出现时，用当前题目的语境解释。不要逐词翻译整段，也不要在一个短句里连续插入多层括号。
- 公式前说明要计算什么，公式后说明变量及结果的含义。代码前讲思路，代码后解释关键边界；保留原有技术条件和限制。
- 可以删掉重复和口号，但不能删掉独有的事实、数字、来源、不确定性或失败条件。不要补写来源没有支持的公司实现。

例如，“同 prompt 多样本，组内相对优势，空组无信号”可以改成：“对同一道题生成几个回答，再比较它们的得分。如果所有回答得分一样，模型就不知道该鼓励哪个回答，这组数据也就提供不了学习信号。”

## 让结构服从内容

不必每题都凑“第一、第二、第三”或“引言、正文、总结”。需要比较、列步骤或回答独立追问时，可以用列表和标题。

避免每条都写成“加粗标签 + 冒号”。保留有助于定位追问或关键条件的强调。日常交流直接回答，不重复问题，不加客套。技术答案不必模仿微信或网络段子的语气。

## 写完后检查

读完整道题，检查：念出来是否像正常人在解释？读者是否需要猜省略的逻辑？是否还留着用于显得高深的抽象词？结尾是否只是在重复前文？公式、代码、来源和题间链接是否仍然正确？

整库改写必须逐题读完短答案和正文，再决定如何改。词表用于发现问题，不能代替理解内容和重写段落。
